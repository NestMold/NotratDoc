# 插件与扩展市场

扩展市场在左侧活动栏的**「扩展」**这一格。它装的是四类可安装的东西。

![扩展市场](/shots/guide/market.png)

## 四个货架

| 货架 | 装的是什么 |
| --- | --- |
| **技能** | 给 AI 的一套固定做法（[详见](/guide/skills)） |
| **连接器（MCP）** | 给 AI 接外部工具（[详见](/guide/mcp)） |
| **专家（智能体）** | 现成的角色（[详见](/guide/experts)） |
| **插件** | 给 Notrat 本体加功能——新面板、新按钮、新编辑器能力 |

每个货架里都分**社区**与**官方推荐**两段：官方推荐在上面带一个 chip 标记，社区的在下面。

::: tip 发现 vs 管理
- **装东西** → 活动栏「扩展」（就是这一格），只逛市场
- **管已装的** → 设置 → **扩展管理**（[详见](/guide/extensions)）

1.3.5 起这两件事彻底分开了。以前市场里还带管理功能，现在不会。
:::

## 装一个插件

在插件货架里找到要装的，点安装。

![插件详情](/shots/guide/market-plugin-detail.png)

装完之后：

1. 插件出现在 **设置 → 扩展管理 → 插件** 页签里
2. 它贡献的东西按类型出现：
   - **面板** → 在插件箱里能找到
   - **活动栏按钮** → 活动栏上多一格（比如「Flow 节点画布」）
   - **编辑器能力** → 直接在编辑器里生效
   - **右键菜单项** → 文件右键菜单底部多几项
   - **技能 / 连接器** → 出现在对应的列表里

::: warning 带连接器（MCP）的插件需要重启
插件如果自带 MCP 服务器，安装后**要重启 Notrat** 才会连上。

这不是缺陷——MCP 服务器是独立的子进程，得在应用启动时一起拉起来。
:::

::: tip 装完没反应？
先看**插件日志**：

- 插件卡片上的 **⋯** 菜单 → **查看日志**
- 或插件箱里右键插件 → **查看日志**

日志里会说清它是没启动、启动失败、还是启动了但报错。
:::

## 权限与安装位置

装插件时 Notrat 会告诉你它要访问什么。插件装在这里：

```
<应用数据目录>/
├── plugins/                 ← 插件本体
└── ...

<工作区>/
└── .notrat/plugins/         ← 工作区级插件（如果按工作区装）
```

::: warning 插件是**代码**，不是数据
插件能在你机器上执行代码。所以：

- **只装你信任的来源**
- 装之前看一眼它要什么权限
- 一个插件出的问题可能影响整个应用

Notrat 对插件的崩溃做了兜底（单个插件面板挂了不会带崩整页），但**能力边界仍然是你给的**。
:::

## 插件市场在哪

| 入口 | 内容 |
| --- | --- |
| 应用内 活动栏「扩展」 | 四个货架，直接装 |
| 网页版 | `notrat.cn/plugins/` —— 不装客户端也能逛 |

两边是同一批内容。

## 更新插件

有两个入口，页头管全部、卡片管单个：

| 入口 | 在哪 |
| --- | --- |
| **检测更新** | 页头的按钮，检查所有已装扩展 |
| **单卡更新** | 每张卡上的更新按钮 |

::: tip 更新时应用正开着插件会失败
Windows 上有个坑：**正在运行的进程会占住它自己的目录**，导致文件删不掉、改不了名。

Notrat 已经处理了这件事（更新前先停掉这个插件自己的连接器、按进程树杀干净）。但**如果更新仍然失败，重启一次 Notrat 再更新**——这是最简单可靠的解法。

修好的那部分要**重启应用**才生效。
:::

## 卸载

设置 → 扩展管理 → 插件 → 卡片上的卸载（或 ⋯ 菜单）。

从市场装的插件，插件市场里也会显示「已安装」状态并给卸载入口。

## 插件能做什么、不能做什么

**能：**

- 加面板（左 / 右 / 底部）、加活动栏按钮、加命令
- 扩展编辑器（自定义组件、覆盖内置组件）
- 提供一个 MCP 服务器（让 AI 用上你写的能力）
- 带自己的技能、专家

**不能：**

- 改 Notrat 的核心行为
- 在没被调用的情况下主动操作你的文件
