# 扩展管理

发现去外面（活动栏「扩展」），管理在这里（设置 → 扩展管理）。

1.3.5 把四类可安装的东西收进了同一个页面，用页签区分。

![扩展管理](/shots/guide/settings-extensions.png)

## 四个页签

| 页签 | 管什么 | 主要操作 |
| --- | --- | --- |
| **技能** | 已装技能 | 启用 / 停用 / 更新 / 删除 |
| **连接器（MCP）** | MCP 服务器 | 看连接状态、改配置、手动执行工具 |
| **专家（智能体）** | 官方与自建专家 | 改角色 / 工具 / 工作流、停用、卸载 |
| **插件** | 已装插件 | 启用 / 停用 / 更新 / 重载 / 卸载 / 看日志 |

每个页签的详细用法：

- [技能](/guide/skills)
- [连接器（MCP）](/guide/mcp)
- [专家（智能体）](/guide/experts)
- [插件与扩展市场](/guide/plugins)

## 档位门槛

| 页签 | 最低档位 |
| --- | --- |
| 插件 | **纯净版**（免费），插件对所有用户开放 |
| 扩展管理（整个分类） | **纯净版** |
| 技能 / 连接器（MCP）/ 专家（智能体） | 基础版 |

低档位进来看得到页签，点开会给升级说明。

## 各页签的更新机制不一样

四个页签的「更新」判定方式各不相同，因为能拿到的版本信息不一样。

| 页签 | 怎么判断有没有新版本 |
| --- | --- |
| **技能** | 按 **slug** 与市场对比 |
| **专家（智能体）** | 与**专家台账**对比 |
| **连接器（MCP）** | 连接器**不上报自己的版本**，靠一个版本台账 `mcpMarketVersions` 记录「装的是市场里的哪个版本」 |
| **插件** | 插件自带版本号，直接比 |

页头有**检测更新**（检查全部），每张卡上也有单独的更新入口。

::: tip 连接器为什么需要「从市场重新同步」
连接器的版本是靠台账**记**出来的，不是它自己报的。台账与实际不一致时（比如你手动改过本地文件），用连接器页的**从市场重新同步**把两边对齐。
:::

## 卸载与残留

卸载扩展时，有些东西不会随卸载一起消失：

| 东西 | 在哪 | 卸载后会怎样 |
| --- | --- | --- |
| 插件的持久化数据 | 应用的本地存储 | 保留（重装能接着用） |
| 插件的注册记录 | `~/.notrat/plugins` 下的 json | 删不干净就会「长回来」 |
| 技能目录 | `.notrat/skills` / 全局 skills | 一般随卸载清掉 |

::: warning 卸载插件别只删文件
如果你手动删掉插件的 json 注册记录，但没删插件本体（或反过来），Notrat 下次启动可能又把它认回来，看起来像是卸载失败。

用扩展管理里的卸载，或插件市场里的卸载入口。
:::

## 兜底：插件崩了会怎样

Notrat 对插件出错做了两层兜底：

1. **单个面板崩溃** → 边界接住，页面其余部分照常，出问题的那个面板显示错误态
2. **插件运行期出错** → 不会带崩整个应用

::: warning 但仍有两处薄弱环节
- 插件**运行期**目前没有完整的安全模式（崩溃后不会自动禁用那个插件）
- 第三方插件里有些字段**类型是不可信的**（比如 `author` 可能被写成对象而不是字符串）。Notrat 在渲染前做了归一化，但这类问题属于插件自己的质量

选插件时留意一下维护状态。
:::
