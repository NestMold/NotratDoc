**这一版**：32 项亮点 · 135 处修复 · 66 项改动详情（详情按模块收起，点标题展开）

## ⚡ 更新亮点

- **🚀 启动更快，启动页也换了模样**：窗口不再等后台准备就绪才显示；进入桌面时「读会话」改成两拍——先上界面、工作区列表随后自己填出来，等待时间大约砍半（工作区 / 会话越多的机器越明显）。启动页从转圈改成品牌牌呼吸 + 阶段文案 + 进度条，等待久时有一句安慰文案，深浅色下都跟主题走。
- **🗒️ 悬浮便签更顺手**：桌面空白处右键即可「新建便签」（Windows，可在 设置 → 通用 里装 / 卸）；标题单击拖动挪窗、双击就地改名；工具栏图标整套换成清晰的线性图标。
- **🔄 扩展管理一键检测更新**：技能 / 连接器（MCP）/ 专家（智能体）/ 插件四个页签各自带「检测更新」，每张卡片带「更新」按钮——装了哪一版、能不能升级，不用再去市场里翻。
- **🔍 社区插件先看详情再决定**：市场里点社区插件卡片开的是详情弹窗（图标 / 版本 / 来源 / 星标 / 简介 / 规范检查 / 仓库地址），不再一点名字就被送去 GitHub 主页。
- **📂 工作台侧栏：AI 改完的文件自动进编辑区**：在侧栏对话里让 AI 改了文件，主要那个会自动在编辑区打开——不用再从文件树里翻（只在工作台生效，搭档模式不参与）。
- **📂 侧栏长清单：超一屏就开一窗**：文件 / 工具调用 / 任务 / 子 Agent 清单再长也夹在一窗里自己滚，**正在跑的那条始终看得见**——不再一路铺下去把对话挤成一条缝。
- **🎛️ 设置页整版焕新**：分类按使用习惯重排——技能 / 连接器（MCP）/ 专家 / 插件四类管理合并进「扩展管理」一页四页签；三处列表改多列卡片、统一卡片语言；开关整套重做；每个插件新增「上手引导」（环境 / 用法 / 手册 / 排错）。
- **🎨 主题定档五套 + 自定义调色板**：极简 / 日落橙 / 紫罗兰 / 靛蓝 / 樱花粉，砍掉不再维护的旧主题；主题卡换成浅深两档实机截图，随「暗色模式」开关自动换档；新增第 6 槽「自定义」——色域方块、色相条、十六进制输入、预设色块，调出一套只属于你的配色。
- **🧑🏫 专家页更好逛**：我的专家分页浏览（每页 9 个），「创建专家」挪到搜索框旁；从市场装来的专家显示货架自带 Logo。
- **👤 个人中心翻新**：会员卡式头部 + 分区卡片；邮箱 / 手机号 / ID 升级为带图标的标签，一目了然。
- **🤖 聊天更干净**：模型偶尔把「调用工具」写成一整段 XML 文本糊在回复里——现在会被正确执行并清理，不再漏出。
- **📄 导出的文件自带图片**：导出 HTML / PDF 图片不再丢失——PDF 里不再只剩破图占位，导出的文件换台电脑、换个文件夹打开都完整。
- **🍎 Mac 与插件运行环境一串修复**：Mac 上插件后台服务「找不到 Node.js」修好了；电脑没装 Node.js 也能跑插件（自动用应用自带运行环境兜底）；官方安装包此前有若干依赖漏装（「压缩为 ZIP」报错即它）——从打包流程到成品一并根治。
- **🍎 Mac 两处硬伤：终端打不开、退出弹「意外退出」**：Mac 上打开终端只有一行 `posixspawnp failed.`、每次退出都弹系统的「"Notrat"意外退出」——这一版一并修好（终端那处从打包环节根治，退出那处是把「收尾没做完就退」改成做完再退）。
- **🗺️ 图谱界面重做：缩到哪都看得清**：活动栏「图谱」（工作区文件的链接关系图）整套翻新——节点 / 箭头 / 标签按屏幕大小绘制，缩放到任何档位都不再糊成一坨；文件名标签常显、带底色描边并自动避让；悬停提示、顶栏与缩放按钮换成与全应用一致的卡片与图标语言，画布配了点阵底纹（深浅主题自动反向）。
- **📂 最近工作区：记 50 条，滚着看更多**：应用记忆的最近工作区从 10 条扩到 50 条；欢迎页「最近使用」首屏 10 条、滚到底自动补下一页，也可以一键「查看更多 / 收起」——更早打开过的项目不必再翻文件夹去找。
- **🔐 登录页换新**：左侧品牌区改成「编号 + 细分隔线」的排印列表，两种登录方式改下划线页签、第三方登录收成两列，输入框都挂上字段名标签；整页去掉光斑与投影——品牌标记也跟着明暗主题走，暗色下不再隐形。
- **📱 远程助手里的「平台插件」改名「IM 插件」，扫码登录整轮翻修**：页签改叫「IM 插件」（英文 IM Plugins）并挂上「内测 / BETA」徽章，面板里写明「接通更多平台，内测中，不稳定」；二维码改由应用本地生成（断网也有图，另有链接兜底），扫码框改左右两栏——左边图、右边提示与「扫不出来？」，码与链接各配一句说明；连接状态改为按「真登录」显示，没扫码不再顶着「已连接」；WhatsApp 一串「用不了」一并修好（国内取不到码、扫码后登录不上、双连接互踢、图片与文件收不下来、只有一个手机号也能「给自己发」），Telegram 的代理也接上了。
- **🔍 插件页：单卡「检测更新」+ 每个插件一个日志入口**：每张插件卡「⋯」里可直接「检测更新（只查这个插件）」，页头多一个「全部更新（N）」批量升级；同一处新增「查看日志」，插件箱右键也有同一项——不用再去翻上手引导。
- **📦 从社区装插件优先装「发行包」**：带界面面板的插件，此前从市场装到的是仓库源码（打开就报错）；现在优先下载作者发布的发行包，版本落后才回落源码，装前还会拒掉「未完成构建」的包并说明原因。
- **👤 会员卡多一个「管理账号」**：个人中心会员卡上一键打开网页版账号页（免二次登录），改头像、昵称、手机号、邮箱都在那边。
- **📦 安装包小了一圈**：同一份功能，三合一通用安装器从 **1033 MB 降到 635 MB**、单架构从 **344.8 MB 降到 212 MB**；装完之后整个安装目录也从 **1.4 GB 降到 748 MB**。
- **🧠 内存占用大幅回落**：长期开着也不再越涨越高——实机占用从约 **5 GB** 降到 **0.8 – 1 GB**。
- **🧩 装机版 DIY：终于能读 / 改源码了**：安装版此前打开组件 DIY 面板，组件清单是 **0 个**、源码两栏写着「not found」（开发时一直好用，装出来的版本却不行）。现在把可 DIY 组件的源码随包带上（357 个文件、6.1 MB）——装好就能读能改。认证 / 权限 / 订阅等级 / 强制更新这几类组件的源码**不进包**（它们本来也不允许被覆盖）。
- **🖥️ 桌面悬浮器听使唤了**：菜单头部那颗 ✕ 以前干的是「收起」（点了悬浮器还在，字面承诺从没兑现），现在它是**真关闭**（与右键菜单里那条同一个动作）；按钮也不再被拖拽吃掉点击——点得动，命中面积按无障碍标准放大，关掉后设置里的「已开启 / 已关闭」跟着改口。
- **🧩 全应用图标统一到一套线性图标**：332 个图标整批换成 lucide 线性图标（91 个文件），活动栏那 27 枚整套重写——两条栏终于说同一种字形语言；尺寸与线条粗细收成一套刻度，图标按钮补上读屏可读的名字。「对话压缩」定为三层叠片、「远程」定为手机 + 平板（两枚都从整套 3800 多枚图标的对比页里逐枚挑定）；模型切换那枚「打印机」换成了芯片。
- **🎨 切主题不再卡顿**：主题切换从「整页重画 + 啪一下硬切」改成一次约 220ms 的**颜色转场**（颜色 / 边框 / 阴影平滑插值）；切换时编辑器不再被重建（正文与光标保持原样），图表也在转场结束后再重画。
- **🔤 对话的字号与字体可调**：设置 → 外观 → 对话字体——「正文字号」12–22px、「字体」与编辑器同一份清单（带「跟随界面」默认档，也能一键加载本机系统字体）；两行各带一行实时字样预览，盖着设置页就能当场比。搭档模式正文比它大一档、气泡与代码块等比缩放，标签类小字不跟（默认 12px 与从前逐像素一致）。
- **⌨️ 输入框更像输入框**：侧栏与搭档模式的输入卡换成主色柔描边（聚焦加深）+ 底色抬一档——此前的灰线在满屏同色卡片里认不出「该在哪儿打字」；口径与欢迎页聊天盒对齐（全应用唯一没被说过「不明显」的输入框）。
- **🧵 新增「多会话并行（后台续流）」**（默认开着）：她在跑的时候你切到别的会话、或者新建对话，在途的回复不会被掐断——它**转到后台继续跑**、跑完自己落盘（会话列表里能看到运行状态：正在跑的行尾转圈、跑完变对勾）；新建对话那一下如果还有回复在跑，Notrat 不会替你闷头决定，而是先弹一个三选一问你（**后台继续并新建 / 停止并新建 / 取消**），勾「不再提醒」就不再问。想关：设置 → 面板 → 对话与启动（旁边的「新建对话时先询问」管弹窗问不问）。
- **🗂️ 聊天顶部：会话标签条 + AI 会话取名**：多会话并行下切来切去不用再翻会话列表——条上的脉冲点标出「还在后台跑」的会话，非当前条悬停出「×」（流式期间点它 = 停掉那条流并关闭）；新建对话的标题先落一条摘要式标题（列表立刻可读），模型生成的短标题随后异步替换——你手动改过名字就绝不覆盖。

- **🪟 插件面板可以「搬」到桌面上**：面板上右键「移动到…」选「独立桌面窗口」，插件面板就从应用里出来、成为桌面上一个真正的小窗——透明背景、常驻最前、可调不透明度、鼠标穿透、位置尺寸记得住、退出重开自己回来；想收回来，选别的位置或「恢复默认位置」即可，桌面窗口自动关上。适合待办清单、监控小窗这类「想一直杵在桌面上」的面板。

## 📚 按模块看改动

::: details 🚀 启动与性能 · 4 项

### 🚀 启动：更快，启动页也换了模样

- **症状**：从双击图标到界面能用，要盯着启动页等好几秒——会话和工作区越多的机器等得越久。
- **现在**：窗口尽早显示；读会话改成分两拍——第一拍只读主页那一份（量很小），界面立刻可用；第二拍等界面画出来之后在后台把各工作区补上，左栏工作区列表先显示占位行、随后一格格填出来（不再是「一片空白」或「暂无工作区」）。开发机实测：「进入界面到可用」由约 10 秒降到 3 秒出头——工作区越多，收益越大。
- **启动页换新**：转圈退休——改成品牌牌呼吸 + 一行说明当前进度的文案 + 一条只表示「还在走」的进度条（不报百分比）；等待久了会浮出一句安慰文案。深浅色主题下自动换面（深色下 logo 反白、牌底压暗），系统里开了「减少动态效果」时全部降为静态，读屏也能读到当前阶段。
- **白屏修复**：另有反馈「加载结束后还要对着白屏等十几秒」。根源不在加载本身——启动封面自带一条保险丝（写死 15 秒）到点就把封面摘掉，而界面主模块在慢机器上可能更晚才到；封面先摘、界面没画出来，就剩一张白纸。现在改成看状态：**界面画出来了才摘封面**；没画出来就继续守着（文案改成「首次加载较慢，仍在准备中，请稍候…」）；到 60 秒仍起不来会明确写「启动失败：界面没能加载出来，请重启 Notrat」——有解释，比一个假装还在爬的进度条诚实。

### ⚡ 大文档：两处「越写越慢」去掉了

- **症状**：文档写到中长篇之后，输入手感变钝——左侧大纲面板和字数统计是重灾区；另外 AI 改完文件、内容回到编辑器时，也有一阵不必要的处理。
- **现在**：大纲与统计改成「一遍过」的线性算法，回灌的多余处理直接短路——中长篇文档的输入手感明显更跟手。

### 📄 超大 Markdown：打开 / 重启不再卡死

- **症状**：打开内容特别大的 Markdown（十万字符量级起、大可以到几 MB）时窗口直接卡死、动不了；更麻烦的是**重启应用会自动恢复上次打开的文件**——同一篇大文档重新灌一遍，开机即卡，而且卡住时连可以点的出口都没有。
- **现在**：超过约 **10 万字符**的 Markdown 不再直接交给富文本编辑器，默认建议在**源码模式**打开——秒开，编辑、保存、AI 改动回灌一切照常。编辑区先给一张说明卡，除了「用源码模式打开」，还留了两个出口：「仍用富文本打开」（点了才会付那份等待——先显示「正在打开」再加载）和「用系统默认程序打开」；源码模式顶部有一条横幅说明它为什么没进富文本，同一个切换出口就放在横幅上。阈值以下的中大文档行为不变。

### 🧠 内存：不再越用越涨

- **症状**：应用开久了内存一路涨——有用户在另一台机器上实报常驻 **5.5 GB**；更气人的是，应用的运行状态面板里那个数字一直显示得很小，看着毫无异常。
- **现在**：长期使用不再越涨越高——实机占用从约 **5 GB** 降到 **0.8 – 1 GB**（Windows · 总内存 32 GB）。运行状态面板里的内存数字也不再少报（以前 **2.5 GB** 会显示成「2.5 MB」）。
- **另修一处「从来没生效」的功能**：知识库的**本地语义检索**一直搜不出东西。现在第一次检索会先把本地模型准备好（选「按需下载」的机器会明确问过才下载）。

### 🖼️ 编辑器：图片可以直接拖进正文，自动收进工作区

- 写文档要插图时，现在可以把本地图片（截图、保存的图片文件）**直接拖到正文里松手**：图片自动拷贝进工作区（`.notrat/images/`），并在你放手的位置插入引用——不用先手动挪文件、再补路径。

- **顺带修好一处旧图裂**：当文档不在工作区根目录时（比如打开的是子文件夹里、或工作区之外的 md 文件），插入/粘贴的图片会显示「读不到」的裂图——图片显示的定位现在统一按工作区解析，与导出、复制时的解析规则对齐。
- 图片改成 Typora 样式：独占一行、居中显示，宽度最多到 800px、高度不超过约 60% 屏高（正文栏更窄时随栏宽缩）；小图保持原尺寸、不拉伸，宽截图不再把正文撑出横向滚动，手机竖版照片也不会一屏铺不完——想更大，拖右下角即可（拖过之后的尺寸听你的，不再受默认上限约束）。
- **图片可以手动缩放**：点一下图片，右下角出现拖拽点，左右拖动即可调整宽度（怎么拖怎么显示，不变形）；**抓着图片右边缘拖也行**——不用非对准那个小方块（鼠标移到右边缘会出现横向拖拽光标）。拖动时会浮出当前宽度的读数。双击拖拽点、或把宽度拖回原始大小，即恢复原尺寸。缩放后的宽度随文档保存、重新打开保持一致（源文件里以 `<img width="…">` 记录，与 Typora 同款写法）。
- **不想拖也能调**：选中图片后用键盘 ←/→ 逐档调整（按住 Shift 步子更大）；右键菜单里也有「图片宽度 → 变窄 / 变宽 / 恢复原始尺寸」，不想用鼠标拖拽时的替代路子都留好了。
- **图片可以直接拖出去用**：把正文里的图片拖到桌面、文件夹或聊天窗口，拿到的是**图片文件本身**（以前拖出去的是个外部程序打不开的东西）；在编辑器里拖动图片换位置不受影响。
- **图片引用平时不再挂在正文里**：点一下图片才浮出它的引用原文 `![说明](路径)`，再点这串文字就能**就地修改**（改完写回图片）；引用那一行**随窗口宽度自动折行**——窗口窄了折行、宽了一整行，路径始终完整看得见；鼠标停在这串引用上还会给出图片实际落到的完整路径。点到别处自动收起——以前只要光标落在图片附近，这串引用就一直显示着，看着像正文内容。

- **修好引用改到一半「字跑进正文」**：此前点进引用后，从第二个字起敲的字会落进后面的正文里（严重时整张图片都被替换成刚敲的字）。现在改引用时敲的每个字都只进引用本身，改完确认才写回图片。

### 📄 导出：图片不再丢（HTML / PDF）

- **网络图片**（本来就是外链的）保持原样引用，不打包。
- 说明：导出 Word（.docx）目前仅保留文字，图片与排版不在其中。

### 🎨 编辑器：代码块的底色与字色，一次查到底

- **症状**：写文档时先反馈「代码框的背景和主题一样，字体很不明显」；把底色加深一版，又说「代码块背景怎么是白色的」；追到最后发现——**一整套深色主题的代码配色跑进了浅色模式**。
- **第一层：底色和页面同色**。代码块底色原来是「一个近似固定的浅色，掺一点当前主题的浅灰」算出来的。在四个彩色主题的浅色档里，掺进去的那点灰和页面底色正好抵消——代码块和页面**完全同色**（实测对比度 1.01:1，等于没有块），只剩一段等宽字；而编辑器这处偏偏又是全应用唯一没有分块边框的地方。
  → 底色改成**从当前页面色自己派生**（页面色 80% + 中性墨 20%）：五个主题一律稳定深一档，不等谁的心情；编辑器与预览补上 1px 细边框，和对话 / 侧栏 / 更新日志同款。
- **第二层：白得看不出是块**。第一版只深 10%，在纯白页面上是 #F0F0F0 这种「近白灰」——**能测出来，但肉眼看不出来**。
  → 浅色档提到 20%（#E1E1E1，离页面 1.28~1.30:1）。深色档一个数没动：深色纸面本就比页面亮一档，再往上提会把靛蓝深色主题的注释压到可读线以下。
- **第三层：真凶——深色配色「串门」**。应用的代码配色本该只跟随当前主题，但皮肤里**混进了一份第三方深色主题**（GitHub Dark），它排在后面、把浅色模式下的代码文字整片涂成了深灰：正文对比度只剩 **1.18:1**（这就是「字很不明显」的本体），加粗、斜体、字符串、数字都在 1.18~1.49:1；聊天里的代码区还会被刷成一块深色底。而底色没被改——这正是「背景是白的、字却发灰」的来源。
  → 把那份第三方深色主题整个停用，代码配色只跟随当前主题（浅色一套、深色一套）；同时补齐我们这边缺的十来个代码元素的颜色（标题、替换符、属性名、正则、选择器、模板标签等），标题类元素保留粗体。
- **顺带：把浅色配色压到可读线**。原来那套浅色配色（One Light）本身偏淡——字符串只有 2.46:1、标题 2.82:1，都压在 4.5:1 的可读线（WCAG AA）以下，这也是「颜色看着发飘」的一部分原因。
  → **色相一个都没换**，只把亮度往下调：五个主题的浅色底上实测 4.60~5.20:1 全部过关，正文墨 13.4:1、注释 6.6:1。深色档同样一个数没动。
- **现在看到的样子**：浅色下代码块是一块带细边框的浅灰纸，字是深色、字符串深绿、关键字深紫、标题深红加粗——不再是「背景白、字发白」。这一版之后，代码块在五个主题、明暗两档下都按各自的配色走。

### 🧭 多步任务与表单：两处收口

- **子任务跟随**：任务里派出的子任务还在跑时，主任务不再抢先「收工」——页面状态跟随子任务，全部跑完才收尾；「停止」是明确终止：被停掉的子任务不会偷偷续跑。
- **表单一次问完**：AI 有时一口气给好几张「请选择」的表单，答完一张又冒一张。现在**一条回复最多一张**，方向与细节并进同一张（多步向导）——答一次就够。

### 💬 主页聊天：不再把新消息「吸」进老工作区

- **症状**：在主页（还没打开工作区）发一条新消息，应用有时会自己打开一个很久以前的工作区，把这条不相干的消息接在旧对话后面——几次下来，新内容总往同一个旧项目里塞。
- **现在**：改为**逐条对话打分**——只有消息里出现某个对话**独有的词**、且得分明显压过其它工作区时才会归位；分不出来就留在当前，不乱打开。

### ⌨️ 输入框：偶发「卡一下」与后台报错 —— 一起清了

- **症状**：切换对话、清空输入框这类操作之后，极偶尔光标没落回该在的位置，或某一下按键 / 输入没接上；同时错误日志里留下一串英文报错（Cannot find a descendant…）。
- **现在**：替换内容的同一拍就清掉旧光标位，新光标随后照常落位——报错与偶发的「卡一下」一并消失。

### 🤖 聊天：模型写出的工具调用不再漏出

- **症状**：某些模型偶尔不按格式调用工具，而是把整段调用**写成 XML 文本**（`<tool_calls>…<invoke name="…">`）直接糊进回复——聊天里冒出一长串没人认识的标签。
- **现在**：识别到这种写法会**真正把它执行掉**，同时在所有显示出口把这串文本清理干净——聊天气泡里不再出现标签；代码块里本来就该展示这类文本的内容不受影响。

### 📊 聊天：Mermaid 图表不再边生成边闪报错

- **症状**：让 AI 画流程图、时序图（Mermaid）时，图表在回答还没写完的过程中会不停闪出红色「渲染错误」框、偶尔冒出半张不完整的小图——因为图表内容还没写完，绘图引擎本来就解析不了半截内容。
- **现在**：生成过程中显示「图表生成中…」的占位提示，回答结束那一刻自动画出完整图表；如果图表真的写错了语法，写完后仍会照旧给出报错提示。

### 💬 聊天：AI 不再把旧消息当成最新一轮

- **症状**：在 WhatsApp 等通道里对话时，AI 答非所问、回复前后串味——问东答西，甚至把很早以前的任务当成新任务重做一遍；会话列表里那条会话的预览也是旧内容。
- **现在**：隐藏节点不再参与排序（界面上不变，历史记录下次保存时自动净化），喂给 AI 的上下文也不含它们；会话列表预览改用界面上真正显示的列表取最后一句。此前的「答非所问」「旧事重提」不再出现。

### ⌨️ 输入框两处：输入法回车劈段、长内容吞掉附件标签

- **中文输入法回车，消息被劈成两行**：症状——用中文输入法发消息时，正文里偶尔多出一个谁也没按过的换行（「用户列表拉 / 出来」被劈成两行）。现在这条默认动作会被拦下；真要换行仍走 Ctrl / Shift + 回车——一字不少，一字不多。
- **内容一长，末尾的附件标签「消失」**：症状——复制图片 / 文件进去，再接着写，写到第二段之后，末尾的附件标签会不见，写字的落点也不对（像被替换了）。现在长内容里光标不跑偏、附件标签稳定待在末尾。

### 🗂️ 聊天顶部：会话标签条回来了，标题也由 AI 起

- **会话标签条**：多会话并行开着时，切走正在跑的会话只能回会话列表里翻——聊天顶部回到一条标签条：**正在后台跑的会话带脉冲点**、非当前条悬停出「×」（流式期间点它 = 停掉那条流并关闭）、末尾「+」直接新建；只有一条且就是当前会话时整行不显示（那一格与标题重复）；标签等分拉伸，条溢出时细滚动条 + 当前标签自动滚进视野。只有工作台布局有它，搭档模式不参与。
- **AI 会话取名**：新建对话的标题此前是「首条消息截 50 字」——长问句原样上列表；而且本该随后换成模型短标题的升级**从来没有执行过**。现在：发送那一刻先落一条摘要式标题（列表立刻可读、模型没连上也有名字），随后由模型生成 ≤12 字的短标题**异步替换**——你手动改过名字就绝不覆盖；首轮就报错的会话也能取名。
- **顺带**：面板「会话历史」回到改版前的两行式（行首图标 + 标题 + 预览行），搭档模式保留一行式；面板这处此前的「运行中 / 刚跑完」状态位也补齐（转圈 / 对勾 / 实心点，点开即消）。侧栏顶部「在新窗口新建对话」的图标入口撤掉——聊天顶部的标签条已取代它（已开的多窗口与恢复不受影响）。

### 🧵 多会话并行（本版新增）：切来切去的一串「空白 / 断层 / 串台」，一次收口

- **症状**（一天里连着报的）：切走再切回来一片空白 / 显示「断开」；正在输出的内容看不到，要打断一下才显示出来；跑完的会话仍显示在跑；来回切换时视图上下跳（不如单轮顺）；开着 GOAL 模式时切走或新建对话，续跑会灌进别的对话。
- **现在**：这些是多会话并行通路上的一串结构缺口，逐条堵上——切走时「恰好为空」的界面状态不再被当成「有内容」（此前切回去会永远空白）；恢复中的流式内容不再被当场抹掉；后台跑完立即丢弃旧的界面快照（切回去读到的是完整回复，不再显示成「断开」）；跑完的流不再被「恢复」成还在运行；恢复后的零点几秒里后台工具调用不再被误杀；恢复后约 700ms 里视图逐帧贴底、之后回到正常跟随（不再上下跳）；GOAL 的续跑只回到原来那条会话——切走期间暂停，切回去照常，**宁可停、不串台**；两条会话在磁盘上互相污染、工具调用记录被写空两个写盘隐患也一并堵住。
- **另两处跨会话余波**：① 关窗 / 重载窗口之后，后台的多轮工具循环**真的会停**了——此前页面看着停了、后台还在继续跑、还继续消耗额度；② 上下文**摘要**（长对话自动压缩）在部分服务商下每轮都失败、被压缩掉的历史真的丢了（模型失忆的直接来源）——现在按当前服务商发送，切点也不会落在工具调用中间（此前会把一次工具调用劈成「孤儿」连环丢）。
- **顺带**：一条会让「看门狗」在 30 秒后误伤**下一条**回复的收尾链故障，以及「多个界面实例互抢同一条会话」的驱动源，一并修掉。

### 🔄 扩展管理：四个页签各自「检测更新」

- 技能 / 连接器（MCP）/ 专家（智能体）/ 插件，每个页签都有页头「检测更新」，每张卡片带「更新」按钮——装了哪一版、能不能升级，一眼看到，点一下升到最新版。
- 各类型按自己的来源比对：技能对照市场同名条目（本地自建的技能不参与）；专家对照官方专家注册表；连接器（MCP）按市场安装时记下的版本账（装得早、没记账的卡片，「⋯」菜单里备了「从市场重新同步」兜底）；插件沿用原有更新通道，检测入口提到页头。
- 有更新时卡片上是琥珀色的「更新」（这是状态提示，不是催你操作）：更新走各类型原有的安装通道覆盖升级，配置与数据不受影响。

### 🔍 扩展市场：社区插件先看详情再决定

- **症状**：在市场里看到社区插件想先了解下，一点名字直接被送去了 GitHub 主页——想看的内容反而找不到了。
- **现在**：点卡片打开详情弹窗，和官方插件同款：图标、名称、版本、GitHub / Gitee 来源章、星标、简介、作者、仓库地址，外加**「规范检查」**——不符合规范的会逐条列出问题（这也就是它为什么不能直接安装的答案）；底部有「打开仓库主页 ↗ / 关闭 / 安装」。
- 卡片上的「安装 / 更新」按钮照旧，点击不会顺带把弹窗也打开。

### 🔌 插件启动失败：错误提示改说人话

- 插件的后台服务起不来时，红色错误卡片现在会先给一句人话：**是哪儿坏了、该怎么办**。比如电脑上的 Node.js 运行环境损坏时，会直接写明「缺少依赖库 libsqlite3.dylib」、给出终端里照抄就能修的修复命令，并说明「这是电脑环境的问题，不是这个插件的问题」——不用再对着 `dyld: Library not loaded…` 自己去猜。
- 覆盖的常见情形：系统运行环境缺依赖库（附修复命令）；没装 Python / uv 等运行环境（附对应安装指引，并提示装完要重启一次应用；Node.js 缺装的情形多已由应用自带环境兜底——见「插件后台服务」一节）；没有执行权限；插件文件缺失或损坏（提示重装插件）；连接器配置不完整；连接超时；以及鉴权失败、地址错误、对方服务器暂不可用等网络类故障。
- 暂时认不出的错误**不给猜测性指引**——卡片保持原样。原始英文输出一字不动地保留在卡片下方（标注「原始输出（排查用）」），「复制详情」里也会带上这段人话诊断，照旧可以发给开发者或客服。
- 设置里的「连接器（MCP）」列表同样生效：测试连接失败时，红色徽章直接显示同一句人话结论（鼠标悬停可见完整建议与原始输出）。

### 📖 插件使用手册：多一路「仓库兜底」

- 插件「上手引导」里的使用手册，现在按顺序找四个来源：**插件目录里的说明 → 官方插件市场自带的说明 → 直接问插件要 → 它公开发布的源码仓库（GitHub / Gitee）里的 README**。
- 主要是社区插件受益：本地没带说明书、插件本身也问不出东西时，还能从它的仓库把 README 取回来，不再只剩一句「没找到使用手册」。
- 联网取不到就安静跳过——不弹错误、不打扰，和原来一样。

### 🔗 扩展市场 ↔ 扩展管理：一键互跳

- 装完插件想调整、或管理完想再挑点新东西，以前要在「扩展」面板和设置页之间自己来回找——现在两边各留了一个出口，而且**跟着你当前的位置走**。
- **在市场里**：面板右上角新增「扩展管理 →」，一步落到设置里的扩展管理页，并且落在与当前货架对应的页签——在技能市场点就落在「技能」页签，在插件货架点就落在「插件」页签，连接器、专家同理（「已安装」归技能）。
- **在扩展管理里**：页签行右端新增「扩展市场 →」，按当前页签落到对应货架，想去市场逛一圈不用再自己切活动栏。
- 两边只是互相「指路」：管理仍然集中在设置里，市场仍然只管发现与安装。

### 🧩 导入 dsh 插件：把「部分适配」说清楚

- 「导入 dsh（DeepSeek Harness）插件」现在写明**只能部分适配**——dsh 插件不能在 Notrat 完整运行：**技能可用**（SKILL.md 自动装进全局技能目录，导入后立即可用）；**工具不导入**（dsh 的工具代码跑不了，需要工具请以连接器（MCP）接入）。
- 菜单与导入框都带上了全名，第一次见「dsh」也知道是什么。

### 🧰 插件后台服务：找不到 Node.js 也能跑

- **症状一（Mac 为主）**：从访达 / 程序坞（Dock）打开应用时，插件的后台服务起不来、报「Command not found: node」；同一个人从终端启动同一个应用却一切正常。
- **症状二**：电脑完全没装 Node.js 的机器上，插件后台服务同样起不来。
- **现在**：查找分三级——① 系统路径原样；② 常见安装位置逐个找（Homebrew、nvm、fnm、volta 等），找到后先验证「确实能跑」再采用；③ 都没有时，**用应用自带的运行环境直接顶上**——电脑没装 Node.js 也能跑插件，无需任何安装。插件里所有用到 node 家族命令（node / npx / npm 等）的后台服务统一生效。

### 🔌 更新插件：不再「文件被占用」

- **症状**：在插件管理里对已安装插件点「更新」覆盖升级，可能直接弹出英文报错 `EBUSY: resource busy or locked`（文件被占用 / 被锁定）——更新失败，插件还停在旧版本。
- **现在**：更新与卸载前会**先停掉这个插件自己的后台服务**，连同它拉起的全部子进程一起收干净，再替换文件；每次启动还会顺手清扫此前遗留在后台的孤儿进程（父进程已不在、命令行指向插件目录的那种；父子都还活着的一律不碰）。万一仍有东西占着删不掉，给出的也是人话指引（重启 Notrat 后重试 / 在任务管理器里结束 node 进程），不再是原始英文报错。
- **顺带堵漏**：后台服务进程此前有几处「还活着却已经脱管」的缝——比如调用工具失败之后进程其实还在，但管理记录里已经被摘掉，从此谁也停止不了它；现在这类进程同样纳入统一管理，停止、重试、更新前清理都够得着。

### 📱 远程助手：「平台插件」改名「IM 插件」，扫码与连接查到「真」

- **改名 + 挂徽章**：设置里的「平台插件」正式改叫「IM 插件」（英文 IM Plugins），页签上挂一枚「内测 / BETA」徽章，面板里写明「接通更多平台，内测中，不稳定」——点进去之前就知道它还不算稳定功能；设置左栏的分类描述同步收口。
- **没登录不再顶着「已连接」**：微信等通道还没扫码时，卡片上就显示「已连接」——因为状态取自「后台服务跑起来了没」，而不是「账号真的登录了」；对比之下 QQ 机器人缺凭据时会正确显示「等待连接」。现在改为按真实登录状态显示：没扫码的显示「等待连接」，二维码在旁边安静地等；给 AI 看的通道清单同样用真话。
- **二维码不再赌第三方图床**：扫码二维码原先是一张第三方服务生成的外链图，网络受限时就是一块白图。现在改由应用本地生成（矢量图，任意尺寸都清晰，断网也有图），图下面恒附二维码内容与「复制」按钮；内容本身是网址时另给一个「在浏览器打开」。
- **扫码框改左右两栏，码和链接各配说明**：卡片很宽，二维码和几行说明原先是居中竖排，四行宽度不一的灰字像一堵墙。现在左边是图、右边是一栏：顶上一句扫码提示，下面是「扫不出来？」的兜底区——先说这是什么、再给内容、最后才是按钮。那段机器码也各自配了说明：是网址的告诉你「复制链接、发到手机浏览器打开就能继续」；不是网址的（比如 WhatsApp 的配对码）直说「不用看懂，复制过去用」。
- **WhatsApp：一串「用不了」，一次修完**：
  - **国内取不到码**：两条叠加——连接没有走代理（这个通信库不认系统的代理设置），加上内置版本号过期被服务器拒绝（即使连上了也拿不到码，只在日志里留一句超时）。现在显式走代理、版本号跟着官方网页版走。
  - **扫码成功反而登不上**：扫码配对成功后，服务器会要求「拿新凭据重连一次」，这一步做完才算真正登录；而当时重连的规矩只照顾「以前登录过」的连接，于是刚扫完就把唯一活路掐死，界面永远停在「扫完在这台电脑上确认」。
  - **登录后发消息没反应**：同一份凭据下起了两个连接（一个是启动时自动起的，一个是点「扫码连接」时又建的），两个互相把对方踢下线，一会儿连上一会儿断。现在同一个实例只保持一个连接，重新注册时也不会把自己刚连上的那个关掉。
  - **图片 / 文件 / 语音收不下来**：收取媒体用的方法挂错了地方（它属于通信库本身，不属于连接对象）——调用失败后来信全变成「[图片]」占位，AI 看不到图还满工作区找文件，后台 CPU 被拉满好几分钟。图 / 视频 / 文件 / 语音 / 贴纸五类一并修好，媒体下载同样挂上代理。
  - **只有一个手机号也能用**：此前「自己发给自己的消息」被一律跳过（防 AI 自问自答），而「给自己发」恰恰是单号用户唯一能对着说话的地方——看起来像「连上了但不好使」。现在放行自聊，同时给每条发出的消息编号、按编号防自问自答。
- **Telegram 的代理也是假的**：Telegram 在墙内必挂，而它一直以为自己配了代理——实际上代理从没真正装上（一装就报错，错误还被吞掉，日志反过来报「没装代理库」）。现在改用正确的装法（与 Discord / Slack 一致），失败时日志也会写清真实原因与代理地址。

### 🔍 插件页：单卡「检测更新」+ 每个插件一个日志入口

- **单卡「检测更新」**：此前「检测更新」一次查的是全部插件。现在每张插件卡的「⋯」菜单里可以直接「检测更新（只查这个插件）」——只查这一个、只写这一条结果，不动别的插件的记录，也不打扰「每几小时自动检查一次」的节奏；查到就长出「更新」键。
- **页头「全部更新（N）」**：检测出来有更新时，页头多一个批量升级键，N 是当前装着且有新版本的数量（不数市场里已卸载的残留）；逐个升级，进度写在同一行报告栏里。
- **每个插件一个日志入口**：此前全应用找插件日志只有一条路——藏在「上手引导」弹窗角落的一行折叠链接，找日志的人不会去点它。现在插件卡「⋯」置顶「查看日志」（没有后台服务的插件不摆这个空键），插件箱里右键也有同一项，两处打开同一个日志窗口。

### 📦 从社区装插件：优先装「能直接用的发行包」

- **症状**：从市场安装带界面面板的插件，装完一打开文件就报错（例如 LaTeX 助手打开 `.tex` 就一片红）。装进来的其实是仓库源码——作者提交的是「构建输入」（面板模板里还带着构建占位符），成品安装包躺在发布页里，而安装通路从来没看过它一眼。
- **现在**：优先下载作者发布的「安装包」（发布页附件），没有或失败才回落源码；发布包版本比仓库落后时不将就（宁可装源码，也不悄悄给你降级）；安装前还会检查一遍——面板源码里若仍带着未构建的占位符，直接拒装并写清来源与补救办法，把「装完就崩」提前成「装不上并说明原因」。
- **实测**：同一个插件走安装包装进来是 21 个文件、整装约 3 秒；走源码则是 274 个文件。

### 🪟 插件面板：能「搬」到桌面上单开一扇窗

- **来由**：插件带的面板此前只能待在应用里（页面 / 侧栏 / 底部抽屉这些地方）；想让「待办清单」「监控小窗」这类面板一直杵在桌面上，没有路可走。
- **怎么用**：面板右键「移动到…」里新增「独立桌面窗口（透明·置顶·每面板一个窗）」，选中即当场在桌面上开出来（插件箱那头也有入口）。想收回来：同一菜单里选别的落脚位置、或「恢复默认位置」，桌面窗口自动关掉。
- **窗口自带**：顶部一条拖拽把手（按住就能挪窗，不必找系统标题栏）、⚙ 设置、✕ 关闭。⚙ 里能调**不透明度**（最低 0.2——再低就看得见、点不着）、**窗口置顶**、**鼠标穿透**（点击落到桌面 / 下层窗口上）、**锁定位置**、**重置尺寸**，外加「**拉回屏内**」的兜底（窗口拖丢了用它找回来）。开着穿透时，鼠标移到顶部那条把手就临时把点击接回来——不会被锁在「点不着」的状态里。
- **记得住、你的优先**：位置 / 尺寸 / 不透明度按**你调过的**来（插件作者在包里写的是默认值，你的调整永远优先）；换显示器 / 改分辨率后自动夹回可见区；退出时开着的窗口，下次启动应用自己开回来。
- **插件作者侧**：面板声明里写 `location: "window"` 即默认开成桌面窗口，可附一组默认参数（尺寸 / 初始位置 / 不透明度 / 是否置顶 / 是否可缩放…）。

- **展开后也能拖**：拖拽把手原先只有那颗小球上有，一展开就被菜单盖掉——菜单或插板开着时就再也挪不动。现在菜单头部与插板标题行都能拖，松手同样会停靠到边缘。顺手修好两个隐患：拖动时用「当前这层窗口自己的尺寸」做边界（否则张开的面板能被拖出屏幕一大半）、以及抓取丢了之后「鼠标扫过头部窗口就跟着跑」的残留状态。
- **页面缩放不再把小圆球压扁**：把应用页面放大后，桌面上的悬浮球会被压成椭圆、上下还会被裁掉一点。现在悬浮器窗口固定按 1:1 显示，主窗口怎么缩放都不受影响。

### 📏 状态栏：窄窗不再挤碎

- **症状**：把窗口收窄（笔记本上分半屏、并排摆两个窗口）时，底部状态栏几处同时出毛病——「插件箱」这个词被压成一行一个字、折成两三行顶出栏条；字数统计（像「101 行」）从自己的位置溢出来，直接糊在右边的文件路径上，连成一片「101行G:\front_project\…」；文件路径被截断，偏偏又是从尾巴开始吃——先把文件名省没了，只剩一截目录，认不出是哪个文件。
- **现在**：给每条排了「谁让位」的次序——固定标签一律不缩、不折行；只有文件路径允许收缩，而且拆成「目录 + 文件名」两段：目录出省略号、**文件名整段保住**、贴右缘显示（鼠标悬停给出完整路径）。路径缩到下限还挤不下时，由插件徽章那一条自己裁尾兜底——插件箱入口与右侧的编辑器状态等项不受影响。
- **实测**：1107 / 980 / 935 / 860 / 800px 五档全部正常——不折行、不重叠、文件名始终可见；最极端的一档（800px 窗口 + 4 个插件徽章）也只是徽章条自己裁掉 3 个，路径尾巴、插件箱入口与右列都在。

### 🔒 免费版聊天输入框：不再「看着能点、点了没反应」

- **症状**：免费档（未登录 / 纯净版）的侧栏聊天框里，模型、思考、GOAL、完全访问、附件、菜单、发送——整条工具条看上去完全点得动，点下去全没反应；想升级，提示却缩在卡片最底下（字比正文还小），前面顶着一个锁 emoji，句子里还混着英文档位名。
- **现在**：工具条整条**变灰、不可点**——不再摆出「都能点」的样子（升级提示与「升级解锁」按钮在它之外，仍然可点，那是锁定态唯一的出路）；升级提示 + 按钮**挪进输入框那一格**，编辑器整格隐藏但内容、草稿、光标都原样留在原地，升级后立刻可用；锁形图标换成与全站图标一致的线性样式。
- **顺带统一档位名**：中文界面里混着的「Basic / Pro」全部改成「基础版 / 专业版」（知识库门禁、插件市场徽章、个人中心等 9 处），英文界面照旧 Basic / Pro；与服务器约定的判断串（「需要 Basic 或 Pro 套餐」）一字不动——那不是文案，改了升级引导会整条失效。
- **实测**：宽栏 / 搭档模式窄栏 / 更窄三种宽度实拍——窄档提示自动折行、按钮不被挤掉；工具条整条半透明且不可点。

### 🧩 装机版 DIY：终于能读 / 改源码了

- **症状**：安装版里打开组件 DIY 面板，左边组件清单是 **0 个**，源码两栏都写着「not found」。
- **现在**：构建时把可 DIY 组件的源码随包带上（**357 个文件 / 6.1 MB**），面板改走相对路径并检查响应——安装版也能打开、读、改组件源码了。出于安全，认证 / 权限 / 订阅等级 / 强制更新这几类组件的源码**不进包**（它们本来也不允许被覆盖，源码不该落到用户机器上）；组件清单同样修好（此前也是 0 个，同一个路径问题）。

### 🎛️ 搭档模式：上下文条与快捷设置的位置

- **上下文条补上「占了多少」**：搭档模式输入框下面那根上下文占用条原来只有颜色，占了多少完全读不出来（只能悬停看）。现在右侧补上百分比（如「62%」），条子整体左移一点、与发送键留出气口——不再挤在一起。
- **快捷设置弹层不再乱弹**：症状——面板压在输入框上、或挂到右侧文件树面板外压住对话文字、或弹得老高不跟手。现在**跟随鼠标弹出**、从左上展开（不会盖住刚点的那个条子——它是「再点一下关」的开关，被盖住就点不回去了），底边贴输入框上沿、不压输入框；上面放不下会自动翻到下方，并始终夹在屏幕内。做法与输入框「＋」号菜单**同一套口径**——面板多高都自动顶着往上长，不再需要「估高度」。
- **撤掉对话列宽度把手**：沉浸式（搭档模式）里对话列右缘那条细竖条是拖动调宽的——撤掉，宽度改为纯自适应（跟着可用空间长、到上限为止）。右侧详情栏的那个把手保留不变。

### 🖥️ 桌面悬浮器：✕ 真关闭、按钮点得动

- **✕ 只是「收起」**：菜单卡头部的那颗 ✕ 点了之后悬浮器还在——它的字面承诺（关闭）从没兑现过。现在它就是**真关闭**：与右键菜单、菜单底部那条是同一个动作；关掉后设置卡里的「已开启 / 已关闭」也跟着说真话。插件面板卡那颗「收起」（不再带 ✕）照旧只负责收起。
- **按钮点了没反应**：头部的 ✕（以及插件面板那颗「收起」）按下去毫无动静——悬浮器头部同时是「拖着挪窗」的把手，按下的一瞬就接管了这次点击，按钮的点击永远送不出去。现在按钮不再进入拖拽路径：都点得动，命中面积也按无障碍标准放大（实测 28×28，够 WCAG 的 24×24），鼠标移上去有高亮。
- **顺带**：悬浮器上的高亮提示气泡先前正好压在按钮上，一亮就挡几秒点击——现在它不再接收点击，纯展示。

### 🎛️ 上下文快捷设置弹层：装不下就翻到下方

- **症状**：从窗口上半部的上下文条（比如沉浸式工具栏那一条）点开快捷设置时，面板被压成一截——下面几组设置根本看不到，中间那个滑块看着像被「顶」住了。
- **现在**：面板开出来后会自动看一眼上下空间：**上方装不下、下方更宽敞就翻到下方显示**，整块都能看见；空间本来够用时，仍是从上下文条往上弹（原来的手感不变）。

### 🧰 设置与连接器市场：一串「点了没反应」清掉

- **AI 配置的「确定」一直是灰的**：症状——在设置 → AI 里改完东西，底部「确定」点不动（识图能力、响应格式这类改动它不认；已保存过的表单再进来，也还是灰的）。现在**「确定」永远可点**——没改动时等于写回同样的值，没有副作用；有改动走主色、没改动走中性，不再摆出「看着就是坏了」的样子。
- **连接器市场：配置窗卡死 + 「安装」永久灰**：症状——点「安装」弹出「填环境变量」的配置窗，窗里的输入框、取消、稍后配置、安装四颗一起灰着点不动；从蒙层逃走之后，卡片上的「安装」永久停在「安装中…」。现在只有真正开始安装时才会显示忙碌，逃出去也会自动复位。
- **各处失败不再零提示**：设置里「开始检测 / 重新检测」「清除所有缓存」「删除服务器」「新建专家 / 删除专家记录」此前失败时会静默——按钮转一圈、界面原样。现在失败都给出可见提示与原因。
- **A2A 的按钮不再卡死在「保存中…」**：开关 / 保存并重启服务 / 同步 Agent 列表三颗，出错时忙态不复位，就地变灰、标签卡在「保存中…」。现在统一走「出错必复位」的写法，失败原因亮在按钮下面。
- **插件包迁移与「问插件要」补上回声**：插件包「迁移到全局 / 工作区」失败时零提示（此前还可能出现「已经卸了、但没装有」的半途状态）；「问插件要帮助」查了个空也只是转一下圈。两处现在都会明说：迁移失败给原因，「问插件要」查空提示「插件可能没启用、或它没带帮助工具」。
- **错误日志弹窗的层级**：它此前容易被别的浮层盖住——现在挂到最外层，不再被压。

### 🔔 两处小修：侧栏「回到底部」与文件变更提示

- **侧栏「回到底部」按钮**：症状——面板模式下按钮几乎看不见（浅色主题下是近白底压在白消息区上）；切布局 / 切会话恢复之后，按钮该出现时不出现。现在按布局选用对的皮肤，恢复后按钮状态也会即时刷新——该出来就出来、该收就收。
- **文件变更提示与界面元素穿插**：症状——「AI 改了哪些文件」的提示会与输入区工具条互相压着、层级抬不起来。现在挂到最外层并定好层级，提示期间也不再吃掉底下发送键的点击。

### 🧩 全应用图标：一套字形语言

- **症状**：界面里的图标来自三个「时代」——同一排工具条里混着四档大小、四种线条粗细，有的还是彩色 emoji；两条边栏（活动栏与侧栏）用的甚至是两套字形，并排看很不对劲。
- **现在**：全应用 **332 个图标**整批换成同一套线性图标（lucide），活动栏那 27 枚整套重画——两条栏终于说同一种字形语言；尺寸与线条粗细收成一套刻度，图标按钮都补上了读屏可读的名字。两枚重点图标也已定稿：**对话压缩 = 三层叠片**、**远程 = 手机 + 平板**（把整套 3800 多枚铺成对比页逐枚挑定的）；模型切换那枚「打印机」换成了芯片。文件树里被这轮波及的两个图标尺寸也一并补回。

### 🎨 主题切换：一次转场，不再重渲整棵树

- **症状**：切换明暗 / 主题那一下明显卡顿——界面先冻住、再「啪」地整体跳过去。
- **现在**：切换改为一次约 220ms 的**颜色转场**（颜色、边框、阴影平滑插值，而不是瞬间跳变）；同时，切换时编辑器不再被销毁重建（正文与光标保持原样）、图表也在转场结束后再重画。从「顿一下再跳」变成「一眼化过去」。

### 🔤 对话字体：字号与字体进了设置

- **在哪**：设置 → 外观 → 对话字体，两行——「正文字号」12–22px（默认 12，与从前完全一致）与「字体」下拉（与编辑器同一份清单：默认档「跟随界面」，也可一键加载本机系统字体）；两行各带一行**实时字样预览**，盖着设置页就能当场比。
- **跟着谁走**：搭档模式正文比它大一档、气泡与代码块等比缩放；胶囊 / 时间戳这类小字**故意不跟**（保持一屏的密度）。点「确定」生效。

### ⌨️ 输入框：主色柔描边 + 底色抬一档

- **症状**：侧栏与搭档模式的输入框「不明显」——灰描边与整屏卡片同色、底色和背景几乎一样，一眼看不出该在哪里打字。
- **现在**：描边换成**主色柔描边**（聚焦时加深），底色上抬一档（聚焦回满）——输入区在全屏里有了一处自己的颜色表态；口径与欢迎页那个聊天盒对齐（全应用唯一没被说过「不明显」的输入框）。聚焦信号交给「描边加深 + 外圈光环」，底色不再继续加深——再深就成「灰板砖」了。

### 📦 安装包瘦身：体积少掉约四成

- **症状**：安装包大得离谱——三合一通用安装器 1033 MB，单架构也有 344.8 MB，下载慢、升级也费流量。
- **现在**：安装器通用 1033 → **635 MB**、单架构 344.8 → **212 MB**；装完之后整个安装目录 1.4 GB → **748 MB**。

### 📦 打包与安装：三处老毛病一起清

- **安装包缺依赖（「压缩为 ZIP」报错）**：1.3.4 各平台安装包里有若干依赖没有打进去——最早被反馈的是在文件树里右键「压缩为 ZIP」直接报 `Cannot find module`；另有几处同根源的漏装（影响图表、消息渠道等场景）。现已从打包流程上修掉，并新增「打包前体检」：任一依赖没进包就中止打包，从源头防止再发出这类安装包。**已装 1.3.4 的朋友正常升级到修复版即可，无需其他操作。**
- **Mac / Linux 版「实时编译」整体报错**：Mac 与 Linux 的正式版里，凡需要实时编译界面的功能——DIY 定制组件、带界面的插件面板等——一律报错打不开（Windows 版不受影响）。现已补齐，Mac / Linux 上这些功能恢复正常。
- **插件包目录被「压扁」**：少数来源的插件包在 Mac 上会被解成一团——插件看着装上了、实则起不来。安装流程现在会先规整再落盘，这类插件包也能正确安装；**此前被装坏的插件，到插件市场对那个插件点一次「重新安装 / 更新」即可恢复。**

### 📢 公告等 Markdown 图片：应用内不再裂图

- **症状**：公告（以及其它以 Markdown 呈现、图片放在自家图片服务上的内容）在客户端里图片一律显示不出来——只剩裂图。
- **现在**：公告里的插图恢复正常显示；其余网络请求的处理方式不变。

### 🔧 后台小修三则（看不见，但该修）

- **重载后的「输入自愈」补上一环**：应用重载后偶发输入框打不出字，错误日志里每次加载还会多一条无意义报错——这一环现已补全，两处都正常了。
- **浏览器自身的循环告警不再上报**：错误日志里少一类无意义的噪音条目（本地日志仍完整保留）。
- **编辑器格子加载失败不再拖垮整窗**：某个编辑器格子的代码加载失败时（例如刚更新过、缓存失效），以前整个窗口会变成一张报错页；现在只影响那一格——格子里直接说明原因，并给一个「重新加载窗口」的按钮（未保存的改动会丢，先存再点），其它格子照常用。

### 💻 Mac：终端打不开、退出弹「意外退出」

- **终端只有一行 `posixspawnp failed.`**：Mac 上打开终端面板就这一句。现在打包时强制补上所需权限并**复核**，缺了就直接中止打包（宁可不出版本，也不发「一开终端就炸」的包）；那份小助手若没有代码签名，打包时也会补一个本地签名。
- **退出弹「"Notrat"意外退出」**：Mac 上每次退出都弹系统的意外退出框。现在改成「**先把收尾做完再退**」；收尾超过 4 秒会自动放行，任何情况下都关得掉，不会卡在「退不出去」。
- **已经装着旧版的 Mac 用户**：这两处都不用干等新版本——找我们拿一份「就地修复」小脚本，跑一遍即可（只改安装包里的权限位，不动包本体；终端那处跑完生效，退出弹窗那处重开一次生效）。

### 🔗 公告里的链接：不再把应用整个带跑

- **症状**：公告里带链接时，点一下整个应用窗口被导航到那个网页——无边框窗口没有地址栏也没有返回键，等于把应用「开没了」，只能重启。
- **现在**：公告里的链接改走**内置浏览器标签页**（在应用里就能读、能关）；拿不到内置浏览器、或本就不是网页链接（邮件、电话、页内锚点）时交给系统默认浏览器。顺手修好一处：从设置 / 商店 / 账号这些页面点开链接时，应用会先切回带标签栏的界面再打开——以前那种场景下页面开在看不见的地方，点了像没反应。
