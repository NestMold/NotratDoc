## ⚡ 更新亮点

- **🧩 插件图标统一成 Notrat 的样子**：没写图标的插件不再落 emoji，默认就是与 Notrat 本体同款的 lucide 线性图标（描边统一 2px，缺省是拼图 Puzzle）。插件作者可以从 83 枚常用图标里挑一枚写进 manifest（`lucide:Workflow` 这样写），也可以用自己的图片——脚本会把它缩成 webp 内联进插件，不用另外传文件。动手开发插件时，插件开发技能会先问你图标想用哪种，不用自己翻文档。
- **🔁 插件箱右键就能重载插件**：在状态栏插件箱里右键任意插件，菜单里多了「重载插件」。它和「扩展管理 → 插件卡片 → ⋯ → 重载」是同一件事——清掉旧覆盖、重新编译面板与渲染器、重启该插件的连接器。改完插件文件就地生效，不用再绕去设置页。
- **🔄 软件更新搬进了设置，升级全程不用离开 Notrat**：`设置 → 通用 → 软件更新` 和用户中心顶部的「检查更新」是同一套。发现新版本会在后台自动下载并显示百分比，不打断手上的写作；下载校验完成后点「重启并安装」，应用内先显示安装状态，安装器窗口接着显示真实的文件替换进度，装好自动重新打开 Notrat——不用再自己去开始菜单点一遍。
- **📚 文档随应用内置，断网也能看完整教程**：使用教程、插件开发、平台文档、更新记录整套文档站随安装包一起带上。帮助页「使用手册」分区下新增「离线副本：随应用内置，断网也能看完整教程」与「打开离线文档」；平时点文档照旧打开线上站，**断网时会自动换成离线副本**——欢迎页、设置、空工作区首页、悬浮器里的教程入口同样有效。在内置浏览器里看文档时，地址栏多一枚硬盘按钮可随时切到离线副本；文档站打不开或不允许嵌入时，兜底提示里也有「打开离线副本」。
- **🧭 新手引导改成直接看教程**：新手任务清单与右上角「✨ 新手任务」徽标不再出现（组件与进度数据保留，暂时收起），自动播放的产品动画教程一并移除。欢迎页唯一的下方文字链改为「📖 第一次用？5 分钟写出第一篇」，点开直达文档站的入门教程；空工作区首页（还没有任何最近项目时）也常驻同一条入口，关掉欢迎页后仍找得到。悬浮器菜单里的「新手任务」改为「使用教程」，公告铃铛也不再因为清单没做完而押后重要公告。
- **🧩 插件面板能「整页」打开，位置菜单也收进了二级菜单**：面板右键的「打开方式」现在有三档——跟随位置 / 标签页 / 整页。选「整页」后，面板像设置、图谱、定时任务一样占满主区、没有编辑器标签栏，活动栏对应插件按钮高亮为当前页；整页面板如果自带侧栏，再点一次活动栏图标即可开合它。13 个位置不再平铺成一根长条，而是收进「面板位置」二级菜单（父行直接显示当前位置）；「打开方式」只在点开才出现的位置显示，常驻面板、悬浮窗和桌面窗口没有这一问。
- **🔌 插件连接器闲下来会自动休眠**：插件自带的连接器（MCP）超过 10 分钟没有被调用，就停掉后台的 node 子进程——17 个插件全开时，这部分常驻内存的理论峰值约 700MB。工具清单和配置仍留在内存里，AI 的工具列表、插件面板都不会少东西；下次调用会自动把进程拉起来。用户自己配置的连接器、SSE / HTTP 连接、有调用正在进行的，都不会被回收。
- **🖥️ 初始字体大小跟着屏幕走**：以前不管屏幕多大，应用都按同一个比例放大（1.2 倍），1366×768 这类小屏笔记本上 14px 正文会被放到 16.8px。现在建窗时按屏幕工作区大小分档：大屏维持原样，普通笔记本降到 1.0，更小的屏幕降到 0.9；`Ctrl+0` 也会回到「当前屏幕的默认档」，不是固定 100%。
- **🛡️ 必须升级的旧版本，应用会先请你更新**：当服务端判断某个版本必须更新时，应用会盖一层不可关闭的全屏提示，列出更新说明并自动下载安装包；下载校验完成后点「重启并安装」，装好自动回来，期间不能继续使用旧版本。下载失败或安装包缺失时会给出安装器直链，不会出现「文件删了却没有安装器」的死角。
- **📄 Word / Excel / PowerPoint 不再「读不懂、改不动」**：AI 现在能直接读 `.xlsx` / `.xls` / `.xlsb` / `.xlsm` / `.pptx` / `.pptm` / `.ppsx` / `.ppsm`（表格按工作表输出、幻灯片按真实页序取文字），把文件拖进对话也能看到正文摘要，不再只塞一串 base64。Excel 编辑器不再只显示 A–Z 和 100 行，能读实际使用范围、合并单元格与「显示更多行」；Word 保存会尽量保留图片、表格、链接和换行；PPT 预览按演示文稿自己的页序显示，并补上主题色、表格、项目符号与背景图。
- **🧩 一个插件面板可以同时挂在多个位置**：右键「面板位置」从单选改为多选——例如同时保留活动栏按钮、右侧停靠栏和桌面窗口；父行显示「首个位置 +N」，勾选状态一眼可见。三个与 AI 对话相关的位置也改成了更具体的名字：「AI 对话输入框上方」「AI 对话消息区顶部」「AI 对话工具栏」。
- **🧠 启动内存大幅回落：会话从「整桶读写」换成「索引 + 一会话一文件」**：以前一个工作区的全部对话装在同一个大 JSON 里，应用一启动就要整份读进来——本机一个 52MB / 27 个会话的工作区，光解析就多占约 178MB 内存。现在启动只读一份几十 KB 的索引和当前正在看的那个会话，其余对话只带标题/时间等元信息，打开时才补正文。同一个工作区实测：内存增量约 178MB → 22MB，启动读取 550ms → 59ms。从这一版起默认走新存储，旧数据首次启动自动迁移一次、原文件保留只读。
- **🧾 AI 改过的文件，Sidebar 里也能开「查看差异」标签页，两种改动都能撤销**：写文件类工具和终端 / 脚本命令动过的文件，现在都能从侧栏的「查看差异」直接打开编辑器标签页——页头标出已新建 / 已修改 / 已删除与增删行数，右边可「打开文件」或一键撤销。撤销前会先确认，动手前再读一遍磁盘确认文件仍是 AI 那次写下的内容；这期间你又改过就停下并提示，不会拿旧内容盖掉新内容。
- **💬 对话里也能划词引用了，右键还有菜单**：在侧边栏或搭档模式的对话正文里选中一段文字，选区旁会弹出「引用到聊天」——点一下就把选段钉到输入框上方，随下一条消息一起发给 AI，来源标为「对话」。发出去之后，消息里也还是这张引用块——来源、行号和选段预览都在，不会变成一张还要再点开的文件卡。选中文字后右键，会弹出「复制 / 引用到聊天 / 全选」；没有选中文字时右键保持原样。纯净版只在右键菜单里保留复制与全选。
- **📝 脚注能和正文互相跳转**：点正文里的上标数字，直接滚到文末对应的 `[^N]:` 定义，光标落在说明开头；点定义行开头的 `[^N]:`，再跳回正文里的第一处引用，目标会滚到可视区中间。找不到对应目标时照常编辑，不会拦点击。
- **🎨 编辑器菜单的图标统一成一套**：工具栏、右键「插入」子菜单和斜杠命令现在共用同一套 lucide 线性图标。文件引用 / 图片 / 嵌入不再用 📎 / 🖼️ / 📄，行内公式、块级公式、代码块也各有各的字形；斜杠命令里 29 个手写 SVG（H1/H2 甚至是用文字拼的）全部换掉；工具栏的「脚注」按钮从上标 x² 换成书签加号。
- **💬 活动栏的按钮，鼠标一停就说清是干什么的**：图标右侧浮出一枚反色小气泡，第一行是完整名字，第二行用一句人话说明它的作用——工作台是「AI 和你一起修改内容」，搭档模式是「AI 是你的搭子，全盘接手」，远程助手、定时任务、自进化实验室、图谱、扩展、帮助、导出、便签、设置也各有说明，中英文跟着界面语言走。公告、头像、插件箱、插件按钮和「更多」同样支持。气泡不占排版、不吃点击，扫过时不弹、拖动排序或菜单展开时自动收起；入场 200ms 减速展开、离场 120ms 快收，按下时不会跟着按钮一起抖。
- **🖼️ 图片能按方向拉伸，调过的尺寸会记住，导出 PDF / Word 也照这个来**：选中图片浮出八个手柄——拖四角等比缩放，拖四边只往那个方向拉伸，可以把图压扁或拉长；右上角多一枚「恢复默认大小」，双击手柄、右键「图片大小」也能还原。尺寸随文档保存，下次打开仍是调好的样子；导出 PDF 与 Word 都按这份尺寸来，Word 导出也从「只剩文字」改成真正嵌入图片。
- **💬 AI 侧栏：默认展开，收起时滑向状态栏，还有一句话告诉你去哪找**：活动栏的「搭档」改叫「AI 搭档」，状态栏那格改叫「AI 对话」。打开应用（包括还没打开工作区时）侧栏默认就在；点右上角 × 收起时，面板向状态栏方向收拢，随后在状态栏「AI 对话」按钮正上方浮出一枚指路气泡——「AI 对话已收起到底部状态栏，点这里随时打开」。点气泡或状态栏那格都能重新展开，收起途中点状态栏会取消这次收起。开着「减弱动态效果」时省掉动画，气泡照常出现。
- **🎨 编辑器正文：表格、引用换成轻圆角**：表格从直角网格变成圆角卡片——外框 1px、四角 6px，单元格只留右 / 下分隔线；引用块加一层比正文深一档的柔填充、圆角 6px，左侧竖线保留；任务清单复选框也换成圆角勾选块。图片保持直角，四角不裁。只是轻轻收边，不抢正文的注意力。
- **🗂️ 对话记录按工作区归口，组合窗口里两个工作区都在**：Sidebar 与工作台会话栏的列表按工作区分组，组的先后固定跟文件树里的根顺序，切换当前工作区不会让列表重排；当前工作区打「当前」，组头写着这一组共有多少条、可以整组收起，点其它组的会话会先切到那个工作区再打开。一个窗口里组合了两个工作区时，两边最近的对话都能看到；只有还没打开工作区时才聚合全部，没归属的旧会话单独归「待归档」，工作区里不再混进来。欢迎屏「最近」也分成「工作区 / 对话」两页签，对话页一行标题、每个工作区最多三条。
- **🕘 对话记录能按时间分栏，搜索直接搜聊天内容**：列表按今天 / 昨天 / 3 日内 / 7 日内 / 一个月内 / 很久分栏，点栏目标题就能展开或收起；全部展开装得下时保持全开，装不下只展开首屏里的栏，搜索时自动全部展开。搜索不再只看标题——第一句用户消息和最后一条回复里的词也能命中；打开会话后正文里会标黄并支持回车逐个跳。点一下「新对话」留下的空会话不再占列表。
- **🔍 左栏的两个搜索并成了一个框，框里选「文件」还是「内容」**：以前文件树顶上有一个按名字筛树的框，左栏「搜索」面板里又有一个搜文件内容的框，两个长得一样、分在两处，新用户不知道该点哪个；想「先按名字找、找不到再搜内容」还得换一处、词重新打一遍。现在只剩工具条上这一个框：点开后左端多一枚「文件 / 内容 ▾」，选「文件」照旧按名字筛树，选「内容」就在整个工作区的文件内容里找（大小写 / 全字 / 正则、按文件分组、点行跳转、替换都在）。两档共用同一个框，切过去切回来词还在。左栏标题栏原来那枚放大镜按钮也一并撤了——框里换档就够，`Ctrl+Shift+F / H` 仍然直接落到「内容」这一档。
- **🧩 工作台右侧合成一整块：AI 对话、会话列表、插件侧栏都在这里**：以前 AI 对话和插件侧栏是两列、两个开关，切到插件页还会把聊天顶掉；现在它们共用一块右区——左边聊天，右边会话列表，头部右上角两枚图标在「对话 / 插件」之间切换，插件数量直接压在角标上。插件页占满整块，会话栏隐藏但宽度保留，编辑器不会跟着抖；设置、市场、扩展、远程助手等普通页也用同一块，不再各摆一套。底部状态栏只留一枚「AI 对话」开关，负责整块右区的开合：收起时点它先回到对话页，停在插件页时点它先切回对话；AI 正在跑时按钮上会显示「AI 运行中 · 12s」。全屏键在右区头部，点一下进入原来的搭档模式。
- **💬 会话列表变成右侧一条窄栏：176px 起步，能拖宽、能收起**：历史对话默认只占 176px（也是最小宽），拖左缘可在 176–400px 之间调；一行一条、只显示标题，不再单独画标题行。收起后整栏归 0 宽，输入框旁的历史按钮就是开合入口，正在跑的会话标记也挂在上面；再点历史按钮，放得下就放回常驻栏，屏幕右边还有位置就先扩窗，都没有才从右缘拉出抽屉，盖住聊天但不改列宽。
- **➕ 每个工作区旁边都能直接新建对话，搭档模式的搜索框也挪到了顶栏**：会话列表里把鼠标移到工作区组头上，右侧会露出 ＋，点一下就在这个工作区里新建一条对话（在别的工作区时先切过去再建）；工作台会话栏和搭档模式左栏都有。搭档模式左栏顶栏的第一行是「退出工作区 / 新对话」，搜索框独占第二行、占满整栏。
- **🖱️ 对话能拖着换工作区、也能拖进拖出「工作空间」组，工作空间的悬停列表也能点**：在会话列表里按住一条对话，拖到另一个工作区组头上松手，这条对话就连同完整历史搬到那个工作区；拖到顶部「工作空间」组头上则把它变成空间级（留在原工作区，显示在空间组下），再拖回工作区组就退回成工作区级。拖动时组头会亮起；当前对话拖去别的工作区会提示先切走，只改空间归属则不受限。另外，欢迎屏悬停工作空间行浮出的内部工作区列表现在可以停留、可以点——鼠标移进去不会消失，点某个工作区就以它为当前根打开整组。
- **🔎 搭档模式点「运行详情」不再跳去编辑器标签页**：全屏里点某一轮的运行详情，直接在右侧停靠栏展开这一轮的详情，不退出搭档模式；编辑器标签页只留给工作台 / Sidebar 形态。
- **🏝️ 运行岛：进度浮在编辑器顶上，点开就是本轮详情**：AI 开始跑工具后，编辑器顶部浮出一条运行岛，不用切页就能看到当前在做什么；结束时停留 8 秒，显示「已完成 · N 个文件已改 · 26s」或「运行失败」。点岛展开 380px 浮层，直接看这一轮的步骤、工具、改动与耗时，底部注明「记录跟随本轮 · 不占常驻栏位」；浮层里可停止，Esc 或点外面关闭。改动照旧一键打开 diff 标签页。侧栏收起时岛还在；从状态栏展开侧栏只展开右区，不会自动把岛弹开。不想看时可以整关：设置 → 面板里关掉「显示运行岛」；只想躲开这一轮，鼠标停在岛上点「停止」左边那枚「隐藏」就行，下次运行它自己回来；藏完会弹一条提示，告诉你去设置里重新打开。
- **⌨️ 键盘快捷键页不再列系统自带的 7 条**：复制 / 粘贴 / 剪切 / 全选 / 撤销 / 重做 / 查找这些浏览器和编辑器自带的快捷键，页面上不再单独列出来占版面——它们照常生效，页脚「编辑器自带的快捷键会自动生效」那条提示还在。
- **🗂️ 一个窗口可以装下多个工作区**：在打开工作区对话框里多了「附加到当前窗口」——保留当前工作区，把新目录作为同一窗口里的另一个根。文件树会同时列出多个根，几个根按添加顺序排列，对话列表里的工作区顺序与它完全一致；窗口左上「Notrat」下面写的是这个工作空间的名字（没起名时用各根名字拼起来）。点根名切换当前根，你正在看哪个根里的文件，哪个根的名字就高亮成主题色。跨根拖文件会先问一句「这会把 N 个项目移出当前工作区，放入「X」」；重启后所有根和当前根原样开回，关闭工作区则回到欢迎屏。
- **🧩 工作空间：给常用的几个根起个名字，一键开回**：窗口里有两个以上根、根数稳定下来时，Notrat 会自己弹出命名框问你这组工作区叫什么（默认用文件夹名以「 + 」拼起来，最多 80 字）；起好名字就把这组根和当前根记下来。欢迎屏的「工作空间」区按名字列出，点一下整组打开；菜单里也能随时重命名或删除。删除只会删这个名字，不会动磁盘上的任何文件；工作空间里的目录都打不开时会明确提示，不会只给你一个空窗口。
- **🧩 工作空间并进「最近」，还能整组开新窗、多个空间合成一个**：工作区菜单顶部不再为当前空间铺「段头 + 重命名 + 删除 + 合并」四行——所有空间（含当前）和最近工作区同列在「最近」里，用层叠图标区分；当前那个只在行内打「当前」徽章，重命名 / 删除 / 在新窗口打开 / 合并收进行内常显的「⋯」和右键菜单。点一个空间和点一个工作区一样，先问「当前窗口 / 新窗口」，选新窗口会把整组根一起带过去，重启后也照原样恢复。「合并工作空间…」把勾选的两个及以上空间去重合成一个新的命名空间（目录不动），原空间保留。「最近」也不再让工作空间和工作区各排一队：两边混在同一条「最近打开」的时间轴上，整组打开只记这一组，成员目录不会各自插一条（除非你单独点开过它）。
- **🗂️ 菜单底部多了「全部工作空间…」，一次看全已保存的空间**：只列工作空间（不含零散工作区），带搜索框；点一行按原来的动线打开（当前窗口 / 新窗口）。同时打开一个空间会刷新它的「最近使用」时间——50 条上限淘汰的永远是最久没打开的那个，而不是最久没重命名的。
- **🧩 工作空间现在也能「装东西」了：连接器、技能、插件都多了一档「只属于这个空间」**：以前安装资源只有「全局 / 当前工作区」两档——工作区档只认当前打开的那个根，空间里的另一个根看不到。现在安装范围多了「工作空间」：装一次，这个空间里的所有工作区都能用；换当前根不会消失，换到别的空间也不会串味。优先级从近到远是「当前工作区 > 工作空间 > 全局」，同名的就近生效。插件包的 ⋯ 菜单和设置里的连接器都能在全局 / 工作空间 / 工作区之间搬家；连接器市场点「安装」也会先问一句装到哪。
- **🔌 插件也认多工作区了，老插件不用改**：插件拿到的当前工作区仍是活动根，旧写法照常工作；同时能拿到本窗口的全部根，增删根会即时刷新，插件窗口和悬浮器也跟着主窗口的当前根走。
- **🧰 AI 会分清「附加工作区」「当前窗口切换」「新窗口打开」了，还能新建并附加**：AI 现在能用专门工具读本窗口的全部工作区根、附加目录、切换当前根、在新窗口打开，以及一次完成「建目录 + 打开 / 附加 / 开新窗」。系统提示新增一张路由表：用户说「附加」绝不会再拿「打开工作区」顶替，说「新窗口」也不会；目标说不清时先按路径和聊天内容打分给候选，拿不准就问，不再瞎猜。
- **🗂️ 对话能归档到另一个工作区，历史完整跟过去**：让 AI 把某条对话「移到 / 归档到某个工作区」，它会先按标题或内容找到那条对话，再整条搬过去——正文和消息顺序原样保留，目标工作区的列表立刻多一条，原工作区少一条；正在看的这条会先拒绝，避免界面和磁盘打架。
- **🧩 「新建工作区并附加…」搬进了打开方式对话框**：新建工作区后，如果窗口里已经开着工作区，会照常弹出三选一——「在当前窗口打开 / 附加到当前窗口 / 在新窗口打开」；选「附加」就能边建边挂进当前窗口，不切当前工作区、不打断正在进行的对话；窗口里因此有了多个工作区时，它们合起来就是一个「工作空间」。文件树工作区根右键也保留了这个入口。想反过来「先选工作区、再新建一个附加进去」也行。
- **⏳ 发送有两种：直接打断，或者排队**：AI 正在回复时按 Alt+Enter（或输入框旁的排队键），这条消息不会打断当前回答，而是连同附件、消息级 MCP 一起排进队列，等这一轮结束再按顺序一条条发。输入框上方会出现队列横幅：「当前回复结束后发送（N 条）」「压缩完成后发送（N 条）」或「已暂停：N 条排队消息」；点开能看每条内容，也可以手动点「发送」或「取消」。
- **🛑 停止键停到底：子任务回传、截断续写、空回复重试都不再自动续跑**：以前点停止只停住眼前这条流，后台子任务晚一步回传、截断续写或空回复重试又会把对话拉起来，看起来像「明明停了还在输出」。现在停止会落一道封条：这几条自动续跑路径全部拦住，队列里的自动条目直接丢掉，用户排队的消息也只暂停不自动发；只有你亲手发出下一条消息（或手动点队列里的「发送」）才解封。
- **📝 刷新 / AI 重载不丢编辑器草稿，回复流完再刷新**：AI 调用刷新时，先给所有有未保存改动的文件拍一份快照（连保存基准一起），再等主对话、子任务和待发送队列都清空，才真正重载；等待期间回复继续流，不会在半句话时被切断。刷新、热更新、AI 重载后，草稿会自己回到编辑器里；保存、关闭文件或主动重新加载时才清掉。
- **🛡️ 磁盘上的新内容不会静默覆盖你的旧草稿**：AI 或别的编辑器刚把文件改到新版，而你这边还停着未保存的旧草稿——以前一保存就把新版盖回去，连提示都没有。现在编辑器会明确告诉应用「这次外部内容我没采纳」，保存前给出三选一：重新加载磁盘版 / 覆盖保存 / 都留下（能合并的自动合并，改到同一处用冲突标记标出来）。
- **🕒 定时任务：每次运行一张卡，日志收得起来**：以前所有运行挤在一屏日志里，看不出这次跑成功没有、从哪开始到哪结束。现在每次运行一张卡片：成功 / 失败 / 未完成 / 运行中一眼可见，旁边是用时和一句结果摘要；点开卡片才展开这一轮的完整过程与原始日志。页面顶部还会汇总今天的成功、失败次数。
- **🎛️ 设置能一键恢复默认，AI 搭档点一下就开**：设置页底部多了「恢复默认设置」按钮，二次确认后把外观、模型、对话、面板恢复默认，活动栏布局也一起重置；点「确定」才生效，点取消什么都不动。活动栏的「AI 搭档」不再先问你「侧栏还是搭档」，点一下直接在工作台右边打开对话；想一打开就整屏用 AI，去「设置 → 面板 → 活动栏按钮」把新增的「AI 全屏」那格点亮即可（默认收起，不占所有人的栏位）。从侧栏进全屏时，对话会以转场动画长成整屏，不再是硬切。
- **📐 窗口变窄，左右栏按比例让位；你拖到哪儿，哪儿就是上限**：以前窗口缩小，FileTree / AI 列还按原来的固定宽占着，编辑器被挤没；现在用户拖定的宽度是「上限」，窗口变窄时各列按比例缩，缩到各自下限为止（AI 列 180px、FileTree 160px）。FileTree 拖到 160–219px 之间松手也不会再弹回 220px；会话栏在编辑器低于 420px 时自动收起，只有窗口重新变宽、且多出 16px 余量才自动放回，不会在边界上来回跳。
- **🗂️ 打开工作区能一次选好几个目录，选完问你要不要合成工作空间**：在「打开工作区」的系统目录框里按住 Ctrl / Shift 多选，选了不止一个，应用会停下来问一句「检测到您选择了多个工作区，需要合并成工作空间吗？」。确认页可以先给这个空间起名（默认用各目录名拼起来，如「docs + src」，也能改成自己喜欢的名字）。合并只是把这几个目录记成一个工作空间，磁盘上的文件一个都不动；之后照常按「当前窗口 / 新窗口」打开整组，欢迎屏和菜单里也能按名字整组开回。只选一个目录时和以前完全一样，直接打开。
- **💬 AI 正在回复时切换工作区，先问一句「这条回复要不要留着」**：在当前窗口打开另一个工作区或工作空间时，如果 AI 正在写，应用不再直接换过去。第一项「把「X」附加进来，对话不断」会把目标目录并进当前窗口——两个工作区就是一个工作空间，正在写的回复照常继续，AI 也能同时处理两边；第二项「仍然切换」明确结束这条回复；也可以取消留在原地。左下角还有「以后切换工作区时不再提醒」，勾一次之后就不再弹。

- **🧭 计划模式：先把计划写清楚，再按步骤派专家去做**：「工作场景」里多了「计划模式」。勾上它，AI 会先把「## 执行计划」完整写在回复里——每一步做什么、动哪些文件、怎么算做完、哪些步骤能并行；写完直接开工，不用再确认一次，也不用另外打开什么开关。能独立完成的步骤交给对应的专家分头做，互不依赖的同时派出，AI 自己负责拆解、验收和汇总，每完成一步回一行「✓ 第 N 步」；计划与进度都在对话正文里，按停止随时打断。原来的「代码规划」独立档与计划卡随之退场。场景面板也顺手重排：每张卡整块可点，「日常任务」只能单独使用，其余场景可以多选。
- **🖼️ AI 能自己「看」它读到的图，认不认图也会用着用着就准**：AI 用工具扫到图片时，识图模型直接拿到图像本身，不用再让你把图贴进对话；不认图的模型会收到一句「这张图你看不到」和该怎么绕（转存成文本、换识图模型），不会照着文件名瞎编。哪些模型认图以前只靠名字猜，连模型列表里明明写着「(视觉)」的 `qwen3.6-plus` 都会漏判；现在接上了应用里已有的两张模型能力表（Coding Plan、MiMo）。服务商接口只回模型名、拿不到「收不收图」，所以还加了一层真实收发学习：发图被拒就记住这个模型不收图、下次直接按文本走；带图跑通就记住它收图，90 天后自动作废重判。Claude Code 这类导入进来的服务商给的是裸模型名（`sonnet-5` / `opus-4.8` / `haiku-5-…`），以前一个都认不出、只能手工改设置，现在也认得；名字实在认不出的模型，你贴了图就照发一次让网关裁决，不会再干等着手动配置。设置里手选的「支持 / 不支持识图」永远压过这些自动结论。

### 🧠 内存与流畅度：PDF、终端、超长回复、多窗口，一处一处收

- **来由**：接着 1.3.5 那条「内存不再越用越涨」继续审计。上一轮解决的是会话数据全量常驻；这一轮把剩下几块「看不见但一直涨」的地方逐个收掉。
- **多开窗口**：以前每开一个新窗口，都要把所有会话完整扫两遍（先为拿工作区路径解析一遍，紧接着读元信息再解析一遍）。本机 65 个工作区会话、共 272MB，一轮扫描后单窗口主进程 689–760MB，多开几个窗口就顶到 3GB——释放掉的内存不会马上还给系统，于是每开一窗线性叠加。现在会话元信息有一份单独的小索引（源文件变了才失效），多窗口同时预热只解析一份；列工作区路径复用同一份元信息；同一窗口连续保存且磁盘仍是自己上次写的内容时走保存快路。后续新窗口只读几 KB，不再整桶解析。
- **流式对话**：以前流式期间每 500ms 防抖就把整个会话完整读一遍再写一遍（68MB 约 519ms，还要多产生 118MB 临时字符串），而且每轮保存对每条消息的每个字段重复比对两遍。现在流式期间不落盘，一轮结束再存；字段比较改为结构化相等（内容没变直接跳过），70 节点会话实测每轮 980 次比对耗的 114ms / 17MB 临时字符串降到接近零。运行时可视化快照也只保留界面真正会显示的轮次与事件（磁盘上曾出现 153 轮 / 8,446 事件 / 3.2MB 的旧快照）。
- **PDF**：以前翻过的页画布一直留着，切换大文档也不销毁 pdf.js 的加载任务；800px 宽的 A4 画布约 3.6MB，百页 PDF 能累积几百 MB。现在换文件 / 卸载时销毁加载任务，缩放或换文档会丢弃在飞的旧渲染；离开可视区 2400px 以外的页释放画布，滚回来再画。
- **终端**：每个终端会话的回滚从 5000 行收到 2000 行——终端切页签只隐藏不销毁，几套会话同时开着时这部分是实打实的 TypedArray；日常排查够用。
- **聊天与缓存**：单段 Markdown 超过 5 万字符时不再做语法高亮（仍正常渲染代码块，只是没有配色），避免一个超大代码块生成几万个高亮节点；工具调用结果缓存加了 32MB 总量上限、附件登记表加了 64MB 总量上限、MCP 调用历史只从文件末尾读最近 1000 条（原来把 13MB / 14,897 行全部解析后反而留下最旧的一批）。
- **后台收尾**：关闭窗口时清理四条流式请求的定时器与连接（原来 6 小时的定时器会把整个请求闭包钉住）、PTY 随窗口销毁一并结束、MCP worker 崩溃后只重建一个、OAuth 隐藏窗加载失败即销毁、知识库闲置落盘关闭、子 Agent 任务日志封顶 50 条。
- **边界**：升级后第一次启动仍要完整扫一轮、建立元信息侧车，从第二次启动起（以及之后新开的窗口）才走快路；会话存储结构本身也在这一版换了，单独写在下一节。

### 🧠 会话存储：从「整桶读写」换成「索引 + 一会话一文件」

- **来由**：2026-10-20 用户实报「打包之后启动内存占用很高，我用 RAMMap 清理之后才正常」。当时仍用旧的整桶存储：一个工作区的全部会话都在同一个 JSON 里，启动和保存都要整份读写；本机那个工作区已经有 52MB / 27 个会话，光启动解析就多占约 178MB 堆内存。
- **以前**：每个工作区的全部会话装在同一个大文件里（主页另有一个）。打开列表、统计、启动预热都绕不开整份解析，界面还会把整个文件留在内存里；任何一次保存都要把整份读出来、合并、再整份写回——最大的 7.5MB 会话单笔保存要 450–550ms。
- **现在**：每个工作区一个目录——一份几十 KB 的索引（会话顺序、当前会话、每个会话的标题/时间/计数等元信息）+ 一个会话一个正文文件。启动只读索引和「当前会话 + 固定页签 / 后台仍在跑的会话」，其余会话只带元信息、不带正文；打开时按需补正文（每次 64 条）。保存只写变脏的会话再原子写索引：同样的 7.5MB 会话单笔保存降到约 175–223ms，日常小改动 6–9ms。删除的会话留 30 天墓碑，避免多窗口对账时「复活」；索引损坏可以从会话文件重建。实测同一个 52.4MB / 27 会话的工作区：内存增量 177.7MB → 22.1MB、整体内存 250MB → 68MB、全部加载 550ms → 59ms；迁移后磁盘占用 70MB → 52.19MB。
- **旧数据与回滚**：旧桶原样保留、只读；升级后第一次启动会自动迁移/对账一次（本机 27 个会话约 3 秒），之后只按修改时间和文件大小比对，不再重复解析。从这一版起默认新存储；也可以在本地配置里退回旧存储——但切换之后新建或修改的会话只存在新存储里，退回旧存储看不到它们。
- **边界**：升级后首次「完整加载」比旧存储慢约 160ms（多文件读），之后走缓存；本次只换了存储结构与渲染端加载方式，会话内容格式和聊天界面没有变化。

### 🖥️ 初始缩放：小屏笔记本不再「字比窗口还大」

- **来由**：2026-10-19 用户：「整个应用的字体大小适配一下屏幕大小，在最开始的时候，小屏幕看到的字体大小太大了。」
- **以前**：应用启动时固定按同一个比例放大（1.2 倍）。1366×768 这类小屏笔记本上，14px 正文会被放到 16.8px，确实偏大；而且 `Ctrl+0` 也会回到这个固定值。
- **现在**：建窗时按窗口所在屏幕的工作区尺寸（DIP）分档：
  - ≥1700×950：1.2 倍（大屏维持原样）
  - ≥1450×820：1.1 倍
  - ≥1250×660：1.0 倍（普通笔记本）
  - 更小：0.9 倍
- **边界**：分档不是连续函数，档位边界附近可能一跳；`Ctrl+0` 回到「当前屏幕的默认档」而不是 100%；用户仍可用 `Ctrl+±` 自己调。

### 🐢 读图 / 读大文件：应用不再僵住几十秒，在跑的工具也不会被连累

- **以前**：让 AI 读一张截图或一个大文件之后，整个窗口会僵住几十秒：点哪都没反应，正在跑的工具跟着被判超时失败——看起来像「mkdir 卡住了」「终端卡顿」。同一条会话里堆过几张大图之后，这个会话还会一次比一次慢。
- **现在**：读图这类结果只保留文件的尺寸、格式和文件名，图片数据本身不再一路带进界面和会话记录；界面不会再被一张图拖住，同时进行的其它工具也不会被连带判成超时。
- **边界**：这一版只改界面与会话记录这一侧，不影响 AI 读文件拿到什么结果。

### 🗂️ 文件树：文件夹再大，展开也不再顿一下

- **来由**：2026-10-25 用户实报「文件太多，FileTree 展开会卡顿」。
- **症状**：`node_modules`、构建产物目录、或者一个装着几百个子文件夹的目录，点一下展开箭头要先顿一下才出内容；连着展开几个大目录，整个界面都发黏。
- **现在**：文件树为了「孙子目录展开时不用再等磁盘」，每展开一层都会顺手预读下一层——原先把**下一层的所有子目录**并行读一遍，界面还要等它们全部回来才画，预读从提前量变成了展开的必经之路。现在预读只取前 32 个子目录，其余留到真正展开时再读（展开本来就总是重读磁盘，内容不会缺）。大目录点开即时出内容，连点几个也不发黏。
- **边界**：32 是「提前量」的取舍，不是数据层的限制——任何深度、任何数量的目录都能展开，只是没预读的那部分在第一次展开时多等一次读盘（通常 10ms 级）。

### 🔍 左栏搜索：两个框并成一个，框里选「文件」还是「内容」

- **来由**：2026-10-27 用户「两个合并到一起呢，然后一个下拉框选择搜索文件还是搜索内容」。
- **原状**：文件树工具条上一个框，按名字筛树；左栏「搜索」面板里另一个框，搜整个工作区的内容、还能替换。两个长得一样、分在两处：想「先按名字找文件、找不到再搜内容」得先换一处，词还得重新打一遍。
- **现在**：只剩工具条那一个框。点开（或框里已经有词）时，框左端变成「文件 / 内容 ▾」下拉——「文件」照旧按名字筛树；「内容」把下面的正文换成原来的全局搜索结果：大小写 / 全字 / 正则三个开关、替换行、按文件分组、点行跳转一个不少。两档共用同一份查询词，切过去切回来都在。
- **按钮让位**：树的那组按钮（新建 / 排序 / 定位 / 展开折叠 / 刷新）只在「文件」档出现；「内容」档整组让位，腾出来的宽度全给搜索框，窄栏里也不挤。
- **入口收拢**：左栏标题栏原来那枚放大镜按钮撤掉了（用户「顶部的搜索按钮就没必要存在了」）——内容搜索就在框里换档，不再留第二个入口。`Ctrl+Shift+F / H / R` 照旧直接进「内容」档，`H / R` 展开替换行，`Ctrl+Shift+4` 仍是整栏搜索面板的开合；回「文件」档走框左端的下拉，或页签条上带左箭头的「文件」。切档只是切左栏的页签状态（「文件」↔「搜索」），框本身不换、词不丢。
- **边界**：只合并左栏这两个入口；编辑器里的 `Ctrl+F / Ctrl+R`（当前文件内查找替换）不受影响。收起态仍是原来那条窄框加放大镜，50px 的几何没动。

### 💬 长对话：点开、删掉，界面都不再僵住

- **来由**：2026-10-25 用户实报「Sidebar 初次展示聊天记录，对话太长，也会卡顿」。
- **症状**：在历史列表里点开一条很长的对话，界面会先僵住一下——点哪都没反应，然后画面才跳过去。删掉当前对话、接手下面那一条时，同样再顿一次。会话越长停得越久。
- **现在**：会话列表平时只加载元信息，正文在你点开时才补。补正文这一路原先走的是阻塞式通道：读盘、解析、瘦身遍历、把整棵消息树结构化克隆回界面线程，全程界面主线程停住（本机一份 12 MB 的会话实测：读盘 80–99ms、解析 43–54ms、克隆 49–54ms，加起来 200ms 上下，还没算把消息铺进列表的重绘）。现在点开会话、以及删掉当前对话后接手下一条，都改走异步通道——主进程干活期间界面照常跑，回来再把正文原地换上；补正文期间你要是又点了别的对话、或新建了一条，这一次的结果作废（后点的赢）。
- **边界**：开机那一次（当前对话的正文在启动时读进来）没有改——它藏在启动封面后面，实测约 0.2 秒，改成异步要动开机时序，风险大于收益。另外，老版本留下的会话桶第一次打开时有一次性的旧格式迁移，那一次仍会停一下，之后不再发生。

### 💥 文件树拖进输入框：应用不再直接闪退

- **症状**：从左侧文件树按住一个文件往右侧 AI 输入框拖，拖到输入框附近时整个应用窗口瞬间消失——不是面板报错，是进程直接退出，控制台往往连一条 JS 报错都留不下。

- **边界**：原生拖拽只会在光标真的离开窗口后启动，拖出动作比原来晚一个拖拽事件，拖出功能本身不受影响。

### 🧩 工作台右区：AI 对话、会话列表、插件侧栏合成一块

### 🖱️ 对话可以拖着换工作区、也能拖进拖出「工作空间」组；工作空间的悬停列表可停留、可点击

- **来由**：2026-10-22 用户「对话能否通过拖动调整位置呢，放到哪个工作区里面」；同日又说「hover 出来的工作区能否常驻支持点击的形态，没有 hover 的时候不展示，也就是界面可停留」。2026-10-24 用户反馈「对话记录 工作区和工作空间的移动还是有问题」。

### 🗂️ 多工作区：多根文件树、跨根移动、重启原样开回

- **来由**：2026-10-21/22 多工作区改造；用户要求一个窗口装下多个根，并追问附加后的对话与记录（后两条见「附加工作区」一节）。
- **以前**：一个窗口只有一个工作区根；打开新目录等于换根，文件树只有一棵；重启只恢复一个根；跨工作区移动文件要手动复制。
- **现在**：
  - 打开工作区对话框新增「附加到当前窗口」；附加只把根加进当前窗口，不切当前根、不动正在进行的对话。
  - 连续附加多个根不会互相顶掉：AI 一次连着发几条附加、或者你在两个入口先后操作，每一条都按落地那一刻窗口里真实的根清单重新拼，先加进来的根一个都不会少。
  - 新建工作区后同样弹三选一：已有工作区时选「附加到当前窗口」，建完直接挂进当前窗口，不切当前根、不打断正在进行的对话。标题栏菜单不再单列「新建工作区并附加…」；文件树工作区根右键仍保留这个入口。新目录要选在已有根之外——同一窗口的根必须平级，互相嵌套会被拒绝。
  - 文件树同时列出多个根，根行用「层叠」图标区分普通文件夹；几个根按添加顺序排列，对话列表里的工作区组序与它完全一致，重开工作空间也不会因为「哪个根是当前」而换位。
  - 窗口左上「Notrat」下面的名字跟着窗口走：在已命名的工作空间里显示空间名；多根但还没起名时用各根名字拼成「a + b」；单根窗口仍显示目录名。
  - 点根名切换当前根，当前根是界面上的活动根（文件树、新建文件、新会话的落点）。「当前」小徽章已经撤掉——行名和「层叠」图标会一起变成主题色来标识；你打开哪个根里的文件，那个根的名字就标出来（点根名切根时也会跟过去），一眼能看出正在哪个工作区里操作。
  - 工具条的「全部展开 / 全部折叠」按树的实际开合显示：在工作空间里单独收起某个根之后，按钮会如实变成「全部展开」，不会再停在旧状态、点下去像没反应。
  - 工作区根行不能拖动、改名或删除，Delete 键也删不掉；要拿掉某个根，右键「从窗口移除」，确认框写明磁盘文件和已有会话都不会删除。
  - 跨根拖文件先确认「这会把 N 个项目移出当前工作区，放入「X」。确定继续吗？」，确认后才移动。

  - 权限弹窗：AI 写同窗口的兄弟根时标「同窗口的另一个工作区」，不再误报「工作区外」。
  - 知识库按窗口隔离：每个窗口只认自己的根，A 窗口不会搜到 B 项目的笔记，索引进度也只推给正在显示该根的窗口。
- **边界**：会话始终绑定创建时的工作区（session home），切当前根只影响界面和新建会话，不搬已有对话；AI 工具默认也走会话的 home，不会因为切根而漂移；「待归档」只在没有工作区时出现。

### 🧩 工作空间：起个名字，一键开回

- **来由**：2026-10-21 用户希望把常用的几个根存成一个名字，下次不用逐个附加。
- **以前**：每次都要重新打开或附加同样的几个目录；窗口关掉后这组搭配就散了。
- **现在**：
  - 窗口里有两个以上根、根数稳定下来（约 1.5 秒）时，应用自己弹出命名框；起个名字（最多 80 字）就把这组根和当前根记下来。当时跳过了也没关系：「最近」里会留一条带「未保存」标记的行，点它就是同一个命名框。
  - 第一次把多个根合成一组时，应用会自己问一次名字：**等根数停止变化约 1.5 秒**才弹，一次附加好几个根时不会在半路上先问（比如准备了四个工作区，不会只扫到三个就冒出输入框）；默认名仍用各根名字以「 + 」拼起来，直接回车即可。命名框与保存读的都是**此刻**窗口里真实的根清单——弹框期间又附加了根，存下的是点「确定」那一刻的整组，不是弹框那一刻的。
  - **「保存」与「取消」分开记**：按「确定」存下这一组之后，就不再有第二次自动询问；点「取消」（含点遮罩、按 Esc）只是这一回不起名，之后继续附加根、根数再次稳定时会按新的整组再问一次（不会立刻重弹）；保存失败也按「还没起名」处理。打开工作区菜单或系统目录框时，还在等的那次询问会先收掉——你显然还在挑下一个目录，等根落定再说。
  - 起好名字后，窗口左上「Notrat」下面显示的就是这个工作空间的名字，不用再靠数根目录名字确认自己开的是哪一组；整组开回时根的先后仍按当初添加的顺序排。
  - 欢迎屏的「工作空间」区按名字列出，点一下整组在当前窗口打开；当前窗口对应的工作空间会打「当前」。
  - 「最近」的排序：工作空间与单个工作区混在同一条「最近打开」时间轴上，最近点开过的排最前；整组打开只记空间这一笔——组里的目录不会各自插一条，除非你单独点开过某一个成员根。主页「最近」、文件树顶部的菜单与「全部工作空间…」对话框读的是同一份顺序，不会各排各的。
  - 工作区菜单里，**所有**工作空间（含当前）与最近工作区同列在「最近」段，用图标区分；当前那个在行内打「当前」徽章，菜单顶部不再为它单开四行段头/重命名/删除/合并。
  - 空间行的重命名 / 删除 / 在新窗口打开 / 合并工作空间收进行内 hover 的「⋯」和右键菜单；点空间本体与点工作区同一条动线——已有工作区时先问「当前窗口 / 新窗口」，选新窗口时整组根一起打开，并登记进窗口恢复清单。
  - 「合并工作空间…」有两个入口：空间行常显的「⋯ / 右键菜单」，以及「打开工作空间」对话框里的「合并到新工作空间…」；勾选两个及以上已保存的空间，根去重后合成一个新的命名空间。只写记录，不动磁盘目录与会话归属，也不删除原来的空间。
  - 50 个上限的判定：最多保存 50 个工作空间，新建第 51 个时淘汰「最近打开时间」最早的那个。**打开工作空间（当前窗口或新窗口）都会刷新它的最近打开时间**，所以淘汰的是「最久没打开」的；合并前也会先 touch 被合并的原空间，淘汰只会落到更久没动的其它空间上——「合并后原来的两个保留」。只有把 50 个全部勾上合并这种极端情形，第 51 条才会挤掉其中一个。
  - 菜单底部新增「全部工作空间…」：只列已保存的工作空间，带搜索框；点一行按原来的动线打开（当前窗口 / 新窗口）。菜单里条目再多，这里也能一次看全、快速定位。
  - 当前窗口对应某个工作空间时，菜单里可以重命名或删除；删除只会删这个名字，不会动磁盘上的任何文件，当前窗口里的工作区照常打开。
  - 工作空间里的目录都打不开时明确提示「这个工作空间里的目录都打不开了」，不会只给你一个空窗口。
- **边界**：工作空间只是「根清单 + 当前根」的名字，不移动、不复制磁盘目录，也不改会话归属；最多保存 50 个工作空间，每个工作空间最多 32 个根。

### 🔌 插件也认多工作区了，老插件不用改

- **来由**：2026-10-21 用户「现在是支持多工作区了，但是有些插件还是用的之前的方式，所以你要做兼容」，并要求顺手排查插件开发技能与文档。
- **以前**：插件只拿得到一个工作区路径；窗口里附加了兄弟根之后，插件仍按旧根找文件；插件窗口和悬浮器也可能停在旧工作区；权限弹窗把兄弟根当成「工作区外」。
- **现在**：
  - 插件独立窗口、悬浮器、便签窗里的插件工具没有自己的工作区，就按主窗口的当前根解析相对路径；内置的文件、终端、知识库、应用控制工具共用这条回落。普通窗口明确关掉工作区时不回落到别处。
  - 显式传 null（没有工作区）时保持 null，不回落全局或别的窗口的根。
- **边界**：老插件不用改；插件的主路径仍只有一个「当前根」，要同时处理多个根得读本窗口的全部根；根变化会刷新插件运行环境并广播给插件窗口，插件自己缓存了旧路径的仍以缓存为准。

### 🖼️ 表格 / 列表 / 标题里的图片：不再「一编辑就坏」

- **症状**：写在表格单元格里的图片（公告里的两张二维码就是）、和文字写在同一行的图片、以及列表项或标题里的图片，打开文档时能正常显示；但只要在它附近打字、删一次图片、或者切到源码模式再切回来，编辑器就会反复报错（控制台可见 `Invalid content for node paragraph`），有时看上去就像网络图片加载不出来。重启能恢复显示，可一旦再次编辑又复发。

### 🖼️ 标题里夹着空标签：编辑器不再整篇报错

- **来由**：2026-10-21 错误上报 `RangeError: Invalid content for node heading: <"5.5 Option", paragraph, "：没有 null">`；上一节「表格 / 列表 / 标题里的图片」是同一个病根的另一半。
- **症状**：打开一篇标题里带空标签的文档（手写锚点 `<a id="…"></a>`、或从别处粘来的长文最常见），显示完全正常；但只要动一下那个标题——打字、改级别、或者让标题编号 / 标题 ID 生效——编辑器就报错，之后整条编辑链路反复出错，看起来像整个编辑器坏了，刷新才恢复。
- **现在**：Markdown 解析器处理行内 HTML 时，空标签会解析出一个空段落，然后被原样塞进标题的行内内容里——标题只收文字，载入时不校验所以看得见，一旦标题被重建（比如给它写一个 ID）就校验失败、整段链路报废；此前的修法只认「图片」这一种块节点，空段落这类混进来的块节点没人管。现在载入时统一规整：「行内内容装错了层」的嵌套段落 / 标题，把里面的文字并回外层（文字不丢，标题也不会被劈成两截）；其它块节点（图片、块级公式、列表等）按顺序拆成平级块。什么算块级按编辑器自己的结构判定，不再靠一份硬编码的名字清单。

### 💬 编辑消息重新回答：不再卡在「生成中」，下一条也不再重复

- **来由**：2026-10-24 用户实报「终端工具为什么调用很容易展示失败」，附的一张内容审计脚本输出（9 张卡片里 8 张有间距问题）被整卡标红，紧接着的「停止后台命令」也报失败。
- **症状**：审计、lint、grep 这类命令其实已经跑完，只是习惯用非零退出码表示「有发现」；工具卡却显示「失败」，展开后错误与结果两栏还是同一段文字，输出还常常只剩错误流。后台命令已经自己退出后，AI 再补一次「停止」，又红一张卡。
- **现在**：
  - 命令真的跑完但退出码非 0 时，卡片显示「退出码 N」并用琥珀色状态点，不再整卡刷红；发给 AI 的结果仍是失败（它该知道的没变），只是界面不再演成「工具坏了」。

  - 「停止后台命令」发现进程已自行退出时，明确回一句「已经自行结束」，不算失败；真正停不下来（id 找不到、杀进程报错）仍然报错。
  - 退出码跟着会话一起存盘——刷新、切回会话后仍显示「退出码 N」，不会退化成普通「完成」。
- **边界**：只区分「命令跑完了但有非零结果」与「真失败」。超时、进程根本没启动、被安全策略拦下，仍显示「失败」；退出码为负（超时或被强制终止）也按失败处理。

### 🖥️ 终端：一条长命令不再拖住后面所有命令

- **来由**：2026-10-24 用户实报（紧接上一条终端问题）：「`echo hello`、`pwd` 也在执行中，这一类没有输出结果」。截图里一条截图脚本挂了 4 分 49 秒，后面的 `ls`、`echo ok`、`echo hello`、`pwd` 全部在转圈；用户随即提出「命令执行时间过长，也不可能排队处理呀……可以使用 Notify 或者手动查询 id 的方式吗，任务在后台执行」，并补充「AI 对话经常调用工具前面都有 sleep」。
- **症状**：同一次对话里，一条命令卡住（比如截图脚本在等页面）之后，再发任何终端命令都停在「进行中」：卡片一直转、一个字输出都没有，等五分钟也不回来。AI 那边却以为工具坏了，隔一阵就换一条命令重试（`echo ok` → `echo hello` → `pwd`），越试越堵。而「列出后台命令」这类工具却能秒回，说明程序本身没死。
- **现在**：
  - **shell 忙就转后台，不再排队**：前一条还在跑时，新命令最多等 2 秒（紧跟在 `cd` 后面的短命令仍进同一条 shell，目录不丢），还轮不上就以独立进程在后台启动，工具立刻返回一个编号和已经捕获到的输出——卡片当场结束，不再转圈。
  - **按编号等结果**：查看后台命令时多了「等待秒数」，可以原地阻塞到命令结束（最长 5 分钟），直接拿到退出码和完整输出。这正是用来替掉 AI「在命令前面拼 `sleep 30 && …`」的习惯——那种写法会占住整条 shell。
  - **兜底收场**：万一仍在排队，最多等 30 秒就返回「会话正忙，本次命令未执行」，并明确说明命令没跑、没有漏掉输出，而不是无休止地转。
  - **会话被回收后自动换新**：排队期间 shell 因超时或崩溃被销毁，命令会重新开一条 shell 执行，不再往已经死掉的进程里写。
  - 终端类工具的单次调用上限从 60 秒放宽到 10 分钟，长命令不会再被当成「调用失败」而让 AI 重发一遍。
  - **提示词同步改了**：系统提示词（随每次请求现拼的终端策略段）写明「别在命令前拼 `sleep`，它占住整条 shell」「要等就用后台编号 + 等待秒数」「`[background] id=…` 不是失败，别重发」——模型不用靠猜（这段不落盘，老用户也立刻生效）。
- **边界**：后台命令是独立进程，不继承前面 `cd` 出来的目录、也不共享会话里的环境变量（返回文本里会写明起始目录）；正在跑的那一条仍然独占会话 shell（沉默 5 分钟算超时），只是不再连累后面的命令；`sleep` 之类真正需要等待的场景，改成「起后台命令 + 按编号等」两步更稳。

### 💬 切换工作区：AI 还在写的时候，先问一句

- **来由**：2026-10-24 用户「如果用户在当前窗口打开其他工作区/工作空间，如果有 AI 对话在执行，应当告诉用户，此操作会断开 AI 对话，如果不想断开，可以选择将其他工作区附加进来，形成工作空间，两个工作区可以同时让 AI 处理，加上一个不再提醒按钮」。

- **现在**：
  - 打开另一个工作区、另一个工作空间，或从主页 / 文件树菜单直接切换时，如果这条对话还在写（正在输出、有消息排在队列里、后台子任务还没收尾），应用先停一步问一句，不会直接换过去。

  - 第二项是「仍然切换」：明确结束这条回复，再到新工作区里继续；目标是一个工作空间时，整组目录一起打开。

  - 目标就是当前这一组时本来就不会弹；附加之后自动切到文件页，方便立刻接着看文件。
- **边界**：欢迎屏还没打开工作区时没有「附加」这一项（无处可附），只提供「仍然切换 / 取消」；AI 自己通过工具切换工作区不弹这层提醒——自动化不该被确认框挡住。

### 🧭 计划模式：先把计划写清楚，再按步骤派专家去做

- **以前**：「代码规划」是工具栏上单独一档，点它先生成一张计划卡，再点「执行全部计划」；卡片一旦转不出来，整轮就停在那里，计划步骤和执行过程也散在卡片与工具调用里。
- **现在**：
  - **入口**：输入框工具栏 →「工作场景」→「计划模式」。它可以单独用，也能和「思维链」「自我验证」一起多选；「日常任务」是独占档，勾了它就只剩它，勾别的场景时它自动让位。
  - **先写计划**：AI 会以「## 执行计划」开头，把计划完整写在回复正文里——每一步做什么、动哪些文件或产出什么、怎么算做完，并标出哪些步骤依赖前一步、哪些可以并行。
  - **写完就做**：不再停下来问「是否开始」，也不需要另外打开派发开关；用户随时可以按停止打断。
  - **派专家分头执行**：能独立完成的步骤交给对应的专家，互不依赖的步骤同一轮一起派出；AI 自己负责拆解、验收和把结果拼起来，每完成一步回一行「✓ 第 N 步」。
  - **随时能停、看得见**：计划与进度都留在对话正文里，没有额外的计划卡，停止键立刻生效。
  - **场景卡顺手重排**：每张卡整块可点，「日常任务」带「单独使用」标记、其余场景可叠加，「当前」标记和选中态一眼能分清。
- **边界**：这一版没有恢复旧的计划卡界面和「执行全部计划」按钮；计划以正文文字为主，是否再列成结构化步骤由模型按任务决定。

### 🖼️ AI 读图：识图模型直接看图，名单不再靠手维护

- **来由**：2026-10-26 用户「AI 扫描到图片之后要能自己看，但要先判断模型支不支持看图」；随后追问「这里自动识图模型列表能够自动完善吗」「图片识别失败的话会自动续流吗」。
- **以前**：AI 只有用文件工具读出的一串 base64，看不到画面；用户在输入框贴的图能直接发给模型，两条路完全分裂。哪些模型「认图」只靠一张手写的名字清单猜——`qwen3.6-plus` 在模型列表里明明写着「(视觉)」，清单却认不出它，工具读到的图因此不会递过去。
- **现在**：
  - **能看的直接看**：识图模型用工具读到图片时，图片作为真正的图像内容随这一轮请求一起发出，不用再让用户把图贴进对话。
  - **不能看的说清楚**：不认图的模型会收到一句「这张图你看不到」以及绕法（转存成文字、改用识图模型），不再照着文件名编。视频 / 音频走同一条提示（抽帧、转写），不会把整份文件当 base64 塞过去。
  - **名单自动完善**：服务商接口只返回模型名，不带「收不收图」，所以除了接上应用里已有的两张能力表（Coding Plan、MiMo），还按真实收发结果学习——发的图被接口拒绝，就记下「这个模型不收图」，下次直接按文本走；带图跑通就记下「收图」。结论按「服务商 + 模型」分别记，90 天后自动作废重判。
  - **拒图自动续跑**：接口拒收图片时，这一轮自动去掉图片重发一次，对话不会断在当下；本次对话后续也不再附新图，按文本继续。
  - **用户手设最大**：设置里的「支持识图 / 不支持识图」永远压过自动判断与学习结果。
- **边界**：视频 / 音频目前只给元信息与绕法，还不能随请求一起发出（这一版没做）。学习结论只影响「要不要附图」，不改模型列表本身；想立刻纠正，去设置里手选一档即可。

### 🔌 连接器（MCP）：不再「隔一阵子就掉线」，npx 启动也不再超时误判

- **症状**：插件带来的连接器（MCP）会毫无征兆地掉线——插件面板显示「服务已停止运行」（The service is no longer running）或一直加载不出来，正在用的工具突然报连接失败；过一会儿或重开面板又好了。每次界面重新加载（开新窗口、切换/恢复工作区）之后尤其集中。另一类是用 npx / npm 方式启动的连接器（网页抓取、搜索类最常见）：机器上第一次启动、或缓存需要重新解包时，转一会儿就报连接超时；反复重试偶尔还会变成「找不到模块」。
- **现在**：例行的工作区刷新会先比对连接实际使用的配置（启动命令、参数、环境变量、工作目录等）——没变就直接沿用现有连接，变了才重启；显式「重载」和调用失败后的自动重连仍然走彻底重启，不受影响。npx / npm / pnpm / yarn / bun / bunx / uvx 启动的连接器，默认等待时间从 30 秒放宽到 120 秒（自己配了超时时间的仍以配置为准），连接握手也使用同一档时间，不会在 60 秒时被提前放弃。效果：界面重新加载、开新窗口不再把全部插件连接器杀一遍；npx 连接器冷启动被误判超时的概率大幅下降，也不会再因为中途掐断留下坏缓存。
- **边界**：多窗口同时打开不同工作区时，同一个插件连接器仍然只有一个后台进程（按插件全局共用），后打开的窗口如果环境不同，会接管这条连接——这个既有设计本次没有改动，只消除了「每次界面加载全量重启」。连接器自身崩溃或被外部结束后，自动重连逻辑照旧生效。

### 🔗 连接器（MCP）：更新或重载插件后不再「未注册」

- **症状**：更新插件、重载插件、或插件目录热更之后，插件面板突然报 `MCP server「…」未注册（不存在或已改名）`，这个插件带的工具全部用不了。有时重开面板能碰巧恢复，有时要重启整个 Notrat。
- **现在**：同一个连接器的启动、停止、重启改为按 serverId 排队，前一件做完才轮到下一件；关闭时只删自己那一份，连接身份对不上就不动别人的。更新、重载、目录热更之后连接器稳定回来，不用再重启应用。
- **边界**：修复前已经卡在「未注册」状态的面板不会自动追回——把插件重载一次即可恢复（重载入口现在就在插件箱右键菜单里，见下）。

### 🩺 运行环境：不再误报「缺 Node.js」

- **症状**：插件卡片上写「缺运行环境：node」，点进上手引导，同一项却显示「已就绪：Node.js」；而插件的连接器其实跑得好好的。
- **现在**：检测与启动共用同一套解析（三级兜底都在，坏掉的 node 和低于 18 的旧版也拦得住），卡片与引导的并发检测合并成一次、共享同一份结果，设置里的自定义工具路径也会带上。没装 Node.js、靠应用自带运行环境跑连接器的电脑，体检同样显示已就绪。
- **边界**：应用自带的运行环境不带 npm / npx，npx 型连接器仍需要机器上自己的 Node.js，检测会如实反映。

### 🧩 插件图标：默认就是 Notrat 的样子

- **以前**：插件图标由作者自己带 emoji 或图片，没写的就落一个 🧩；不同插件摆在一起，和 Notrat 全线的 lucide 线性图标明显不是一套。
- **现在**：包级图标统一由同一个组件渲染。manifest 里写 `lucide:Workflow` 就是 Notrat 同款线性图标（描边 2px，白名单收录 83 枚常用图标）；没写、或写的名字不在白名单里，静默回落默认的拼图 `Puzzle`，不再是 emoji。自己的图片也仍然可用——开发脚本会把它缩成 webp data URI 内联进 manifest（≤512KB，不收 SVG），远端 http(s) 图片地址和旧插件的 emoji 继续兼容。
- **覆盖**：插件箱 tile、插件箱右键菜单头、插件设置对话框、扩展管理列表、上手引导与日志弹窗。
- **边界**：插件面板内部自己的小图标不走这套，仍由面板自己决定；写插件时也不用背图标名——插件开发技能会先问你想用 lucide 还是自己的图片，再按回答写进 manifest。

### 🔁 插件箱：右键直接重载插件

- **入口**：状态栏插件箱里右键任意插件，菜单新增「重载插件」（和「更新」是同一枚旋转箭头）。它与「扩展管理 → 插件卡片 → ⋯ → 重载」完全同一条动作：清掉旧覆盖 → 重新编译面板 / 渲染器 → 停掉旧连接器并拉起新的。
- **反馈**：重载期间该项显示「重载中…」且不可再点，「更新」也一并禁用，避免重复提交；成功后 tile 上闪一条「✓ 已重载」，失败则弹出具体原因。
- **边界**：用独立窗口打开的面板会随重载关闭，重载完从插件箱重新打开即可。改完插件自己的文件就地重载，不用再绕去设置页，也不用重启 Notrat。

### 🪟 插件独立窗口：拉回屏内真的回得来，控制面由开发者决定

- **症状**：「拉回屏内」以前只在窗口几乎整个跑出屏幕时才有可见效果——它走的是安全兜底，只保证窗口留 48px 在屏内。窗口拖到半屏外时点它，位置几乎不变，看起来就像按钮坏了（2026-10-19 用户报「独立窗口的拉回屏内用不了」）。另外，桌面小窗里的窗口设置面板可能比窗口还宽 / 高，「拉回屏内」这一行被裁在窗口外，点都点不到。
- **现在**：「拉回屏内」改用整窗摆回：四个方向都按整扇窗收回当前工作区，副屏带偏移量按那块屏算，窗口比工作区大就先压进工作区；插件代码运行时传坐标仍只做安全钳位，不会把窗口挪得莫名其妙。窗口设置面板也收进小窗内——宽度随窗口、内容可滚、底部动作行吸底，「拉回屏内」始终够得着；控制栏隐藏时面板贴顶，不再留一条空白。
- **控制面由开发者决定**：独立窗口的插件作者可以在 manifest 里各自决定是否显示顶部控制栏（`showControlBar`）、标题文字（`showTitle`）、锁定（`showLockButton`）、设置（`showSettingsButton`）、关闭（`showCloseButton`）；旧插件的 `dragBar: false` 仍是「不要顶部条」，行为不变。面板代码也能在运行时用 `window.notratPluginWindow.setOptions({...})` 覆盖，并和其他窗口设置一样落盘，重启后仍生效。鼠标穿透开启时控制栏强制保留（否则整窗不吃点击、用户再也关不掉穿透）；控制面全部关掉时，右键面板仍能唤出窗口设置，插件箱菜单也仍能关闭窗口。
- **边界**：这五个开关是给插件作者的，用户自己的 ⚙ 面板不提供（避免普通用户把窗口弄成「没有任何出口」的样子）；开发者至少应留一条操作路径。

### 🧩 插件面板：「打开方式」多了「整页」，位置菜单也收进了二级菜单

- **来由**：2026-10-20 用户连续三条——「能否支持直接以一个页面的形式打开，和 Notrat 的其他页面一个性质」「这里可以把位置调整弄到二级菜单里面吗」「有些位置才可以弄打开方式吧」。此前「打开方式」只有跟随位置 / 完整页面（标签页）两档，13 个位置在右键菜单里平铺成一根长条，常驻面板也照样显示「打开方式」。
- **以前**：想让插件面板像设置、图谱那样占满主区，只能开成编辑器标签页——上方始终有一条标签栏；右键菜单要滚 13 行才能找到目标位置；常驻面板、悬浮窗、桌面窗口上也挂着「打开方式」，改了也不会改变它们的形态。
- **现在**：右键面板 →「打开方式」三档：
  - **跟随位置**：按面板所在位置决定（触发位弹窗、`page` 标签页、常驻位保持常驻）；
  - **标签页**：开成主区标签页，有标签栏，可以和文件标签并排、多个同时开；
- **菜单**：13 个位置收进顶层「面板位置」二级菜单——父行行尾直接显示当前位置（与「打开方式」显示当前档位同形），当前位置是 manifest 默认位时带「默认」徽章；子菜单仍按内嵌面板 / 按钮入口 / 浮层 / 页面与窗口四段分组，当前项打勾，改过位置才出现「恢复默认位置」。子菜单高于视口时在视口内滚动，底部目标够得到。
- **位置可多选**：同一面板可以同时挂在多个位置（例如活动栏入口 + 右侧停靠栏 + 桌面窗口），子菜单里勾选多个；父行显示「首个位置 +N」。三个与 AI 对话相关的位置改名为「AI 对话输入框上方」「AI 对话消息区顶部」「AI 对话工具栏」，不再用「侧边栏 / 对话页」这种换个页面就对不上的说法。
- **打开方式只在点开才出现的位置显示**：活动栏、侧边栏工具栏、状态栏、编辑器标签栏、编辑器标题栏、`popup`、`page` 七处；常驻位（输入框上方 / 消息区顶部 / 右侧停靠栏 / 大纲）、`floating`、`window` 没有这一行，之前残留的覆盖也不再生效（例如先设了整页再挪去桌面窗口，不会再被旧档位带走）。
- **插件箱与 manifest**：抽屉里点 tile 打开主面板时，整页档优先于标签页档，常驻位仍是恢复 + 聚焦；manifest 的 ui[].openMode 同样接受 `"fullpage"`，用户右键覆盖优先于 manifest。插件开发技能与开发文档同步更新：先问用户放哪儿、只在适用的位置声明打开方式。
- **边界**：同一时间只保留一个插件整页——页面是「当前在哪一页」的语义，后开的整页会顶掉先开的，不像标签页可以并列；「面板位置」和「打开方式」是两张表，搬位置不会改打开方式，反之亦然。

### 🔌 连接器（MCP）：闲下来自动休眠，工具不会消失

- **来由**：插件自带的连接器在应用启动时会全部拉起，但绝大多数时间没人调用；每个 node 子进程约 45MB，17 个插件全开≈700MB 常驻。这是 Electron 自身进程之外最大的一块「白养着」的内存。
- **以前**：插件连接器一旦启动就一直活到应用退出，没有空闲回收。插件越多，后台常驻越高。
- **现在**：插件自带的本地连接器超过 **10 分钟**没有调用，就停掉后台进程；配置和工具清单仍留在内存里——AI 的工具列表、连接器列表、插件面板照常看得到这个连接器（标为已连接 + 空闲），下次调用工具 / 读资源时按原配置自动拉起，不会广播「断开」让界面清缓存、技能列表短暂消失。
- **不会误伤**：用户自己配置的连接器、SSE / HTTP 这类远程连接、与其他别名共用同一条连接的、以及有调用正在进行的，都不回收；长任务不会被中途杀掉。空闲回收的时长可调整，设为 0 即关闭。
- **边界**：休眠后的第一次调用要等进程重新起来，比常驻时慢一点；面板如果每隔几秒轮询工具，会持续刷新「最近使用」，这个连接器就不会休眠——属正常行为。

### 🧩 工作空间级资源：连接器、技能、插件都能只装在某个空间里

- **来由**：2026-10-22 用户问「MCP、技能、插件之前都是全局和工作区两种形态，那工作空间呢」——工作空间已经能整组打开，但装东西仍只有「全局 / 当前工作区」两档，空间里的其他根看不到，换个根还可能像换了项目。
- **以前**：
  - 连接器（MCP）的「工作区」档只认当前打开的那个根；设置页里连接器一多，迁移按钮还会按「有没有打开工作区」猜方向，全局连接器也可能显示成「迁移到全局」。
  - 技能只有全局和工作区两档，工作区档只扫当前根，空间里的兄弟根带的技能不会出现在候选里。
  - 插件包只有全局 / 工作区两档，装到工作区后换当前根就看不到了。
- **现在**：
  - 安装范围多了「工作空间」：连接器市场点「安装」、插件市场（含官方货架）选安装范围时都能选；AI 新建技能时也能指定装到当前工作空间。空间里的所有工作区共用这一份，切换当前根不受影响。
  - 优先级从近到远是「当前工作区 > 工作空间 > 全局」：同名的连接器 / 插件就近生效，技能查找也先命中更近的一档。
  - 设置 → 连接器里，每张卡片的 ⋯ 菜单会按它**实际所在的位置**给出迁移目标；插件卡片的 ⋯ 也按当前所在档列出可搬去的目标，不再出现「点了必然失败」的项。
  - 离开某个工作空间时，只属于它的插件会先卸下、不再运行；重新进入会从磁盘装回，开关状态保留。
  - 删除工作空间只删名字，不动磁盘上的资源目录（与「删除名字不动文件」的既有承诺一致）。
- **边界**：空间档要求窗口已经属于一个**有名字**的工作空间（先把两个以上根保存成工作空间）；会话归属、AI 工具的工作目录仍按会话自己的单个工作区，不会被换成整个空间；技能的变量 / 环境变量配置目前仍只有全局和工作区两档；两个窗口各在不同空间时，插件清单仍共用同一份本地存储（多窗口插件清单的后续改造）。

### 🧩 技能面板上的技能清单：不再「已加载 0 个技能」

- **以前**：技能面板里的来源目录列不出来——明明装了技能，在这里看起来一个都没有，用到技能的那一轮，技能上下文也是空的。
- **现在**：来源目录照常列出，用到技能时会带上真正装了哪些技能。
- **边界**：只影响「列出技能来源」这一处显示，技能的扫描范围与加载规则没变。

### 🧩 技能自动匹配：不再把不相干的技能塞进这一轮

- **症状**：问一件跟医疗、引用格式毫无关系的事，自动选中的却是一串临床助手、用药参考、参考文献格式检查。实测两次：问「文档站里写的 macOS 最低支持版本是哪个」，一次带上 8 个完全不相干的技能；贴一段 `Cannot find module 'electron'` 的报错问插件路径怎么改，第一位是批量生图，其余是药学、临床、广播。这些技能会被真的载入这一轮上下文。
- **还有一处**：技能列表里有些技能的介绍是空的，或者干脆显示成 `>-`，自动匹配时也拿不到它们的描述。
- **现在**：
  - **简介读得全**：CRLF 换行、多行折叠（`>` / `>-` / `|` / `|-`）、跨行引号三种写法都能正确取出简介，技能列表与自动匹配用的是同一份。
  - **匹配认「连续词组」，不认「字词凑数」**：问句里的中文段要能在技能简介或正文里连续对上（简介里连续 4 个字、或一半以上的字连续铺满、正文里连续 6 个字，才算命中），英文名要整词对上；小写「ui」不再被 `build` 里的两个字母误命中。
  - **判不准就交给模型**：一条硬证据都没有时不再自己拍板，而是带着完整技能目录（含简介）问一次模型；模型说「没有匹配」就不载入任何技能。
  - **最多 3 个**：真的多技能命中时也只保留分数接近的少数几个，不再一次带 8 个。
- **实测**：同一台机器同一份技能目录，上面两个查询现在都是「一个都不选」；「把这篇笔记发到公众号和小红书，一稿多投」只选广播发布，「引用格式检查一下参考文献编号有没有跳号」只选引用格式检查，「帮我查一下心血管指南怎么说」只选医学指南。本地判别耗时 1 到 3ms，粘贴长日志也不掉帧。
- **边界**：只改「选哪些技能」这一层；技能本身的加载、优先级、作用域规则没变，手动点名技能（`@` / 斜杠命令）照旧直接生效。
