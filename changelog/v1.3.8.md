# 1.3.8

发布日期：2026-11-06（已上线）　·　最后补充于 2026-11-11　·　[← 上一版](/changelog/v1.3.7)

**这一版**：18 项亮点 · 59 处修复 · 40 项改动详情（详情按模块收起，点标题展开）

## ⚡ 更新亮点

- **📝 Word（.docx）换成能「原样读、原样写」的引擎**：以前是先把 docx 转成网页再拿网页重建一份 docx，能活下来的只有标题、粗斜体、链接和表格；字体、字号、颜色、对齐、页边距、页眉页脚、分栏、浮动图片、文本框、目录和样式表基本全丢，改一个字保存回去，整篇的版式就变了。现在换成直接解析 docx 包、再按原结构写回的引擎（@docx-editor.dev，Apache-2.0）：常见版式打开什么样、改完还是什么样，标题栏 / 菜单栏 / 工具栏跟着 Notrat 的主题走，文档画布保持 Word 原色；外部程序改过这个文件再保存会先问一句，Ctrl+S 直接保存。
- **📊 Excel 换成完整的电子表格**：以前是手写的表格，只能双击改值、拖列宽，公式栏、工具栏、多工作表、合并单元格、撤销重做都得自己补。现在换成 FortuneSheet（MIT）做编辑面：完整工具栏、公式栏、工作表页签、合并单元格、撤销重做、选区复制一次到位，顶部还按 WPS 排了「开始 / 插入 / 数据 / 公式 / 视图」五个功能区页签（撤销 / 重做常驻，不随页签收起），图标统一换成 Lucide。读写的值、类型、公式、数字格式、列宽、行高和合并仍按原来的通路走，保真度不变。
- **🧭 Word 的菜单、大纲、查找都并进 Notrat 自己的入口**：点文件树顶部那枚 ▾ 打开顶部菜单栏时，「编辑」后面会多出 Word 的「格式 / 插入 / 审阅」三组，页面设置、表格网格、批注模式都还是引擎原装的那一套，不另做一份。左栏「大纲」直接读 Word 的标题样式；没有用标题样式的文档会提示「没有找到大纲信息」，并给一个「智能检索」按字号与加粗识别标题，识别出的条目同样能点、能跳。查找替换也换成 Notrat 的底部面板，引擎自带的导航窗格整块关掉，不再两套入口来回找。
- **🖼 PowerPoint（.pptx）从只读预览变成能改的演示文稿**：以前只能看，改一个字都做不到。现在能编辑页面、插入形状与文本、调整文字格式，左栏多出「幻灯片」页签（真实缩略图、右键增删排序、悬停按钮），大纲逐页读标题与正文；支持全选、框选、复制粘贴、动画与 F5 放映，保存后在 PowerPoint / WPS 里也能正常播放。
- **🤖 子 agent 默认和主 agent 同权，模型由主 agent 指定**：以前派去总结文件的子 agent 会回「我作为子代理没有文件读取权限」——它被硬编码成一件工具都不给；派发参数里也没有模型，临时 agent 只能继承全局默认。现在专家没配工具就与主 agent 同权，派发时可以精确授予 / 收窄工具权限，并指定用哪个服务商的哪个模型（认不出就明确报错并列出可选项，不再静默回退）。
- **🪟 安装程序重做成一张「请柬」**：760×580 单栏三页向导（装在哪 → 顺手带上什么 → 可以开始了），暖纸 + 铜色，内容直接落在纸上，没有一格白卡片；「磁盘占用」按装完之后真实占用的体积显示（当前约 508 MB），不是安装包本身的大小；用户协议运行时优先在线拉取、断网回退随包副本，第三方致谢放在右侧独立抽屉；也能被应用内自动更新直接调用，无人值守装完自动重开。
- **📐 Word / PowerPoint / Excel 都随窗口自适应**：Word 在 100% 档按页宽自动缩放（窄窗缩小、宽窗不超过 100%），其它缩放档位仍按你选的比例；PowerPoint 在数字档位下窗口一变就按新宽度重算，幻灯片始终完整居中、不出现横向滚动；Excel 的表格区域本来就会跟着窗口重排。
- **📂 打开外部文件：四个选项，选一次就记住**：单文件在当前窗口 / 用工作区在当前窗口 / 用工作区在新窗口 / 单文件在新窗口。勾过「记住选择」之后不再每次问，想改回就进 设置 → 通用 →「打开方式」选「每次询问」。
- **🧩 常用的插件按钮可以固定到发送键旁边**：工具栏上的插件按钮右键选「固定到工具栏右侧」，它就从会被「＋」收走的那一排搬到发送 / 历史按钮旁常驻，主界面和搭档模式都生效；再右键「取消固定」即可收回。
- **🖥️ 后台命令跑完，结果自己回到对话**：以前后台命令（显式后台运行，或终端忙时自动转后台）只有模型再问一次才会交出输出；回合结束后才退出的命令，输出就一直悬着。现在命令一退出，结果、退出码和耗时会被送回发起它的那个窗口，并自动起一轮让 AI 接着干；会话在命令真正结束前保持「运行中」，不会先响一声「完成」再推回来响第二遍。展示上并进原来那张「运行 X」工具卡（第二行「收到结果 · 退出码 N · 耗时」，展开才看输出），不会长成用户气泡。
- **🔐 连接器支持浏览器登录（标准 OAuth）**：以前服务端要求 OAuth 的连接器只能手填 token 或 Header。现在连接被 401 挡下会按 MCP 标准自动发现授权服务器、动态注册并带 PKCE 打开系统浏览器，授权完回到本机完成登录；client 信息、access / refresh token 与 PKCE 校验串加密存在本机，界面上只看得到「未授权 / 待授权 / 已授权」，拿不到 token。设置页里可登录、退出、继续授权和复制授权链接；市场安装会先试着连，真的要求授权才引导登录。
- **🧩 连接器也能在对话里让 AI 加**：新增一组连接器管理工具（增、查、改、删、测），AI 可以把连接器写进全局或当前工作区的配置，和设置页手工改走同一条落盘通路；密钥、Header 值只写盘、回显成 `***`，重名、缺启动命令、给 stdio 条目硬开 OAuth 会当场拒绝；删除时连运行中的进程一起停，另一档还有同名条目会提醒一句。
- **🧩 划词气泡里也能放插件按钮**：插件可以在 manifest 里声明划词动作，选中文字时「引用到聊天」右边会并排出现它们（文字、图标或自绘按钮）；点一下可打开插件自己的界面，或直接调用连接器工具，点下去那一刻的选区快照会一起交给它。覆盖 Markdown、代码、Word、PDF、Excel、CSV、PPT 与对话正文，没声明这个表面的插件不会冒出来。
- **🧩 连接器市场：从精选几十条，扩到官方 Registry 的数百条**：以前市场只有人工精选的 63 条，翻两页就到底；现在接上官方 MCP Registry 的分页（每页 100 个不同的连接器，最多 20 页、约两千条），弱网下「能拿多少算多少」，精选仍排最前。条目优先显示官方图标：Registry 自带的 `icons`、GitHub 头像、站点 favicon 依次兜底，有图片 logo 的排在只有 emoji 的前面；专家货架同样按「有官方图片 logo 的优先」排序。
- **💾 市场内容会存到本地：打开先出上次的，后台再更新**：MCP 目录、官方插件 / 专家列表、SkillHub 与 ClawHub 的默认货架，拉取成功后都会写入本机磁盘缓存，下次打开市场先秒出缓存，后台超过 6 小时才悄悄刷新一次；点「刷新」按钮才强制重拉，不用每次启动都把整个 Registry 翻一遍。
- **🛍️ 技能 / 专家 / 插件货架：简版卡片，缺头像用名字缩写**：一张卡只留图标、名字、一行描述和右上角动作，底栏只放少量指标与收藏；左栏分类与页头不动。没有官方头像的条目不再整屏同一个占位字——中文取前两个字、英文取首字母当头像（批量上架的「增长飞轮AI-…」终于分得清）。
- **🧩 技能货架从两百多条扩到最多约一千六百条**：SkillHub 之前发的是 `limit`（服务端不认），默认只回 20 条；ClawHub 只取第一页，约 196 条。现在按官方分页参数翻：SkillHub 浏览货架最多 6 页 × 100 条、分类 3 页、搜索 1 页，ClawHub 用游标最多 5 页 × 200 条；默认货架仍先读本机缓存。
- **🗂️ 工作区名片：选工作区之前，先知道它「在做什么」**：主页「最近」里每个工作区行多一句话——取最近对话主题、顶层目录 / 文件名、`NOTRAT.md` 或 `README.md` 头几行拼成；鼠标停住能看完整详情卡，点「AI 概括」可以让模型再缩成一句（只送目录名，不送完整路径）。工作空间那一行也会显示成员工作区的摘要；AI 判断「这句话该进哪个工作区」时，候选里也带上了这张名片。

### 📝 Word（.docx）：换内核，格式保得住

- **以前**：旧实现把 docx 转成网页，再从网页重建文档。标题、粗斜体、下划线、链接、表格、图片能活下来；字体、字号、颜色、对齐、页边距、页眉页脚、分栏、浮动图片、文本框、目录、样式表基本全丢——改一个字、按一次保存，排版就和原稿对不上了。
- **现在**：换成 @docx-editor.dev/react（原 eigenpal/docx-editor，Apache-2.0），直接解析 docx 包、按 OOXML 的结构排版、再原样写回，不再经过「网页」这个中间层。编辑时能改的就是原稿里的那些格式；保存时取整份文档字节，转 base64 后由既有的写盘通路落盘。另做五处：
  - **外部修改守卫**：打开时记下磁盘基准，保存前发现文件被别的程序改过，先弹「文件已在外部修改」问要不要覆盖；读不到磁盘（被占用 / 权限）不拦，避免永远存不出去。
  - **Ctrl+S**：App 的全局保存对 `.docx` 故意让路（写盘归编辑器自己），由 Word 编辑器直接接住；标题栏右侧显示「保存中… / 未保存」。
  - **外观接回主题**：引擎自带的标题栏、菜单栏、工具栏、弹层用 Notrat 的主题色；文档画布保持 Word 原色，不让主题色污染正文、打印和排版。
  - **打开速度**：引擎是一个约 4.6 MB 的懒加载包，第一次打开才现拉会白等 1~2 秒。现在启动后先让出启动期，再趁空闲把模块求值一遍（只解析模块，不挂载编辑器、不读文档），真正打开时只剩引擎初始化与文档解析；预热失败静默，不影响正常打开。
  - **选区**：引擎把「字与字之间的版面间隔」画成每个字符上的外边距（中文逐字约 0.78px，中文 / 西文自动间距约 8px）——这是 Word 的排版行为，不是多余空格。但浏览器的选区底色只盖内容本身、不盖这段间隔，拖选中文时每个字之间都露出一条白缝。现在把这段间隔改画成内边距：总宽度不变（字的位置、换行、光标落点都不变），选区背景却能连成一条。
- **边界**：`.doc`（旧版二进制格式）仍然只能只读预览 + 外部打开，这条没变；`.docx` 引擎只在打开 Word 时才加载。

### 🧭 Word 的菜单、大纲、查找：都用 Notrat 自己的入口

- **以前**：旧 Word 编辑器的菜单藏在自己的标题栏里，左栏没有 Word 大纲，查找替换也只在编辑器内部；换成新引擎后，引擎默认又带一整套自己的标题栏菜单和导航窗格（大纲 + 查找 + 定位书签），如果不做整合，就会和 Notrat 的顶部菜单栏、左栏大纲、查找面板各自为政。文档没用 Word 标题样式时，左栏也没有任何可用的下一步动作。
- **现在**：
  - **菜单**：编辑器里不再留「菜单」按钮；Word 的菜单投递到 App 顶部菜单栏「编辑」后面那一格，只投递「格式 / 插入 / 审阅」三组（文件与帮助在 App 自己的分类里已有同名项，不并排两份）。页面设置、表格网格、批注模式仍是引擎原装命令。
  - **大纲**：左栏读 Word 的标题样式。点一条大纲，标题一律顶到上边——此前目标已经贴在视口底边时点起来像没反应；离屏时又会居中，和 Word 导航窗格不一致。
  - **智能检索**：没有标题样式时，直接读 docx 里的正文与样式定义，解析样式继承（含文档默认值）算出每段的有效字号 / 加粗，以全文字数加权的正文字号作基线，把明显更大的段落、或「正文大小且整行加粗且短」的段落识别成标题，再按字号分档到 1~6 级。只读解析，不改文档；点「重新检索」时用编辑器当前的字节，包含尚未保存的修改。
  - **跳转兜底**：智能条目的 id 带段落标识，有标识就按锚点跳；旧文件没有标识、大纲文本又按空白归一过（正文里可能少一个空格），逐字符搜不到时，最后一级改按「去掉全部空白后的文本」在已排版的页面里找行再滚。
  - **查找替换**：引擎自带的导航窗格整块关掉，改用 Notrat 自己的底部面板驱动引擎的查找 / 选中 / 替换；入口与其它编辑器同一条（App「编辑 → 编辑器内查找」，焦点在文档里时 Ctrl/Cmd+F），查找框里 Tab 进替换框，Enter / Shift+Enter 跳下一处 / 上一处。
- **边界**：智能检索是启发式的，只按字号与加粗判断，不认颜色、缩进、编号等其它排版习惯；文档画布颜色不跟 Notrat 主题（保持 Word 原色）。

### 📝 Word 套标题样式：点一下就整段生效

- **以前**：三件事叠在一起——段落上原有的手动加粗 / 字号 / 颜色比样式更近一层，光套样式文字外观可以一点不变；折叠光标下「清除格式」什么都不清；引擎按词切分文本片段，只清到第一个词，同一段其余的词仍是手动格式。
- **现在**：套样式前先把选区扩到整段，同步派发一次选区变更让引擎感知，清除这一段的直接格式，再在下一拍把光标放回原处（放早了会被引擎自己的聚焦覆盖成整段选中）；段落按引擎的段落壳识别，不再按词片段猜。工具栏的样式项与「样式」菜单两个入口共用同一条逻辑，列表段跳过清除（避免连编号一起抹掉）。
- **边界**：样式显示名按界面语言翻译（Heading N → 标题 N），引擎自带工具栏下拉里仍是文档原本的英文名；这条只作用于被选中段落。

### 🔤 Word 的「建议」模式：没有可用实现，整项撤掉

- **以前**：模式菜单里有「编辑 / 建议 / 查看」三项，但「建议」是修订跟踪，新建修订和批注需要闭源的 pro 模块（官网定价 500 美元 / 月），开源三件套只能显示文档里已有的修订，不能新建，所以这一项永远灰着。
- **现在**：整项从模式菜单撤掉，只留「编辑 / 查看」；文档里已有的修订仍按最终内容显示，改动不受影响。
- **边界**：没有接入 pro 之前不会恢复该入口。

### 📊 Excel：从手写表格换成完整电子表格

- **以前**：手写的表格只能双击改值、拖列宽；公式、工具栏、选中区域统计全靠自己补，多工作表、合并单元格、撤销重做、选区复制都没有。
- **现在**：编辑面换成 @fortune-sheet/react（fortune-sheet，MIT），读写盘仍走原来的 SheetJS 通路，中间加一层转换：
  - **工具栏**：完整命令条由库提供；上方补一条 WPS 式功能区页签「开始 / 插入 / 数据 / 公式 / 视图」，切换的是显示哪些命令（命令本身仍是库的原生实现，不重写）。撤销 / 重做作为快速访问常驻，不随页签收起；「截图」项按用户要求去掉，不要再加回。
  - **交互**：公式栏、多工作表页签、合并单元格、撤销重做、选区复制、行高列宽调整全部可用。
  - **图标**：库原本用内嵌图标，现在统一覆盖成同名的 Lucide 图标；只换图标，不动库自己的内部元素。
  - **状态**：顶部那条文件名 / 保存条按用户要求去掉（文件名看页签），保存只走组件内 Ctrl+S；「保存中… / 未保存 / 计数：N」进 Notrat 底部状态栏；库自带的底部统计条整条收起，不再留一条空带。
  - **页签不会再整排收进「更多」**：库在工具栏条目数变化时，会拿上一个页签的旧坐标算换行位置，插入 / 数据 / 公式 / 视图这些明明放得下的页签也被切出「更多」，而且不会自愈。这一版已经修好，五个页签都能完整显示。
  - **大表闸门**：完整电子表格会把表格展开成稠密矩阵，超限会把界面撑崩。现在超过 3 万行 / 1024 列 / 50 万格 / 8 万非空格就降级成只读预览（分页表格 + 外部打开），绝不拿原文件冒险。
  - **未保存判定**：库在切换选区时也会触发变更事件，不能一选就标「未保存」；改为用内容指纹和基准比对，基准在首次指针按下 / 按键时抓，保存成功后刷新。
- **边界**：SheetJS 社区版读不到也写不回字体 / 填充这类样式，所以 Excel 里改的字体、颜色、填充保存后不落盘（编辑态也不接这些字段）；值、类型、公式、数字格式、列宽、行高、合并的既有保真度不变，`.xls` 仍按原格式回写。样式之外的编辑都正常保存。

### 🖼 PowerPoint（.pptx）：只读预览换成能改的演示文稿

- **以前**：`.pptx` 用只读预览组件打开，能看不能改；没有编辑工具栏，左栏「大纲」对 PPT 不提供任何结构，深色底或彩色形状上的文字光标（写死黑色）看不见。

  - **工具栏**：引擎自己的编辑工具栏开在顶部（撤销 / 重做、插入形状与文本框、幻灯片操作、文字格式），按 Word 编辑器的样子改成通栏并接回 Notrat 主题；引擎顶部那条「文件名 / 查看·编辑 / 保存」整行隐藏，交给 Notrat 的页签。文件菜单里的新建、打开、另存、打印一律关掉——绕过统一链路的小门不开。按钮按 WPS 的样子做成「图标在上、短标签在下」的两行，标签收成 ≤3 个中文字。
  - **直接打开**：没有工作区时用「单文件」方式打开 `.pptx`（拖进来 / 系统关联 / 双击），左栏会自动唤出并直接落在「幻灯片」页签，离开 PPT 后收起，主页照旧不摆空文件树。
  - **左栏**：`.pptx` 打开时，左栏是三只页签——文件 / 大纲 / 幻灯片。页面切换进「幻灯片」页签，铺的是真实页面缩略图（第一张就是封面，所见即所得），点哪一页跳哪一页，顶上还有上一张 / 下一张与「第几张 / 共几张」；右键盘与悬停层提供新建 / 复制 / 删除 / 上移下移 / 隐藏。大纲只收真文字：图标字体画的图标、页码 / 日期字段、只剩「01」「•」「→」的装饰段落全部滤掉。
  - **大纲点到组件上**：每条文字在收集时就记住它出自哪个组件，点击后翻到那一页、选中那个组件，并把光标落到你点的那一段。
  - **一页一页编辑**：编辑区一次只放当前这一页（居中、不出现滚动条），翻页走左栏「幻灯片」页签；在画布上按 PageUp / PageDown、方向键、Home / End 或滚轮也能翻页，左栏跟着同步。
  - **全选、框选、复制粘贴**：Ctrl+A 选中当前页全部组件，空白处拖框相交即选、按住 Shift 加选；选中后可整组删除 / 微调 / 移动，Ctrl+C、Ctrl+V 整组复制粘贴，副本错开 16px 并自动成为新的选区。
  - **动画**：画布右下角「动画」按钮打开右侧动画面板（浮层，不挤画布），也可以直接右键组件加「进入 / 强调 / 退出」动画；每条可改触发方式、时长与延迟、调整顺序、单独删除、一键预览。应用内 F5 放映会按单击组一组组演出来，最后一页放完再点一下即结束。
  - **放映**：进入全屏不再「开一下就自己弹回来」，翻多少页也不会中途退出全屏；方向键、空格、滚轮都能翻页；可以从左栏任意一页（悬停 ▶ 或双击）开始放映。动画按 PowerPoint 原生格式写进文件，保存后在 PowerPoint / WPS 里都能正常播放。
  - **外观**：工具栏、菜单、右键菜单与按钮提示跟随 Notrat 的语言显示中文；图标统一换成 Lucide；深色底或彩色形状上编辑文字时，光标按所在背景自动反色。
  - **划词引用**：在 PPT 里选中文字，和 Word / PDF / Excel 一样会弹出「💬 引用到聊天」。
- **边界**：主题色只接工具栏、弹层、页码列表底，幻灯片画布保持原色（排版保真）；超过 300 张的演示文稿，左栏大纲只覆盖前 300 张；右键菜单暂不含「插入文本框 / 图片」（工具栏里已有）。Ctrl+A、框选与复制 / 粘贴都只作用**当前页**；复制出的组件只能粘回原来那一页。幻灯片之间的切换效果仍不支持（文件里原有的切换条目不会删），应用内放映也只播组件动画。路径动画、图表动画等认不出的效果只读保留，不会被覆盖。

### ↩️ PowerPoint 文字编辑：撤销重做这次真的管用

- **以前**：引擎的撤销有三个硬伤——文本框里的 Ctrl+Z 只撤当前编辑会话，点出去就没了；文字提交时会把这一页的历史整个清掉，改一个字后连拖动、删除形状都撤不了；只有形状记历史，幻灯片增删和图片操作完全不记，而且没有独立的重做接口。工具栏的撤销按钮也只数形状，只改过文字时一直是灰的。
- **现在**：按页维护一套统一历史：文字提交记下改前 / 改后两份段落快照，形状操作记一条标记、撤销时原样转交引擎自己的栈，引擎栈被清过就跳过这条继续往上找；撤销 / 重做后主动通知画布重绘。工具栏按钮在历史非空时保持可用，点击由 Notrat 接住；文本框里按 Ctrl+Z 会和引擎自己的局部撤销对齐，不会在出框后表现成「重做」。
- **边界**：新建 / 复制 / 删除 / 移动幻灯片会让页号整体错位，这一类动作会清空历史；动画的增删改不在文字撤销范围内。

### 📐 办公三件套：窗口一变，页面跟着缩

- **以前**：Word 的共享 100% 档写的是固定的绝对比例，窗口一窄就出现横向滚动；PPT 只在引擎自己的 `fit` 档按容器重排，数字档位下写进去的是「当时算好的固定数字」，窗口一变就卡住，幻灯片被截。
- **现在**：
  - **Word**：共享 100% 档改为「按页宽自适应」——窄窗自动缩（下限 50%），宽窗最多 100% 不放大，引擎自己观察容器重排；其它缩放档位仍写绝对比例，用户选多少就是多少。
  - **PowerPoint**：数字档位下按引擎同一套适配公式反推当前容器能放多大，窗口一变就重写「适配比例 × 缩放档位」；比例没变不写，避免抖。
  - **Excel**：不用新代码——表格的编辑面本来就跟着容器宽高重设，列宽变化后工具栏再自己重新折行。
- **边界**：Word 自适应只在 100% 档生效，选 125% / 150% 等仍是固定比例；PPT 在 `fit` 档仍交给引擎自己算，Notrat 不重复接管。

### 💬 编辑消息与切分支：旧回合留在旧分支，切完还是同一个形态

### 💬 思考内容：跟到底，也不再卡

- **以前**：流式思考走的是单独的更新通道，既不动消息列表、也不动「正在生成」的状态——外层列表的自动跟随收不到任何增长信号，思考块只能顶着视口往上长。同时每个思考分片都是整段替换，几万字的文本每帧重排，吸底区域还要每帧读一次滚动高度，主线程被吃满，看起来就像文字在内部反复重新拼接。
- **现在**：思考状态每次推进都请求一次「跟随到底」，与正文流共用同一个每帧最多一次的调度，用户手动上翻时仍由跟随逻辑自己拒绝，不会抢回滚动。思考文字的上屏节奏做了合并，数据本身不降频——画面上的快照永远是最新值；生成结束和「思考段固化」这两个时刻立即刷新，避免同一段文字同时出现在时间线和实时槽位两处。
- **边界**：正文流仍按帧合并，不受这次调整影响；用户上翻后不会被强制拉回底部；刷新页面仍会中断当前流，只保留已经生成的内容。

### 🖥️ 后台命令：跑完自己把结果交回对话

- **以前**：后台命令只有「拉模式」——模型调 `get_background_command` 才看得到输出；回合收尾之后才退出的命令，输出一直悬在主进程里，界面已经翻成「已完成」，完成提醒也先响过一次。
- **现在**：命令退出时主进程把事件定向发给发起它的那个窗口，渲染层确认「是这条会话、当前空闲、用户没按过停止」后，把结果排进发送队列、串行起一轮新回合；展示上并进发起它的那张「运行 X」工具卡（第二行「收到结果 · 退出码 N · 耗时」，展开才看输出），不会长成用户气泡。后台命令还在跑的会话，列表行与运行岛继续保持「运行中」，完成提醒等它真正结束再响。
- **不推的三种情况**：用户按过停止；退出时还有 `wait_seconds` 等待者（那段输出已经作为工具结果交回模型）；没有发起窗口（IM / 网关调用）。
- **模型侧也知道了**：结果会自动回来写进了每次请求现拼的运行提示词（老用户升级后同样生效，不依赖默认提示词）——回合结束后才退出的命令不用反复去问；回合还在跑就自己带 `wait_seconds` 等，等过就不再补推。后台 id 是 `[background] … id=` 里那串不透明 UUID，必须原样抄，不许自造、缩写或跨命令复用，应用重启后旧 id 一律失效；查不到时会当场列出当前还在跟踪的命令，让模型自己改口。
- **边界**：只在会话空闲、且事件属于当前会话时推；回合还在跑时留给模型自己拉，不制造并行回合。注入消息在模型侧仍是 user 角色，只是显示层不按用户气泡画。

### 📝 Markdown 往返：图片并排、空格空行原样，源码改完切回去就是新内容

- **以前**：图片是块级原子节点，同一行的多张徽章在序列化 / 再解析时被拆成独立块，中间只剩「只有空格的段落」被当成空行吃掉——空格数量、空行分段、并排关系全部失真。源码模式改完切回编辑时又用进源码之前那份正文，加上 800ms 防抖和「暂停外部同步」标记，改动像没发生过；顶栏按钮与快捷键还各走一条路，结果不一致。
- **现在**：图片改成行内节点，同一行的多张徽章共享一段、按宽度自然换行；单独成段的图片由解析后处理包回段落，空行原样保留；手打 `![说明](地址)` 会就地换成图片。源码 → 编辑把逐次击键写入的草稿灌进富文本（比上层 content 新），原文没改、富文本没编辑过就跳过整篇重解析；编辑 → 源码方向在富文本没编辑过时原样交还原文。顶栏、快捷键、外部切换收口到同一个入口。
- **边界**：真正在富文本里编辑过才以富文本为准序列化；图片行内化后跟着文字排版，点选八边形手柄缩放的能力不变。

- **现在**：插件按钮右键（或用面板右键菜单里的「面板位置」）选「固定到工具栏右侧」，这一枚就搬到发送 / 历史按钮旁常驻——固定的这一组不参与收纳，永远不会进「＋」；主界面与搭档模式都显示。再右键「取消固定」即可收回，「面板位置」菜单里同一条也会同步显示当前状态。
- **边界**：欢迎屏不是侧栏，不显示工具栏固定按钮；面板被挪离「AI 对话工具栏」位置后，固定状态不生效；全部固定时行内那一组不占位、不会留下空档。

### 🧩 划词气泡：插件也能在这里放按钮

- **以前**：选中文字时只有内置的「引用到聊天」；插件想对选区做点什么，只能让用户复制粘贴到别处。
- **现在**：插件在 manifest 的 `contributions.selectionActions[]` 里声明按钮——文字 / 图标，或一段自绘 TSX；点击可打开插件自己的动作组件（挂在应用根节点，可以 portal 出自己的界面），或直接调用该插件的连接器工具。按钮与「引用到聊天」并排、排在它后面，按 `order` 排序；按下时把这一刻的选区快照（文字、文件路径与文件名）一并交给动作，不依赖 250ms 防抖。表面覆盖 Markdown、代码、Word、PDF、Excel、CSV、PPT 与对话正文，manifest 里写错的值会被忽略。
- **边界**：编辑器表面取各编辑器已上报的全局选区，对话正文由消息列表显式传入；点按钮不折叠选区；自绘按钮编译或渲染失败时回退成插件图标。

::: details ⚡ 启动与性能 · 3 项

### 💾 保存 Office：窗口不再刷一下

- **以前**：保存写盘后，文件监听把「自己刚写出去的内容」当成外部改动，内容版本号一涨，整个编辑器就被卸载重挂——引擎重新读字节、重新解压建模型，看起来就是窗口闪一下。
- **现在**：保存成功后登记「这份内容是我写的」（30 秒内有效），监听到同一份内容直接吞掉；就算没被认出来（例如批量保存），只要磁盘内容与当前编辑内容逐字相同，也只对齐磁盘基准、不重新加载。真正的外部改动（内容不同）仍照旧整格重载。
- **边界**：保存失败不登记；被外部程序改成同样的内容不算外部改动；重载逻辑未改。

### ⚡ 编辑器加载：重依赖分档，空闲时先热身

- **以前**：文件查看器在顶层静态引用了 PDF、旧版 PPT、Excel 三个编辑器，它们的依赖全被并进入口包，构建产物 5.7 MB——打开一张图、一个 docx 也要先解析这几 MB。
- **现在**：三个编辑器改成按需加载，渲染点统一包一层「加载中」占位；启动后按 2.5 秒 / 4 秒 / 6 秒的顺序，在浏览器空闲时分别把 Word 引擎、富文本引擎（约 2.1 MB，含公式 / 代码高亮 / 代码编辑）、PPT 引擎的模块先求值一遍——只解析模块，不挂编辑器、不读文档，真正打开时只剩初始化和文档解析。预热失败静默，不影响正常打开。
- **边界**：第一次打开仍要等引擎初始化与文档解析；预热只发生在应用启动后的空闲窗口，不抢启动期。

### 🩺 编辑器偶发「加载失败」：不再裸读还没挂好的视图

- **以前**：富文本编辑器在视图还没挂载时返回一个代理，除了少数几个状态字段，其它属性一读就抛错。最容易命中的是：界面更新时同步触发监听器，监听器里去读视图，而此刻编辑器刚好被销毁定时器销毁；事件监听器和延时定时器里也有同类读法。
- **现在**：所有读取都走安全取景器（视图未就绪就返回空），事件监听器、面板级拖放、延时归位定时器一并改掉；编辑器内容组件只挂活实例。另加回归围栏，禁止再出现裸读写法。
- **边界**：只影响「视图还没挂好」的瞬间；正常编辑路径不变。

### 🪟 安装程序：从「下一步」到一张请柬

- **以前**：双击 `.exe` 走的是默认的安装向导——一页页灰底「下一步」，没有品牌感，也不会告诉你装完到底占多少磁盘。

  - **第一页**：大标题 + 一句官网同款标语，下面是安装位置、「磁盘占用 · 管理员权限」细线行和三个卖点。磁盘占用按装完之后实际占用的体积显示（当前约 508 MB），不是安装包本身的大小。
  - **第二页**：「顺手带上这些」——快捷方式与「用 Notrat 打开」两组胶囊，文件关联按实际勾选汇总到第三页。

  - **协议与致谢**：用户协议运行时优先在线拉取（4 秒超时、失败静默），源码里先塞随包副本，抽屉右上角小印标「在线获取 / 随安装包附带」；第三方开源组件致谢放在右侧独立抽屉，按钮写「关闭」，不参与同意勾选。
  - **接自动更新**：应用内更新把它叫起来时走无人值守，原样交给内嵌安装流程，装完自己拉起应用；手动双击永远走完整向导。

### 📦 安装包：把 PPT 编辑器装进去，也把不该带的依赖拿掉

- **以前**：`.pptx` 的编辑器代码没进包（且 Windows / macOS 都没注册 `.pptx` / `.docx` / `.xlsx` 文件关联）；只在界面里用到的依赖还留在生产依赖里，打包时又原样带了一份。
- **现在**：
  - **补齐**：PowerPoint 编辑器随包；Windows 与 macOS 的 `.pptx` 关联注册进安装包，`.docx` / `.xlsx` / `.xls` / `.xlsm` / `.xlsb` 一并补上。
  - **瘦身**：只被界面引用的依赖移到开发依赖（打包时不再重复携带）；离线语音识别只保留运行必需的文件。
  - **再瘦身**：Windows x64 解包目录 794 MB → 532 MB；Electron 自带的语言包只留中英两种；离线推理只留当前平台 / 架构的二进制；旧版 PDF 演示页的静态副本与构建期资源不再进包。**下载体积**：Windows x64 安装器 233 MB → 152 MB，三合一通用安装器 699 MB → 492 MB。
- **边界**：macOS 的文件关联由系统登记，未签名 / 未公证的包可能不认；具体体积以本次构建产物为准。

### 🪟 安装器细节：32 位界面、安装目录与发布者

- **以前**：32 位安装包只能显示简化界面（WebView2 加载失败，错误码 `0x8007000B`）；安装时把文件直接铺在用户选中的目录里；属性里的「发布者 / 公司」写的是简称；点「浏览」永远从默认目录开始。
- **现在**：32 位外壳配 32 位加载器、64 位 / ARM 配对应位数；选中的目录不是 `Notrat` 时自动建一层子文件夹，覆盖升级按原安装位置不搬家；发布者改为法定全称「泸州市江阳区巢墨科技工作室（个体工商户）」；「浏览」从输入框当前目录打开。
- **边界**：覆盖升级不改变原有安装位置；发布者名称写入安装包版本资源。

::: details 🔌 连接器与智能体 · 4 项

### 🔌 连接器（MCP）：缺环境变量时，装完就知道缺哪一个

- **以前**：只认几种固定的英文措辞。漏认的后果不是报错本身，而是安装时不出「配置环境变量」弹窗：用户装完一启动就是「子进程退出」，还得自己回头找是哪一步缺了变量。
- **现在**：补上 Python 的 `<VAR> environment variable is required / not set / must be set`，以及 `environment variable: <VAR> …` 写法；同时加上「全大写 + 至少 3 个字符」的形态判断——为了认 `Api key is required` 这类措辞，旧规则会连小写的 variable 也抓出来当变量名，新措辞一加就暴露了。
- **边界**：只认常见措辞，认不出的启动失败仍按原始错误展示。

### 🤖 子 agent：默认与主 agent 同权，用哪个模型由主 agent 定

- **以前**：运行时专家里 summarizer 被硬编码成「不给任何工具」，派发参数也没有模型字段——临时子 agent 只能继承全局默认，想换模型只能先把专家写进配置。工具为空时提示词里也没有任何交代，模型只能自己编一个理由。
- **现在**：
  - **权限**：优先级从高到低——主 agent 派发时给的 `tools`（服务器 id / 工具名 / 工具名前缀三种写法都认）→ 专家自己配了具体的连接器 → 专家级「不用工具」开关 → 其余一律**与主 agent 同权**。授出的工具仍受全局开关约束，不能越过用户关掉的连接器；派发时传空数组 `[]` 表示「这次明确不给工具」，与「没指定」区分开。
  - **如实汇报**：子 agent 的运行时上下文里写明工具数量、可用工具清单和权限来源；缺工具时要求点名缺哪一项能力，由主 agent 带着授权重新派发，不再笼统地说「工具不可用」。
  - **模型**：派发与创建专家时都可以指定 `provider` / `model`；服务商认 id 或显示名（大小写、首尾空格不敏感），只给模型就挂在当前服务商上，认不出的服务商直接报错并列出可用清单——**绝不静默回退**。
  - **不用猜**：派发工具的说明里现读当前配置的服务商与模型目录，主 agent 照着填即可。
- **边界**：`provider` 只能在已配置的服务商里选；设置页给 researcher 的那个「允许使用工具」开关仍是硬关闭，派发也绕不过去。

### 🔐 连接器登录：浏览器授权一次，凭据留在本机

- **以前**：只能手填 `Authorization` 或 API Key；服务端要求 OAuth 时连接直接失败，市场却把「带网址」的条目一律写成「还差一步登录」，点下去还报 `HTTP connection failed (200)`。
- **现在**：按 MCP 标准走完整链路——连接被 401 拦下 → 读 `WWW-Authenticate` 指向的受保护资源元数据 → 找到授权服务器 → 动态注册客户端 + PKCE → 打开系统浏览器 → 回到 `127.0.0.1` 临时端口上的固定回调路径 → 用 code 换 token。换到之后拿新凭据真连一次，连不上就把真实原因回给回调页。
- **凭据放哪**：client 信息、access / refresh token、PKCE 校验串加密写入本机 `<Notrat 主目录>/.mcp/oauth-credentials.json`（系统加密不可用时退化 base64 并在日志说明）；状态广播不带 token，界面只看到「未授权 / 待授权 / 已授权 / 出错」。设置里可登录、退出、继续授权、复制授权链接；市场安装先连，真被 401 挡住才引导登录。
- **边界**：只有明确 `enabled: true` 才启用；10 分钟内重启复用 state 与回调地址；连接器地址变了旧凭据立即作废；测试连接把「未授权」当非失败。

### 🧩 连接器也能让 AI 加：在对话里说「装一个…」

- **现在**：`mcp_add_server` / `mcp_list_servers` / `mcp_update_server` / `mcp_remove_server` / `mcp_test_server` 五个工具。写的是磁盘配置：全局 `<Notrat 主目录>/.mcp/config.json`，工作区 `<工作区>/.notrat/mcp/config.json`；先写 `.tmp` 再改名，设置页与侧栏同步器收到变更后重读，和用户手工改文件是同一条路。列出时工作区覆盖全局并带运行状态；更新会停旧连接；删除连运行中的进程一起停。
- **安全与校验**：密钥、Header 值只落盘，回显 `***`（日志和会话里也不留明文）；id 限可读 slug、不参与拼路径；全局档新增同名工作区条目会被覆盖，所以直接拒绝；缺启动命令、重复 id、给 `stdio` 硬开 OAuth 都当场拒绝。
- **边界**：空间档（space）不开放——主进程拿不到发起窗口所在空间的根；需要空间作用域请到设置页迁移。测试连接成功返回工具数，「要求授权」不算失败。

::: details 🧩 市场与技能 · 5 项

### 🛒 连接器市场：从精选几十条，扩到官方 Registry 的数百条

- **以前**：市场只有人工精选的 63 条，翻两页就到底；官方 Registry 那段其实一直请求 `limit=500`，接口回 422，拿到的永远是空数组；就算参数对了，默认按版本翻页，同一个连接器会被十几条历史版本占满一页。
- **现在**：接上 `registry.modelcontextprotocol.io/v0/servers` 分页——每页 100 个不同的连接器（`version=latest`），最多 20 页、约 2000 条；单页 20 秒、整轮 120 秒预算，哪页失败就停，已经拿到的照常进市场，并且是渐进加载：精选先上屏，每翻回一页就补一批。精选永远排最前；同款包（npm / PyPI 包名归一后）与精选重复的跳过，同名多版本只留最新。
- **logo 从哪来**：Registry 自带的 `icons` → GitHub 头像 → 站点 favicon → 分类 emoji；不重画、不伪造第三方 logo。专家货架同理：有官方图片 logo 的排前面，其余保持原顺序。
- **边界**：只收 Registry 里带可用配置（npm / PyPI 包或远程地址）的条目；弱网 / 内网可能只翻到前几页；浏览器里一份缓存约 1.6M 字符，写不下会退回主进程磁盘缓存。

### 💾 市场数据：打开先出上次的，后台再刷新

- **以前**：每次打开市场、每次启动都把整个 Registry 重新翻一遍，网络负担很大，弱网下列表一片空白。
- **现在**：MCP 目录、官方插件 / 专家列表、SkillHub 与 ClawHub 默认货架拉取成功后写入本机磁盘缓存；下次打开先秒出缓存，后台超过 6 小时才刷新，点「刷新」才强制重拉。缓存 key 带版本，升版时不端出旧目录。刷新时每翻回一页先把已经拿到的铺上，列表边刷新边长。
- **边界**：带关键词的搜索不落盘；缓存过期但仍可用时先出旧内容，不在打开时阻塞界面。

### ⚡ 市场图标：看得见才加载，失败的不再反复重试

- **以前**：一屏几百个 logo 同时发请求，翻页、重挂还会把加载失败的图再试一遍。
- **现在**：离屏的图不发请求（提前 400px 才开始加载），全进程最多 12 张同时在飞，15 秒没回来就放开位置；失败的 URL 记下来（最多 600 条），翻回来不再重试；图片一律懒加载 + 异步解码；官方推荐技能窗口里的头像也改成懒加载。
- **边界**：限流只作用在图片加载，不影响目录请求；失败记录在本次运行内有效。

### 🛍️ 技能 / 专家 / 插件货架：简版卡片，缺头像用名字缩写

- **以前**：卡片信息多、底栏指标多；SkillHub 上游不少技能的 `iconUrl` 本来就是空的，没有头像的条目显示同一个占位图标，同一发布者批量上架的「增长飞轮AI-…」整屏都是同一个「增」。
- **现在**：三个货架都换成简版卡片——图标、名字、一行描述、右上角动作，底栏只留少量指标与收藏；已安装卡片仍有强调底色，收藏仍在底栏用星标标出。缺官方头像时用名字缩写：中文取前两个字，拉丁名取首字母大写。
- **边界**：缩写只在没有官方 iconUrl 时兜底，有官方图仍用官方图；不重画、不伪造第三方 logo。

### 🧩 技能货架：从两百多条扩到最多约一千六百条

- **以前**：SkillHub 的 `/api/skills` 发的是 `limit`，服务端不认，永远只回默认 20 条；ClawHub 的 `/api/v1/skills` 只取第一页，约 196 条。
- **现在**：SkillHub 改用 `page` + `pageSize`（1~100）翻页——浏览货架最多 6 页约 600 条，分类 3 页、搜索 1 页；ClawHub 用 `nextCursor` 游标续页，每页约 200 条、最多 5 页约 1000 条；默认货架仍先读本机缓存（命中 24 小时、兜底 7 天），带关键词的搜索不落盘。分类计数与列表共用同一个判定；点分类一律清空搜索词；「加载更多」改为滑到底自动加载（提前 300px）。
- **边界**：旧 `/search` 兜底接口单次上限 100 条；分类只做本地筛选；两边合并后按包名去重，实际条数以货架为准。
