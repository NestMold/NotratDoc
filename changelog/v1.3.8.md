# 1.3.8

发布日期：2026-11-06　·　[← 上一版](/changelog/v1.3.7)

**这一版**：9 项亮点 · 35 处修复 · 26 项改动详情（详情按模块收起，点标题展开）

## ⚡ 更新亮点

- **📝 Word（.docx）换成能「原样读、原样写」的引擎**：以前是先把 docx 转成网页再拿网页重建一份 docx，能活下来的只有标题、粗斜体、链接和表格；字体、字号、颜色、对齐、页边距、页眉页脚、分栏、浮动图片、文本框、目录和样式表基本全丢，改一个字保存回去，整篇的版式就变了。现在换成直接解析 docx 包、再按原结构写回的引擎（@docx-editor.dev，Apache-2.0）：常见版式打开什么样、改完还是什么样，标题栏 / 菜单栏 / 工具栏跟着 Notrat 的主题走，文档画布保持 Word 原色；外部程序改过这个文件再保存会先问一句，Ctrl+S 直接保存。
- **📊 Excel 换成完整的电子表格**：以前是手写的表格，只能双击改值、拖列宽，公式栏、工具栏、多工作表、合并单元格、撤销重做都得自己补。现在换成 FortuneSheet（MIT）做编辑面：完整工具栏、公式栏、工作表页签、合并单元格、撤销重做、选区复制一次到位，顶部还按 WPS 排了「开始 / 插入 / 数据 / 公式 / 视图」五个功能区页签（撤销 / 重做常驻，不随页签收起），图标统一换成 Lucide。读写的值、类型、公式、数字格式、列宽、行高和合并仍按原来的通路走，保真度不变。
- **🧭 Word 的菜单、大纲、查找都并进 Notrat 自己的入口**：点文件树顶部那枚 ▾ 打开顶部菜单栏时，「编辑」后面会多出 Word 的「格式 / 插入 / 审阅」三组，页面设置、表格网格、批注模式都还是引擎原装的那一套，不另做一份。左栏「大纲」直接读 Word 的标题样式；没有用标题样式的文档会提示「没有找到大纲信息」，并给一个「智能检索」按字号与加粗识别标题，识别出的条目同样能点、能跳。查找替换也换成 Notrat 的底部面板，引擎自带的导航窗格整块关掉，不再两套入口来回找。
- **🖼 PowerPoint（.pptx）从只读预览变成能改的演示文稿**：以前只能看，改一个字都做不到。现在能编辑页面、插入形状与文本、调整文字格式，左栏多出「幻灯片」页签（真实缩略图、右键增删排序、悬停按钮），大纲逐页读标题与正文；支持全选、框选、复制粘贴、动画与 F5 放映，保存后在 PowerPoint / WPS 里也能正常播放。
- **🤖 子 agent 默认和主 agent 同权，模型由主 agent 指定**：以前派去总结文件的子 agent 会回「我作为子代理没有文件读取权限」——它被硬编码成一件工具都不给；派发参数里也没有模型，临时 agent 只能继承全局默认。现在专家没配工具就与主 agent 同权，派发时可以精确授予 / 收窄工具权限，并指定用哪个服务商的哪个模型（认不出就明确报错并列出可选项，不再静默回退）。
- **🪟 安装程序重做成一张「请柬」**：760×580 单栏三页向导（装在哪 → 顺手带上什么 → 可以开始了），暖纸 + 铜色，内容直接落在纸上，没有一格白卡片；「磁盘占用」按装完之后真实占用的体积显示（当前约 508 MB），不是安装包本身的大小；用户协议运行时优先在线拉取、断网回退随包副本，第三方致谢放在右侧独立抽屉；也能被应用内自动更新直接调用，无人值守装完自动重开。
- **📐 Word / PowerPoint / Excel 都随窗口自适应**：Word 在 100% 档按页宽自动缩放（窄窗缩小、宽窗不超过 100%），其它缩放档位仍按你选的比例；PowerPoint 在数字档位下窗口一变就按新宽度重算，幻灯片始终完整居中、不出现横向滚动；Excel 的表格区域本来就会跟着窗口重排。
- **📂 打开外部文件：四个选项，选一次就记住**：单文件在当前窗口 / 用工作区在当前窗口 / 用工作区在新窗口 / 单文件在新窗口。勾过「记住选择」之后不再每次问，想改回就进 设置 → 通用 →「打开方式」选「每次询问」。
- **🧩 常用的插件按钮可以固定到发送键旁边**：工具栏上的插件按钮右键选「固定到工具栏右侧」，它就从会被「＋」收走的那一排搬到发送 / 历史按钮旁常驻，主界面和搭档模式都生效；再右键「取消固定」即可收回。

### 📝 Word（.docx）：换内核，格式保得住

- **以前**：旧实现把 docx 转成网页，再从网页重建文档。标题、粗斜体、下划线、链接、表格、图片能活下来；字体、字号、颜色、对齐、页边距、页眉页脚、分栏、浮动图片、文本框、目录、样式表基本全丢——改一个字、按一次保存，排版就和原稿对不上了。
- **现在**：换成 @docx-editor.dev/react（原 eigenpal/docx-editor，Apache-2.0），直接解析 docx 包、按 OOXML 的结构排版、再原样写回，不再经过「网页」这个中间层。编辑时能改的就是原稿里的那些格式；保存时取整份文档字节，转 base64 后由既有的写盘通路落盘。另做五处：
  - **外部修改守卫**：打开时记下磁盘基准，保存前发现文件被别的程序改过，先弹「文件已在外部修改」问要不要覆盖；读不到磁盘（被占用 / 权限）不拦，避免永远存不出去。
  - **Ctrl+S**：App 的全局保存对 `.docx` 故意让路（写盘归编辑器自己），由 Word 编辑器直接接住；标题栏右侧显示「保存中… / 未保存」。
  - **外观接回主题**：引擎自带的标题栏、菜单栏、工具栏、弹层用 Notrat 的主题色；文档画布保持 Word 原色，不让主题色污染正文、打印和排版。
  - **打开速度**：引擎是一个约 4.6 MB 的懒加载包，第一次打开才现拉会白等 1~2 秒。现在启动后先让出启动期，再趁空闲把模块求值一遍（只解析模块，不挂载编辑器、不读文档），真正打开时只剩引擎初始化与文档解析；预热失败静默，不影响正常打开。
  - **选区**：引擎把「字与字之间的版面间隔」画成每个字符上的外边距（中文逐字约 0.78px，中文 / 西文自动间距约 8px）——这是 Word 的排版行为，不是多余空格。但浏览器的选区底色只盖内容本身、不盖这段间隔，拖选中文时每个字之间都露出一条白缝。现在把这段间隔改画成内边距：总宽度不变（字的位置、换行、光标落点都不变），选区背景却能连成一条。
- **边界**：`.doc`（旧版二进制格式）仍然只能只读预览 + 外部打开，这条没变；`.docx` 引擎只在打开 Word 时才加载。

### 🧭 Word 的菜单、大纲、查找：都用 Notrat 自己的入口

- **以前**：旧 Word 编辑器的菜单藏在自己的标题栏里，左栏没有 Word 大纲，查找替换也只在编辑器内部；换成新引擎后，引擎默认又带一整套自己的标题栏菜单和导航窗格（大纲 + 查找 + 定位书签），如果不做整合，就会和 Notrat 的顶部菜单栏、左栏大纲、查找面板各自为政。文档没用 Word 标题样式时，左栏也没有任何可用的下一步动作。
- **现在**：
  - **菜单**：编辑器里不再留「菜单」按钮；Word 的菜单投递到 App 顶部菜单栏「编辑」后面那一格，只投递「格式 / 插入 / 审阅」三组（文件与帮助在 App 自己的分类里已有同名项，不并排两份）。页面设置、表格网格、批注模式仍是引擎原装命令。
  - **大纲**：左栏读 Word 的标题样式。点一条大纲，标题一律顶到上边——此前目标已经贴在视口底边时点起来像没反应；离屏时又会居中，和 Word 导航窗格不一致。
  - **智能检索**：没有标题样式时，直接读 docx 里的正文与样式定义，解析样式继承（含文档默认值）算出每段的有效字号 / 加粗，以全文字数加权的正文字号作基线，把明显更大的段落、或「正文大小且整行加粗且短」的段落识别成标题，再按字号分档到 1~6 级。只读解析，不改文档；点「重新检索」时用编辑器当前的字节，包含尚未保存的修改。
  - **跳转兜底**：智能条目的 id 带段落标识，有标识就按锚点跳；旧文件没有标识、大纲文本又按空白归一过（正文里可能少一个空格），逐字符搜不到时，最后一级改按「去掉全部空白后的文本」在已排版的页面里找行再滚。
  - **查找替换**：引擎自带的导航窗格整块关掉，改用 Notrat 自己的底部面板驱动引擎的查找 / 选中 / 替换；入口与其它编辑器同一条（App「编辑 → 编辑器内查找」，焦点在文档里时 Ctrl/Cmd+F），查找框里 Tab 进替换框，Enter / Shift+Enter 跳下一处 / 上一处。
- **边界**：智能检索是启发式的，只按字号与加粗判断，不认颜色、缩进、编号等其它排版习惯；文档画布颜色不跟 Notrat 主题（保持 Word 原色）。

### 📝 Word 套标题样式：点一下就整段生效

- **以前**：三件事叠在一起——段落上原有的手动加粗 / 字号 / 颜色比样式更近一层，光套样式文字外观可以一点不变；折叠光标下「清除格式」什么都不清；引擎按词切分文本片段，只清到第一个词，同一段其余的词仍是手动格式。

### 🎨 弹层边界：下拉、面板、对话框统一描边

- **以前**：电子表格的白底浮层只画阴影、不画边框——白底浮层压在同样偏白的编辑面上，边界全靠阴影，浅色主题下看起来像「糊上去的一块」，和 App 里已经统一带边框的弹窗 / 菜单不是一套语言。App 侧也有五个模态框（插件迁移对话框、个人中心弹窗、设置页三处对话框）和两个计划卡悬停提示没带边框。
- **现在**：Excel 编辑面统一补一圈固定浅灰描边加柔和阴影，覆盖工具栏下拉（字体 / 字号 / 数字格式 / 对齐 / 合并 / 货币 / 分列…）、「更多」面板、缩放比例菜单、消息框 / 查找替换对话框；App 侧五处模态框和两个悬停提示也补上边框。
- **颜色面板不加**：颜色面板库自己带边框，再给内层加一圈会变成灰底里套白框的双层边；右键菜单与公式提示库自己带边框，也不重复加。共享的通用弹窗、统一权限弹窗、右键菜单本来就有边框，未改。
- **边界**：颜色用固定浅灰而不是主题色——Excel 编辑面是固定浅色的（画布不跟主题），暗色主题下主题边框色会发白、反而看不见；阴影顺手收到 App 弹窗那一档，避免原来 2px 的硬阴影显得脏。

### 🔒 保存失败：文件被别的程序锁住时，不再弹英文

- **以前**：保存走的是统一写盘通路，失败时直接把系统错误原样弹出来——Windows 上文件被 WPS / Office / 同步盘占着时，提示是一整句英文，中文界面里显得突兀，也不知道该怎么处理。
- **现在**：按错误码给中文（英文界面给英文）：「被占用 / 锁定」会提示关闭占用它的程序（如 WPS、Office、同步盘）后重试；「没有权限」提示检查权限；找不到文件、磁盘空间不足、只读磁盘、文件名过长也各有对应说法。
- **边界**：认不出的错误仍回退到原来的通用「保存失败」提示，不吞错误；Word / Excel / PPT 的编辑器内保存走同一套映射。

### 🧩 插件按钮：常用的固定到发送键旁边

- **以前**：插件工具栏按钮整组参与自动收纳，输入框一行变窄时整组先被收进「＋」，常用的插件入口也跟着一起消失。
- **现在**：插件按钮右键（或用面板右键菜单里的「面板位置」）选「固定到工具栏右侧」，这一枚就搬到发送 / 历史按钮旁常驻——固定的这一组不参与收纳，永远不会进「＋」；主界面与搭档模式都显示。再右键「取消固定」即可收回，「面板位置」菜单里同一条也会同步显示当前状态。
- **边界**：欢迎屏不是侧栏，不显示工具栏固定按钮；面板被挪离「AI 对话工具栏」位置后，固定状态不生效；全部固定时行内那一组不占位、不会留下空档。

::: details ⚡ 启动与性能 · 3 项

### 💾 保存 Office：窗口不再刷一下

- **以前**：保存写盘后，文件监听把「自己刚写出去的内容」当成外部改动，内容版本号一涨，整个编辑器就被卸载重挂——引擎重新读字节、重新解压建模型，看起来就是窗口闪一下。
- **现在**：保存成功后登记「这份内容是我写的」（30 秒内有效），监听到同一份内容直接吞掉；就算没被认出来（例如批量保存），只要磁盘内容与当前编辑内容逐字相同，也只对齐磁盘基准、不重新加载。真正的外部改动（内容不同）仍照旧整格重载。
- **边界**：保存失败不登记；被外部程序改成同样的内容不算外部改动；重载逻辑未改。

### ⚡ 编辑器加载：重依赖分档，空闲时先热身

- **以前**：文件查看器在顶层静态引用了 PDF、旧版 PPT、Excel 三个编辑器，它们的依赖全被并进入口包，构建产物 5.7 MB——打开一张图、一个 docx 也要先解析这几 MB。
- **现在**：三个编辑器改成按需加载，渲染点统一包一层「加载中」占位；启动后按 2.5 秒 / 4 秒 / 6 秒的顺序，在浏览器空闲时分别把 Word 引擎、富文本引擎（约 2.1 MB，含公式 / 代码高亮 / 代码编辑）、PPT 引擎的模块先求值一遍——只解析模块，不挂编辑器、不读文档，真正打开时只剩初始化和文档解析。预热失败静默，不影响正常打开。
- **边界**：第一次打开仍要等引擎初始化与文档解析；预热只发生在应用启动后的空闲窗口，不抢启动期。

### 🩺 编辑器偶发「加载失败」：不再裸读还没挂好的视图

- **以前**：富文本编辑器在视图还没挂载时返回一个代理，除了少数几个状态字段，其它属性一读就抛错。最容易命中的是：界面更新时同步触发监听器，监听器里去读视图，而此刻编辑器刚好被销毁定时器销毁；事件监听器和延时定时器里也有同类读法。
- **现在**：所有读取都走安全取景器（视图未就绪就返回空），事件监听器、面板级拖放、延时归位定时器一并改掉；编辑器内容组件只挂活实例。另加回归围栏，禁止再出现裸读写法。
- **边界**：只影响「视图还没挂好」的瞬间；正常编辑路径不变。

### 🪟 安装程序：从「下一步」到一张请柬

- **以前**：双击 `.exe` 走的是默认的安装向导——一页页灰底「下一步」，没有品牌感，也不会告诉你装完到底占多少磁盘。
- **现在**：换成 760×580 单栏三页向导，暖纸底 + 铜色主按钮，内容直接落在纸上，没有一格白卡片：
  - **第一页**：大标题 + 一句官网同款标语，下面是安装位置、「磁盘占用 · 管理员权限」细线行和三个卖点。磁盘占用按装完之后实际占用的体积显示（当前约 508 MB），不是安装包本身的大小。
  - **第二页**：「顺手带上这些」——快捷方式与「用 Notrat 打开」两组胶囊，文件关联按实际勾选汇总到第三页。
  - **第三页**：「可以开始了」——版本 / 位置 / 快捷方式 / 文件关联 / 占用五行对账，页脚勾选用户协议后铜色主按钮才可用。
  - **协议与致谢**：用户协议运行时优先在线拉取（4 秒超时、失败静默），源码里先塞随包副本，抽屉右上角小印标「在线获取 / 随安装包附带」；第三方开源组件致谢放在右侧独立抽屉，按钮写「关闭」，不参与同意勾选。
  - **接自动更新**：应用内更新把它叫起来时走无人值守，原样交给内嵌安装流程，装完自己拉起应用；手动双击永远走完整向导。
- **边界**：外壳按 x64 编译（ARM64 Windows 由系统模拟运行）；外壳自身没有差分更新数据，取不到时回退整包下载，功能不受影响。

### 📦 安装包：把 PPT 编辑器装进去，也把不该带的依赖拿掉

- **以前**：`.pptx` 的编辑器代码没进包（且 Windows / macOS 都没注册 `.pptx` / `.docx` / `.xlsx` 文件关联）；只在界面里用到的依赖还留在生产依赖里，打包时又原样带了一份。
- **现在**：
  - **补齐**：PowerPoint 编辑器随包；Windows 与 macOS 的 `.pptx` 关联注册进安装包，`.docx` / `.xlsx` / `.xls` / `.xlsm` / `.xlsb` 一并补上。
  - **瘦身**：只被界面引用的依赖移到开发依赖（打包时不再重复携带）；离线语音识别只保留运行必需的文件。
  - **再瘦身**：Windows x64 解包目录 794 MB → 532 MB；Electron 自带的语言包只留中英两种；离线推理只留当前平台 / 架构的二进制；旧版 PDF 演示页的静态副本与构建期资源不再进包。**下载体积**：Windows x64 安装器 233 MB → 152 MB，三合一通用安装器 699 MB → 492 MB。
- **边界**：macOS 的文件关联由系统登记，未签名 / 未公证的包可能不认；具体体积以本次构建产物为准。

::: details 🔌 连接器与智能体 · 2 项

### 🔌 连接器（MCP）：缺环境变量时，装完就知道缺哪一个

- **以前**：只认几种固定的英文措辞。漏认的后果不是报错本身，而是安装时不出「配置环境变量」弹窗：用户装完一启动就是「子进程退出」，还得自己回头找是哪一步缺了变量。
- **现在**：补上 Python 的 `<VAR> environment variable is required / not set / must be set`，以及 `environment variable: <VAR> …` 写法；同时加上「全大写 + 至少 3 个字符」的形态判断——为了认 `Api key is required` 这类措辞，旧规则会连小写的 variable 也抓出来当变量名，新措辞一加就暴露了。
- **边界**：只认常见措辞，认不出的启动失败仍按原始错误展示。

### 🤖 子 agent：默认与主 agent 同权，用哪个模型由主 agent 定

- **以前**：运行时专家里 summarizer 被硬编码成「不给任何工具」，派发参数也没有模型字段——临时子 agent 只能继承全局默认，想换模型只能先把专家写进配置。工具为空时提示词里也没有任何交代，模型只能自己编一个理由。
- **现在**：
  - **权限**：优先级从高到低——主 agent 派发时给的 `tools`（服务器 id / 工具名 / 工具名前缀三种写法都认）→ 专家自己配了具体的连接器 → 专家级「不用工具」开关 → 其余一律**与主 agent 同权**。授出的工具仍受全局开关约束，不能越过用户关掉的连接器；派发时传空数组 `[]` 表示「这次明确不给工具」，与「没指定」区分开。
  - **如实汇报**：子 agent 的运行时上下文里写明工具数量、可用工具清单和权限来源；缺工具时要求点名缺哪一项能力，由主 agent 带着授权重新派发，不再笼统地说「工具不可用」。
  - **模型**：派发与创建专家时都可以指定 `provider` / `model`；服务商认 id 或显示名（大小写、首尾空格不敏感），只给模型就挂在当前服务商上，认不出的服务商直接报错并列出可用清单——**绝不静默回退**。
  - **不用猜**：派发工具的说明里现读当前配置的服务商与模型目录，主 agent 照着填即可。
- **边界**：`provider` 只能在已配置的服务商里选；设置页给 researcher 的那个「允许使用工具」开关仍是硬关闭，派发也绕不过去。
