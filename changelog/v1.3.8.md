## ⚡ 更新亮点

- **⚙️ 设置里能自己关掉硬件加速**：设置 → 通用 多了一行「硬件加速」开关，默认开着。关掉之后下次启动改用软件渲染（界面交给 CPU 画），显卡驱动爱闹别扭的机器可以就这么长期用着；拨动即保存，旁边会提示「重启 Notrat 后生效」，不用再点「确定」。处在自动降级状态时，这个开关显示的是真实的「关」，不会骗你说还开着。
- **🛡️ 显卡进程连续出事，应用会自己退一步**：同一个 7 天里显卡进程崩了两次，下次启动自动切成软件渲染，并在角落弹一条提示：「检测到显卡驱动异常，已关闭硬件加速（设置里可重开）」。只弹一次，不反复打扰；不自动重启应用，也不偷偷每隔一会儿再试一次硬件加速——界面照常可用，你自己在设置里重新打开就解除。
- **🩺 崩溃记录带上了现场**：以前后台只留一句「显卡进程异常退出」；现在同一条记录旁边会写上显卡型号与驱动版本、崩溃那一刻开着几扇窗口、进程数与内存 / 显存占用。下一次遇到同类问题，不用再从你的描述里拼现场。
- **🖐️ 当前正在看的那条也能拖走了**：以前把正在看的对话拖到另一个工作区，会提示「无法移动对话——先切到那个工作区的另一条对话」，得先手动点开另一条再回头拖。现在直接拖就行：会先替你切到源工作区的另一条对话（没有就开一条空的），再整条搬过去。另一个窗口正开着这条时，它会被提示「这条对话已被移到其他工作区，已为你切到别的对话」并自动让开，不会两个窗口守着同一条抢着写。
- **🧩 子 Agent 做完的结果，就在那一轮的 agent 卡里**：后台子 Agent 交回来的结果不再伪装成一条「你发的消息」插进对话流，而是并进本轮 agent 卡（和工具调用同一张卡）的展开区，每条一块结果卡：标着「结果 / 失败」、Agent 名、耗时，下面是它交回来的正文。跑完的活终于看得见，过程仍旧只留在底部运行面板里。
- **⌨️ 回复一结束，键盘就落在选项面板上**：回复里带选项卡 / 选择向导时，以前光标还留在输入框，得先拿鼠标点一下面板才能用方向键；现在回复一结束焦点就在面板上，↑↓ 选、←→ 翻页、回车确认直接可用。想回输入框按 Esc，或者干脆开始打字——第一个字会一起带进输入框，不会白按。

## 🩹 修复速览

::: details 展开全部 · 8 条

- 显卡驱动出问题之后整机死机、托盘消失，应用里一条记录都没有 —— 修好（自动降级，重启后改走软件渲染）

- 显卡崩溃的上报只有一句「异常退出」，型号、驱动、当时的内存全靠你描述 —— 修好（自动带上现场）

- GOAL 模式下同时开好几条对话，续跑被延迟之后接错了地方，你的消息和整段回复都落进刚切过去 / 新开的那条对话 —— 修好（自动续跑只回到它自己的对话）

::: details 🚀 启动与性能 · 2 项

### 🛡️ 显卡进程崩了两次，下次启动自动改用软件渲染

- **来由**：2026-10-31 有用户遇到显卡进程异常退出之后整机死机、托盘消失，只能手动重启。这类问题是显卡驱动把图形上下文丢了，应用修不了，但可以少让用户再撞一次。
- **以前**：崩了就是崩了，下次启动照样用硬件加速，同一台机器上会反复发生；也没有任何地方记录「这台机器最近崩过几次」。
- **现在**：应用在本地记一本显卡崩溃流水（7 天窗口）。窗口内累计到 2 次，就进入安全模式：把「关闭硬件加速」写进设置，下次启动直接以软件渲染运行，并在界面弹一次说明。单次偶发不降级；已经在安全模式里再崩，只继续记流水，不会每崩一次弹一次。
- **边界**：不自动重启应用、不自动再试硬件加速——解除只需要在设置里把「硬件加速」重新打开；应用自己退出、重载带走的显卡进程不算崩溃，不计入流水；安全模式期间，别处保存的整份设置不会把开关翻回「开」，只有设置页那个开关能解除。

### 🩺 崩溃记录：补上显卡型号、驱动版本和当时的进程占用

- **来由**：10-31 那次只拿到「显卡进程异常退出」这一句，显卡型号、驱动版本、当时开了几扇窗、内存涨到多少，全靠事后问用户。
- **以前**：崩溃上报只有类型、原因和退出码；显卡相关的问题尤其缺上下文，同一个现象背后的机型差异完全看不出来。
- **现在**：显卡进程退出、窗口进程退出、页面加载失败这三类记录，都会顺带写上显卡型号与驱动版本、窗口数、进程数与内存 / 显存占用。字段都是短的文本，不改变原有的上报数量和内容口径。
- **边界**：显卡信息在启动时异步取一次（取不到就留空，不拖慢启动）；内存数字以系统给出的工作集为准，跟任务管理器里的读数可能有小幅出入。

:::

::: details 🎛️ 界面与交互 · 3 项

### ⚙️ 硬件加速：出问题的时候，自己能关掉

- **来由**：2026-10-31 有用户遇到显卡驱动问题之后整机死机，而此前应用里连一个开关都没有。
- **以前**：硬件加速一直开着，没有设置项；驱动不配合的机器只能每次等它崩，也没有任何办法长期改走软件渲染。
- **现在**：设置 → 通用 新增「硬件加速」开关，默认开着。拨动即保存，旁边写明「重启 Notrat 后生效」。关闭后下次启动界面改由 CPU 绘制，显示效果与操作方式不变，只是重负载的画面（大图谱、大量动画）会慢一点点。
- **边界**：开关只在启动时生效，改完必须重启才能体会到；处在自动降级状态时，开关显示的是真实状态（关），不会被别处保存的旧设置覆盖；只有明确关掉才算关，配置文件里写成字符串之类的手改脏值一律按「开」处理。

### 🖐️ 拖走当前对话：不用先切走，别的窗口也会跟着让开

- **来由**：2026-10-31 用户拖对话时被提示「无法移动对话 —— 这条对话是它所在工作区的当前对话。先切到那个工作区的另一条对话，再拖过来。」
- **以前**：会话能拖，但只限没被打开的那几条；正在看的那条一律拦住，要先手动点开另一条、再回头去拖——两步换一步，还容易忘。另一个窗口如果正开着这条对话，把它搬走之后那个窗口还攥着一份旧副本，下一次保存就把它写回原来的工作区，等于搬了又自己长回去。
- **现在**：正在看的那条直接拖即可。会先在源工作区切到另一条对话（没有就开一条空白对话），确认真的切走了，才把这条整条搬过去；搬完源工作区的当前对话自动指到下一条。另一个窗口正开着这条时，它会收到「这条对话已被移到其他工作区，已为你切到别的对话」的提示并自动切走。
- **边界**：正在生成回复的那条仍然不能搬（会提示「这条对话正在生成回复。等它结束（或先点停止），再拖到别的工作区」），因为这一轮收尾要落回它原来的工作区；被搬走时被动让开的窗口，那一轮没跑完的回复不会保存（对话本身和已有内容完好）；自己拖走的那次不会再弹一次提示。

### 🎛️ 模型选择器：选完就收

- **来由**：2026-10-31 用户「在输入框下面的 ToolBar，选择模型之后，点击之后没有立即消失面板」。
- **以前**：此前是有意做成「选完不关」的，为的是让旁边的模型详情卡（推理等级就挂在里面）能马上接着改。代价是每选一次模型，面板都挂在那儿，得再点一下外面才收——菜单该有的「选中即完成」被破坏了。
- **现在**：点模型立即收起整个下拉，并把展开的服务商分组、详情卡目标一并清空。要改推理等级，重新点开下拉看详情卡，或从「工作场景」里改。
- **边界**：只改「点选之后」的手势；悬停预览详情卡、键盘上下移动列表、点外面关闭、离开自动收起这些都没变。

:::

::: details 💬 聊天与 AI · 3 项

### 🧩 子 Agent 的结果：并进那一轮 agent 卡

- **来由**：2026-10-31 用户「已执行完的 Agent 我看不到结果」。
- **以前**：后台子 Agent 交回结果时，会在对话流里插一条长得像「你发的消息」的注入消息——可它其实不是你发的；而且结果多半在主 AI 还在输出时就到了，挂在占位的位置上，等这一轮流完就找不回来，结果整块消失。
- **现在**：回传结果不再以用户消息的形态出现，而是并进本轮 agent 卡（与工具调用同一张卡）的展开区：每条一块结果卡，标题行写「结果」或标红的「失败」、Agent 名和耗时，下面是它交回来的正文；失败的结果整段标红。跑完的活就这么摆在那儿，随卡展开就能看。
- **边界**：结果仍留在会话里给主 AI 读，只是不在对话流里重复显示；执行过程照旧只在底部运行面板里；某条结果对不上任何一轮（比如派发它的那条对话已经关掉）时，会单独成行显示，不会丢。

### 🔁 GOAL 多会话：续跑只回到它自己的对话

- **来由**：2026-10-31 用户「GOAL 模式下，多个会话输出渲染有问题，因为涉及到了重新发送续流，会对接到新对话上」。
- **以前**：自动续跑（GOAL 继续、截断续写、子任务整合）排队时不记自己属于哪条对话；而队列要等压缩结束或这一轮收尾之后才统一发出。这段时间里只要切走或新建对话，续跑和整段回复就落进了新那条对话，看起来像凭空多出一轮。
- **现在**：所有自动续跑在排队那一刻就记住自己属于哪条对话；发送时凡是不属于当前对话的自动续跑直接丢掉，绝不发进别处。你自己排队的消息不受影响——它们按会话挂起，切回那条对话（或点横幅里的「发送」）才发出。
- **边界**：手动点「发送」按你此刻的意图发到当前对话；按过停止之后，自动续跑不会复活；压缩期间手动发消息会作废这次压缩，和原来一样。

### ⌨️ 选项面板：回复一结束就接过键盘，Esc 或直接打字退回输入框

- **来由**：2026-10-31 用户「AI 回复完了之后，如果有面板的话，光标还是在输入框上面，而不是在面板上面，除非用户一直按 ↓；减少鼠标化，用户能用键盘完成的事情，就不用鼠标完成」。
- **以前**：选项卡 / 选择向导早就支持 ↑↓ 选、←→ 翻页、回车确认，但回复结束时焦点几乎总在输入框里，而焦点在文字输入处时不抢——于是面板在最该用键盘的那一刻永远拿不到键盘，只能拿鼠标点一下；焦点进了面板后，想回输入框也只能再点回来。
- **现在**：回复一结束，只要这条回复里带着交互面板、而输入框里没有草稿，焦点就直接落在面板上——↑↓ 选、←→ 翻页、回车确认马上能用。想回输入框按 Esc，或者直接开始打字：第一个字会一起带进输入框，不会白按。输入框空着时按 ↓，也能随时把焦点交给最后一张面板。
- **边界**：输入框里已有草稿不抢；正在别处打字不抢（@ 面板搜索框、文件树搜索框、行内重命名）；窗口不在前台不抢；只有「刚生成完的那一张」会自动接焦点，打开历史会话时几十张旧面板不会挨个抢；面板里需要打字的自由输入框照旧交给浏览器。
